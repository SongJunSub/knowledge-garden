## 한 줄 요약

**NHN Cloud의 GPU Live는 AI 학습 환경 구성부터 자원 관리까지 전 과정을 통합 지원하는 멀티테넌트 GPU 클러스터 서비스로, 단일/분산 학습과 인터랙티브/배치 실행을 유연하게 선택할 수 있게 하고 GPU 동적 할당과 빈패킹으로 자원 낭비를 줄인다는 서비스 소개 글이다. 다만 "빈패킹"이라는 구체적 기법이 이 글에서 정확히 어떻게 구현됐는지는 확인하지 못했고, 아래 내용은 Slack 발췌와 회사 공개 발언을 교차한 정황 수준이다.**

## 핵심 포인트

- **통합 지원 범위**: ***GPU Live는 AI 학습 환경 구성부터 자원 관리까지 전 과정을 통합 지원하는 멀티테넌트 솔루션***이라고 소개된다 — 개별 GPU 프로비저닝 도구가 아니라 환경 구성·스케줄링·운영을 아우르는 플랫폼으로 포지셔닝.
- **워크로드 유연성**: 워크로드 성격에 따라 ***단일 및 분산 학습을 지원하며, 인터랙티브와 배치 실행 방식을 유연하게 선택 가능***하다고 설명된다 — 노트북 기반 실험(인터랙티브)과 스케줄된 대량 학습(배치)을 같은 플랫폼에서 전환할 수 있다는 의미로 읽힌다.
- **핵심 기술로 언급된 것**: ***GPU 동적 할당과 빈패킹(bin-packing) 기술을 적용해 자원 낭비를 최소화하고 클러스터 전체의 활용 효율을 극대화***한다고 되어 있다 — 빈패킹은 일반적으로 서로 다른 크기의 작업을 최소한의 노드/GPU에 밀집 배치해 유휴 조각(fragmentation)을 줄이는 스케줄링 기법인데, 이 글에서 Kubernetes 스케줄러 확장인지 자체 개발 스케줄러인지는 확인 불가.
- **회사가 공개적으로 밝힌 맥락(WebSearch로 교차 확인, 이 글과 동일 수치인지는 미확인)**: NHN Cloud CTO는 GPU 1장을 여러 워크로드가 나눠 쓰면 동일 시간에 1.4배 많은 요청을 처리할 수 있다고 밝혔고, H100 GPU 한 장이 유휴 상태일 때 시간당 약 2.10달러가 낭비되며 온프레미스 고객이 GPU를 50%만 쓴다고 가정하면 연간 약 140억 원 손실이라는 계산을 제시했다. Kubernetes·Slurm 기반 자원 관리 기술을 적용했다는 보도도 있다.
- **사업 맥락**: 광주 국가 AI 데이터센터에서 NVIDIA H100과 국산 NPU를 함께 운영하며, GPU Live는 FactoryX라는 AI 풀스택 브랜드의 구성 요소로 2025·2026년 AI TECH+ 전시에 소개됐다.

## 내 생각 · 적용점

### 핵심 전이 1 — [[2026-09-17-inference-hardware-revolution-2026]]이 진단한 "병목 이동"의 운영 측 대응으로 읽힌다

그 노트는 추론 컴퓨트 수요가 2026년 전체 AI 컴퓨트의 2/3를 넘어서면서 칩 설계의 병목이 연산에서 메모리 대역폭으로 옮겨간다고 진단했다. GPU Live가 공략하는 문제(유휴 GPU 시간당 2.10달러 손실, 50% 활용 시 연 140억 원 손실)는 그 칩 설계 수준의 병목과는 다른 층위지만, 같은 "GPU가 비싸고 부족한 자원"이라는 전제 위에서 운영 측(스케줄링·멀티테넌시)이 할 수 있는 대응이라는 점에서 같은 문제의식의 다른 레이어로 연결된다.

### 핵심 전이 2 — [[2026-09-10-aws-eks-gemma4-vllm-part2-throughput-slo]]와는 "GPU 활용 극대화"라는 목표는 같지만 접근 층위가 다르다

그 노트는 GPU 한 장 안에서 양자화·캐시 정책으로 처리량을 끌어올리는 "단일 GPU 최적화" 접근이었다. GPU Live는 반대로 여러 GPU·여러 워크로드를 하나의 클러스터로 묶어 동적 할당·빈패킹으로 "클러스터 전체"의 활용률을 높이는 "멀티테넌트 오케스트레이션" 접근이다. 두 노트를 합치면 GPU 활용 극대화가 "한 장을 잘 쓰기"와 "여러 장을 잘 나누기"라는 두 개의 독립적인 최적화 축으로 이뤄진다는 그림이 보인다 — 어느 하나만으로는 완결되지 않는다.

### 핵심 전이 3 — [[2026-10-07-kyungshin-holdings-ax-agentcore-platform]]과 "거버넌스/플랫폼 레벨" 포지셔닝이 겹친다

그 README 항목이 짚었듯 경신홀딩스 사례는 "단일 에이전트가 아니라 데이터연결·인증·카탈로그를 표준화한 플랫폼/거버넌스 레벨 사례"였다. GPU Live도 같은 패턴이다 — 개별 학습 작업 하나를 최적화하는 도구가 아니라, 여러 조직·워크로드가 공유하는 GPU 자원 전체를 멀티테넌트로 관리하는 플랫폼 레벨 서비스라는 점에서, "AI 인프라를 개별 작업 단위가 아니라 플랫폼 단위로 추상화한다"는 같은 흐름의 다른 영역(에이전트 거버넌스 vs GPU 자원 거버넌스) 사례로 묶을 수 있다.

## 호스피탈리티 / CRS 적용 포인트

**직접 적용은 멀다.** 온다 CRS는 자체 GPU 클러스터를 운영하는 인프라 사업자가 아니라 B2B SaaS이고, 현재 자체 LLM 추론 인프라를 운영하는지도 확인되지 않는다. 다만 이 글이 보여주는 "유휴 자원 비용을 명시적으로 계산해 동적 할당의 근거로 삼는다"는 접근 원칙은, CRS가 향후 자체 추론 서버나 배치 작업 클러스터를 운영하게 될 경우 참고할 만하다 — [[2026-09-10-aws-eks-gemma4-vllm-part2-throughput-slo]]의 "캐시가 곧 원가" 원칙과 마찬가지로, "유휴 자원이 곧 손실"이라는 계산을 먼저 명시적으로 세워두면 투자 결정의 근거가 명확해진다는 원칙만 전이할 수 있다.
