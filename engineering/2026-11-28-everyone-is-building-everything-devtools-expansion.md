# 모두가 모든 것을 만들고 있다(GeekNews)

> 출처: GeekNews [id=37978](https://news.hada.io/topic?id=37978) 경유, 원문 매체·저자 미확인 · Slack `#개발-뉴스-dev-news` 채널(원문 링크봇) 경유 · 정리일 2026-11-28
>
> **출처 한계**: news.hada.io egress 차단으로 원문 미열람. Slack이 언급한 **WorkOS의 사내 앱 플랫폼, Depot의 Git 호스팅, Linear의 AI 코딩·코드 리뷰 확장, Warp의 에이전트 호스팅 확장이라는 구체적 사례**는 WebSearch로 독립 확인하지 못했다(WorkOS 공식 블로그에서 사내 봇·에이전트 샌드박스 관련 포스트는 찾았지만 이 글이 말하는 정확한 서사와는 결이 다르다). 다만 **"개발 도구 시장이 단일 기능 경쟁에서 인접 카테고리로 확장하는 국면으로 넘어갔다"는 거시적 주장은 Sentry(에러 추적→옵저버빌리티)·GitHub Copilot(코드 완성→PR·리뷰·테스트) 같은 독립적인 사례로도 뒷받침된다.** 개별 회사 서사는 미확인, 추세 자체는 부분 확인으로 분류한다.

## 한 줄 요약

**개발 도구 업체들이 기존 제품을 버리고 새 제품으로 피벗하는 대신, 핵심 영역을 유지하면서 인접 제품군으로 동시에 확장하고 있다고 전해진다(인증 업체 WorkOS는 사내 앱 플랫폼, 빌드 업체 Depot은 Git 호스팅, 이슈 추적 Linear는 AI 코딩·리뷰, 터미널 Warp는 에이전트 호스팅으로). AI 덕분에 기능을 만드는 건 쉬워졌지만, 그 이후 지원·온콜·보안·SLA·규제 준수 부담이 제품마다 새로 붙고, 신제품을 출시한 뒤 "고객이 실제로 쓰게 만드는 일"이 오히려 더 어려워졌다는 결론이다.**

## 핵심 포인트

- **확장의 형태 — 피벗이 아니라 병행** — 개발 도구 업체들이 기존 제품을 버리는 피벗 대신, ***다른 제품군으로의 확장***을 병행하고 있다고 전해진다.
- **구체 사례(미확인)** — 인증을 제공하던 WorkOS는 사내 앱 플랫폼을, 빌드에 집중하던 Depot은 Git 호스팅을 출시했다고 전해진다. 이슈 추적 도구 Linear는 AI 코딩과 코드 리뷰로, 터미널 Warp는 에이전트 호스팅으로 확장했다고 전해진다.
- **AI로 기능은 쉬워졌지만 부담은 늘어남** — AI로 기능을 만들기는 쉬워졌지만, 제품마다 ***지원·온콜·보안·SLA·규제 준수*** 부담과 시장 진출 지원이 추가된다고 전해진다.
- **진짜 어려움은 출시 이후** — 새 제품을 출시한 뒤에는 ***고객이 실제로 쓰게 만드는 일***이 더 어려워졌다고 전해진다. Vercel이 CI를 추가할 수 있었던 건 기존 (Slack 발췌가 여기서 끊김).
- **(교차확인) 거시 트렌드** — 2026년 개발 도구 시장을 다룬 복수 가이드는 "시장이 증식 단계를 지나 인접 카테고리로 확장하는 국면"이라고 진단하며, Sentry(에러 추적→옵저버빌리티 플랫폼)·GitHub Copilot(코드 완성→PR 설명·리뷰 제안·테스트 생성)을 예로 든다.

## 내 생각 · 적용점

### 핵심 전이 1 — "제어면 장악"이라는 이 가든의 반복 패턴

[[2026-08-19-github-is-not-just-git]]에서 정리했던 **"GitHub은 저장소를 잘 호스팅해서만 승리한 게 아니라, Issues·Actions·정체성까지 네 층을 모두 장악했기 때문에 떠나기 어렵다"**는 분석이 이 글에서는 업계 전체의 전략으로 일반화된다. 인증(WorkOS)·빌드(Depot)·이슈추적(Linear)·터미널(Warp) 각자가 "핵심 기능 하나"에 머물지 않고 인접 영역으로 확장하는 건, 각자가 자기 영역에서 **GitHub과 같은 다층 락인 구조**를 만들려는 시도로 읽을 수 있다.

### 핵심 전이 2 — AI가 "만드는 비용"은 낮췄지만 "유지하는 비용"은 그대로다

이 글의 결론 — 신제품 출시보다 "고객이 쓰게 만드는 일"이 어렵다 — 는 [[2026-09-18-how-spacexai-built-grok-bot-in-a-month]]의 "unshipping(기능을 걷어내는 것)에 집중했다"는 전략과 정반대 방향에서 같은 교훈에 도달한다. 둘 다 **AI로 "만들기"가 쉬워진 세계에서, 희소 자원은 더 이상 구현력이 아니라 "무엇을 쓰게 만들 것인가에 대한 판단"**이라는 걸 보여준다.

### 핵심 전이 3 — 도구 공급사의 수직 확장은 "빌려쓰던 부품을 소유로 바꾸는" 흐름과 같은 축

[[2026-11-05-openai-acquires-pierre-computer-company]]에서 정리했던 "OpenAI가 Codex가 의존하던 Git 저장소 라이브러리 회사를 인수했다"는 사례와, 이 글의 "Depot이 Git 호스팅으로, Linear가 AI 코딩으로 확장한다"는 사례는 같은 방향의 움직임이다 — **개발 도구 공급사들이 서로의 영역을 잠식하며 하나의 통합 플랫폼이 되려는 경쟁**이 진행 중이다.

## 호스피탈리티 / CRS 적용 포인트

**적용 가능성 있음(제한적)**: CRS·PMS·채널매니저·결제 벤더를 선택·갱신할 때, **"이 벤더가 핵심 기능만 깊게 파는지, 아니면 인접 영역까지 침투해 전환 비용(락인)을 쌓고 있는지"를 평가 기준으로 명시적으로 추가**할 수 있다. 벤더의 인접 영역 확장 자체가 나쁜 건 아니지만([[2026-08-19-github-is-not-just-git]]의 "제어면이 어디 있는가"가 핵심 질문이듯), 멀티 벤더 전략을 쓸지 올인원을 쓸지는 이 트렌드를 인지하고 의도적으로 선택해야 한다.
