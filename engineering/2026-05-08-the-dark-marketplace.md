# 다크 마켓플레이스 — AI 에이전트가 거래를 대행하는 커머스의 미래

> 출처: [Euclid Ventures — The Dark Marketplace](https://insights.euclid.vc/p/the-dark-marketplace) · 레퍼러: [GeekNews 29278](https://news.hada.io/topic?id=29278) · 정리일 2026-05-08

## 🔖 한 줄 요약
*AI 에이전트가 사용자 대신* 상품 발견·가격 협상·구매를 *보이지 않게* 수행하는 **다크 마켓플레이스**가 다음 커머스 패러다임 — 진짜 해자는 UI가 아니라 **사용자별로 축적된 판단 데이터(memory)**. B2B가 소비자보다 먼저 도착할 영역.

## 🧩 핵심 주장

### 1. Anthropic *Project Deal* 실험 (사실 수치)
- **69명 직원, 186건 완료된 거래, 총 $4,000+**
- 강한 AI 모델 = *객관적으로 더 나은 결과*
- 그러나 **사용자는 *자기 에이전트의 저성능*을 감지하지 못했다** — 가장 무거운 발견

### 2. 4단계 여정
| # | 단계 | 의미 |
|---|------|------|
| 1 | **Stated Preferences** | 사용자가 *명시적으로* 원하는 것을 말함 |
| 2 | **Behavioral Inference** | 시스템이 *말하지 않은 패턴*을 관찰 |
| 3 | **Contextual Judgment** | 시장 조건·제약과 통합 |
| 4 | **Autonomous Decision-Making** | 인간 감독 *최소화*하고 자율 행동 |

→ 1→4로 갈수록 **사용자 화면이 사라진다**. 이게 *"다크"*.

### 3. Engagement-Proximity 매트릭스
성공 = *높은 사용 빈도* × *실제 거래 근접성* — **둘 다 필요**.
- 한 축이 약하면 빠르게 메워야 함
- 화면을 가진 회사는 *거래 근접성*을, 거래를 가진 회사는 *반복 사용*을 추가해야 한다

### 4. 왜 B2B가 먼저인가
- *반복 구매*가 학습 데이터 생성
- *컴플라이언스·예산*이 추상화 가능 패턴 형성
- *전환 비용*이 자동 누적
- 소비자 구매는 *경험 자체*가 가치 — 자동화하면 *재미가 사라짐*

### 5. 진짜 해자 = *Memory*
> "The moat is memory, not UI."

- *UI는 복제 가능* / *축적된 판단 데이터는 복제 불가*
- 사용자별로 더 오래 학습한 회사가 *전환 거부 가능한* 우위 확보

> "The system doesn't just respond to expressed intent, it anticipates latent demand."

## 💭 내 생각 · 적용점

### 호스피탈리티 IT 직격 — *2번째 OTA 시대*
이 글의 흐름이 그대로 호스피탈리티에 적용되면:
- **1세대 OTA**: 사람이 화면을 보고 호텔을 *직접 검색·비교·예약*
- **2세대 (현재)**: OTA + 메타서치(트리바고·카약) + 호텔 직판 사이트
- **3세대 (다가오는)**: **다크 마켓플레이스** — *내 AI 에이전트가 호텔 예약을 대행*

→ [YC RFS #12 *Software for Agents*](2026-04-29-yc-rfs-summer-2026-hospitality-it.md)의 *호스피탈리티 버전*. 내 가든이 **이미 1주일 전 같은 흐름을 식별했고, 이 글이 *증거 보강***.

### *사용자가 자기 에이전트의 저성능을 감지 못한다* — 핵심 위협
- 호텔 입장에서 *어느 에이전트*가 우리를 추천하는지가 *결정적*
- 고객이 *자기 에이전트 품질*을 평가 못하므로 → **에이전트의 *학습 데이터 = 호텔 측 노출*이 새 광고 경쟁**
- [Glaser의 *Loop Intelligence*](2026-05-07-when-everyone-has-ai-but-company-learns-nothing.md), [Willison 외형 동일](../ai/2026-05-07-vibe-coding-agentic-engineering-converging.md)과 직접 결합

### 호스피탈리티 4단계 매핑
1. **Stated**: *"강남, 5/15-17, 더블, 50만원 이하"* — 현재 OTA 검색
2. **Behavioral**: 매번 *조선·신라 스타일*만 고른 패턴 추론
3. **Contextual**: 그 주말 *행사·날씨·교통* 통합
4. **Autonomous**: 사용자에게 *"5/15-17 조선강남 예약했어요"* 통보만

→ 우리(호스피탈리티 IT)의 가장 큰 위협 = **3-4단계에서 *어느 호텔이 *추천 후보 풀*에 들어가는가***. *호텔 직판 채널*이 *AI 에이전트 친화적*이지 않으면 **에이전트의 *기본 후보*에서 빠진다**.

### 즉시 적용 액션 — *Agent-First Distribution*
[YC RFS 호스피탈리티 글](2026-04-29-yc-rfs-summer-2026-hospitality-it.md)에서 #12 *Software for Agents*를 🔴 최상으로 분류했는데, 이번 글이 그 우선순위를 *재확인 + 수치 증거 제공*. 구체화:

| 후보 | 설명 |
|------|------|
| **MCP 서버 노출** | 호텔 가용성·요금·메타데이터를 *AI 에이전트가 자율 호출 가능*하게 |
| **자연어 친화 엔드포인트** | *"강남 더블 50만원 이하"* 같은 쿼리를 받아 *구조화된 답변* |
| **에이전트 인증·rate-limit 정책** | 사람 트래픽과 *다른 SLA*로 별도 운영 |
| **에이전트가 호텔을 *왜* 추천했는지 받는 메타데이터** | 호텔이 *어떤 신호*에 반응하는지 학습 |

### *Memory가 해자*는 호스피탈리티 신뢰 자산과 짝
- [No One's Happy의 *신뢰 자산*](../ai/2026-05-07-appearing-productive-in-the-workplace.md): 공정 데이터·정확 정산·SLA
- 이 글: *사용자별 축적된 판단 데이터*
- 둘 다 *시간을 들여야만* 만들어진다 — *AI로 가속 불가*
- → 호스피탈리티 IT가 *이미 가진 데이터*가 새 시대의 *모트* 후보

### B2B 호스피탈리티 = 가장 빠른 적용 영역
글의 *B2B 우선* 논리가 호스피탈리티에 정확히 적용:
- **법인 출장 예약** = 반복 구매 + 예산 + 컴플라이언스
- **여행사 B2B** = 반복 구매 + 학습 가능한 패턴
- → *B2C*(개별 게스트)보다 **B2B(법인·여행사)에서 다크 마켓플레이스가 먼저 도착**할 가능성 높음

이건 우리 호스피탈리티 IT의 *B2B Connectivity API*가 가장 먼저 *AI-Agent-First*로 재설계되어야 하는 이유.

### 반론·균형점
- *"다크"가 의미하는 *사용자 가시성 부재*는 *법적 책임*에서 새 회색지대 — *사용자가 안 본 거래에 대한 분쟁 처리*는 [3 역법칙 책임 포기 금지](../ai/2026-05-07-inverse-laws-of-robotics.md) 적용 필요
- *Memory 해자*가 *몇몇 거대 플랫폼에 집중*되면 호스피탈리티 측에서 *기존 OTA 종속*보다 *더 강한 종속* 형성 가능 — *대안 분산*이 정책 우선순위
- *4단계 자율*은 호스피탈리티에선 *예약 취소·환불* 같은 *결정적 가역성 낮은* 결정에 신중 필요

## 🎯 즉시 시도할 액션 3가지
1. **CRS·Connectivity API의 *Agent-First* 재검토 시범** — MCP 서버 시도 후보 1개 식별 (가용성 read-only가 안전)
2. **호스피탈리티 *Engagement-Proximity 매트릭스* 작성** — 우리가 *어느 축*이 약한가 1페이지 분석
3. **B2B(법인·여행사) 채널을 *다크 마켓플레이스 1번 후보*로 분류** — Connectivity 우선순위 재정렬 메모
