# 소프트웨어 팩토리, 빛과 어둠 (Addy Osmani) — 다크 팩토리는 '이해 부채'를 쌓아 조용히 늦게 무너진다

> 출처: [Software Factories, Light and Dark](https://addyo.substack.com/p/software-factories-light-and-dark) (Addy Osmani, Google Chrome 팀·웹 성능/개발자 도구 · GeekNews GN⁺ 요약) · 정리일 2026-07-24

## 한 줄 요약

**Addy Osmani가 AI 에이전트 자동화를 3계층(루프→하네스→팩토리)으로 정리하고, 제조업의 '다크 팩토리(무인공장)' 비유로 두 운영 모델을 가른다 — 밝은 팩토리는 인간 판단을 상류(제품·설계·아키텍처)에 두고, 다크 팩토리는 기계만 검증하고 인간이 안 읽은 코드를 배포한다. 다크 팩토리는 초기 처리량이 급증해 보이지만 근본 병목이 있다: 생성은 넓은 입구(CI·테스트가 거의 무비용으로 확장)인데 검증은 좁은 목(인간 판단은 확장 불가)이라, 입구를 빨리 해도 목의 더미는 안 줄어든다. 그 결과 '이해 부채(comprehension debt)' — 존재하는 코드와 인간이 여전히 이해하는 코드 사이의 벌어지는 간격 — 가 초록 테스트 아래 쌓이고, 3~6개월 뒤 조용하고 늦게 터진다. 원칙은 백프레셔: 루프에 줄 자율성은 값싸고 안정적으로 검증 가능한 범위까지만. 순수 루프 대신 상태 머신(그래프)으로 제어 흐름을 소유하고, 인증·결제·공개 API 같은 비싼 결정엔 '불을 켜둬라'. 인간의 새 역할은 코드를 쓰는 게 아니라 외부 루프를 설계하고 게이트를 지키는 것이다.**

## 핵심 포인트

- **3계층** — **루프**(에이전트가 맥락 수집→행동→확인→반복; *"루프 엔지니어링은 매 턴 프롬프트하는 게 아니라 에이전트를 위해 프롬프트하는 작은 시스템을 설계하는 것"*; Dex의 경험칙: 3~10단계는 유지, **20단계+에서 맥락 누적으로 탈선**). **하네스**(루프를 감싸는 환경: 샌드박스·도구·메모리·완료 게이트; *"루프는 행동, 하네스는 그 행동이 실행되는 환경"*). **팩토리**(다수의 하네스된 루프가 작업 큐로 공급돼 검토 게이트를 거쳐 프로덕션으로, 인간이 전체를 소유; *"더 크고 똑똑한 에이전트가 아니라 루프로 만든 조직도"*).
- **다크 vs 밝은 팩토리** — 다크(FANUC 2001~ 무인공장, *"기계는 못 보니 불 켤 필요 없음"*): **인간이 안 읽은 코드가 기계 검증만으로 배포**. 밝은: **인간 판단을 끝이 아니라 상류에** — 제품·설계·아키텍처를 먼저 정하고 → 에이전트 구현 → 자동 검사 → 판단 필요할 때만 검토 게이트. *"200줄 계획을 검토하는 게 2,000줄 생성 코드를 읽는 것보다 훨씬 효율적."*
- **비대칭: 생성 넓은 입구 vs 검증 좁은 목** — *"입구를 빠르게 하는 것만으로는 목에 쌓인 더미를 못 치운다."* 생성(CI/테스트/스캔)은 거의 무비용 병렬, **검증(검토 게이트)만 비싼 박스** — 인간 판단은 여전히 필수. *"좋은 아키텍처는 개월·년 단위로 측정돼 깔끔한 그래디언트가 없어 모델이 못 배운다."*
- **이해 부채(comprehension debt)** — *"존재하는 코드의 양과 인간이 여전히 이해하는 양 사이의 벌어지는 간격."* 다크 팩토리는 **초록 테스트인 채로 최대한 빠르게** 쌓음. 위험: 3~6개월 뒤, 10년+ 엔터프라이즈에서 심각. *"최종 계산은 극적인 '모두 망함'이 아니라 조용하고 늦다."* 설계 이해 없이 다음 변경 시 예상 밖 파급.
- **백프레셔 규칙** — *"루프에 줄 수 있는 자율성은 값싸고 안정적으로 검증 가능한 범위까지만."* 검증 가능 = 자동화 가능(초록/빨강 오라클·타입 게이트·속성 테스트·루브릭 리뷰) + 즉시 응답 + 증명 가능. *"높은 볼륨 + 신뢰 불가 게이트 = 제조 결함 불가피."*
- **상태 머신 > 순수 루프** — 순수 루프는 에이전트가 완료 선언까지 도구를 계속 호출, 경로 불확정·탈선. 그래프(미리 정의된 방향 그래프+조건부 엣지)는 *"백프레셔를 다이어그램으로 그린 것"* — 필수 검사점 명시·실패 지점 특정. LangGraph·LlamaIndex Workflows, David Khourshid: *"상태 머신과 액터 모델의 새 옷일 뿐."* *"제어 흐름을 소유하는 게 중요 — 항상 흐름도를 알았는데 순수 루프에서 잠깐 잊었을 뿐."*
- **인간 = 외부 루프 소유** — 역할 전환: 코드 작성(내부 루프) → **외부 루프 설계·감시**. 내부(에이전트): 진단·구현·테스트·보고. 외부(인간): 옳은 접근인가·타당한가·승인·책임. *"라인에 내려가 변경을 쓰는 게 아니라, 생산 라인 끝에서 설계하고 게이트를 지킨다."*
- **증거 기반 감시(값싼 안전망)** — 타입·시그니처·테스트 시임·명확한 레이아웃·짧은 콜스택·명확한 경계·의존성 주입 → 검토 효율. *"새로울 것 없다 — 늘 좋은 아키텍처를 말했지만 무시했다. 이제 에이전트 때문에 이게 값싼 안전망이 된다."*
- **불을 켜둘 곳** — 인증·결제·공개 API 계약 같은 **비싼 결정**은 인간 검토 유지. *"깨진 인증 시스템을 보며 깨어나기 싫으면 거기 불을 켜둬라."* (반대로 성공 사례: 매일 밤 cron이 안티패턴 하나만 고쳐 팀이 읽을 크기의 작은 PR.)
- **최종 원칙** — *"로봇은 어두워도 되지만 인간은 자기가 하는 일을 봐야 한다. 공장 바닥이 다 어둡고 조명을 못 찾겠다면, 거기가 위험한 지점이다."*

## 인상 깊은 문장

> "생성은 넓은 입구이고 검증은 좁은 목이다. 입구를 빠르게 하는 것만으로는 목에 쌓인 더미를 해결 못 한다."

> "이해 부채: 존재하는 코드의 양과 인간이 여전히 이해하는 양 사이의 벌어지는 간격. 최종 계산은 조용하고 늦다."

> "루프에 줄 자율성은, 값싸고 안정적으로 검증할 수 있는 범위까지만." (백프레셔)

> "로봇은 어두워도 되지만, 인간은 자기가 하는 일을 봐야 한다."

## 내 생각 · 적용점

### 핵심 전이 1 — 이번 주 판단·이해·외부루프 스레드 전체를 명명·체계화한 캡스톤이다

이 글은 이번 몇 주 담론을 **한 프레임으로 묶는다.** 'comprehension debt'는 [[2026-07-14-understanding-is-the-new-bottleneck]]의 *"이해가 병목·인지 부채"*를 명명한 것이고, 'external loop / 인간이 외부 루프 소유'는 [[2026-07-13-own-the-outer-loop]] 그 자체이며, '생성은 확장되나 검증은 안 된다'는 [[2026-07-19-human-in-the-loop-is-tired]]의 *"시작은 폭증·완료는 불변"*이다. '백프레셔'는 [[2026-07-18-ai-music-video-arena-fable-vs-sol]]의 *"평가 함수 없으면 자율성이 평균만 낳는다"*의 처방(평가 가능한 데까지만 자율)이고, '불을 켜둘 곳=인증·결제·API'는 방법론 §7(**LLM 위임 금지 영역**)·Dry-run 게이트 그대로다. **흩어져 있던 조각들이 "밝은/다크 팩토리 + 이해 부채 + 백프레셔"라는 하나의 운영 모델로 조립됐다** — 이번 주의 종합 노드.

### 핵심 전이 2 — "이해 부채"는 어제 explain-diff가 갚는 바로 그 부채다

comprehension debt를 이름 붙이니, 어제 정리한 [[2026-07-23-geoffrey-litt-explain-diff]]가 **그 부채를 갚는 도구**임이 분명해진다 — 퀴즈가 *"통과해야 이해했다고 보장"*하는 건 곧 **다크 팩토리로 새는 이해 부채를 막는 게이트**다. 그리고 [[2026-07-23-sharpening-knives-for-the-wrong-fight]]의 *"비용 필터가 사라져 검증 안 된 게 완성품처럼 보인다"*가 바로 **다크 팩토리의 발생 메커니즘**이고, [[2026-07-18-make-out-like-bandits-senior-dev-value]]의 *"AI가 부채를 쌓는다"*가 comprehension debt의 노동시장 결과다. [[2026-07-22-who-will-thrive-in-the-age-of-ai]]의 *인지적 항복(검증 능력 위축)*은 **인간이 검토 게이트에서조차 이해 못 하게 되는** 다크 팩토리의 인간 쪽 실패다. 이 글이 그 전부를 한 도표로 정리한다.

### 핵심 전이 3 — 백프레셔 = 평가 가능성이 자율성의 상한이라는 보편 법칙

*"자율성은 값싸게 검증 가능한 범위까지만"*은 이 가든이 여러 각도에서 말한 것의 **가장 깔끔한 정식화**다 — [[2026-07-18-ai-music-video-arena-fable-vs-sol]]("평가 함수 없으면 정체"), 방법론의 자가수정 루프("DoD를 실행 가능한 체크로"), [[2026-07-20-synthetic-customers-bain]]("백테스트로 신뢰 증명 후에만"). **핵심은 검증 가능성이 자율성의 상한을 정한다는 것** — 검증할 수 없는 걸 자동화하면 결함이 불가피하다. 이건 [[2026-07-22-taste-cannot-be-delegated]]의 *"안목=평가 함수"*와도 만난다: 평가 함수(안목·테스트·백테스트)가 있는 만큼만 위임하고, 없으면 사람이 판단한다.

### 핵심 전이 4 — "상태 머신으로 돌아가라"·"제어 흐름을 소유하라" = 하네스 논제의 결론

*"순수 루프 대신 상태 머신·그래프로 제어 흐름을 소유하라 — 우리는 항상 흐름도를 알았다"*는 이번 주 하네스 논제([[2026-07-18-state-of-open-source-ai-2026-mozilla]] "하네스가 모델을 이긴다")의 **엔지니어링 결론**이다. 모델을 키우는 게 아니라 **결정적 제어 흐름(그래프)으로 감싸는** 것 — [[2026-07-15-wrapping-the-unpredictable-genius]]의 *"해자는 wrap"*·[[2026-07-13-own-the-outer-loop]]과 같은 처방이 여기선 "상태 머신"이라는 오래된 도구로 착지한다. David Khourshid의 *"새 옷 입은 상태 머신"*이 정확 — AI 오케스트레이션의 답은 새 발명이 아니라 **잊었던 제어 흐름 설계**다.

## 호스피탈리티 / CRS 적용 포인트

이번 주 글 중 **온다 AI 도입의 운영 매뉴얼로 가장 직접적**이다.

- **인증·결제·정산엔 불을 켜둔다(§7).** CRS의 비싼 결정(결제·정산·권한)은 다크 팩토리 금지 — 인간 검토 + 결정적 코드. "깨진 정산을 보며 깨어나기 싫으면."
- **백프레셔로 자동화 범위를 정한다.** 온다에서 자동화할지는 "이걸 값싸게·안정적으로 검증할 수 있나"로 판단 — 초록/빨강 오라클(테스트·타입)이 있는 태스크만 완전 자동화, 없으면 사람이 게이트.
- **이해 부채를 지표로 감시.** AI가 만든 코드가 초록 테스트여도 **아무도 안 읽은 코드의 비율**을 본다 — explain-diff류 이해 게이트([[2026-07-23-geoffrey-litt-explain-diff]])를 머지 전에.
- **계획을 검토, 코드가 아니라.** "200줄 계획 > 2,000줄 코드 읽기" — 판단을 상류로(스펙·설계 검토), 방법론의 plan/spec 단계가 곧 밝은 팩토리.
- **제어 흐름을 그래프로 소유.** 온다 에이전트 워크플로를 순수 루프가 아니라 상태 머신(필수 검사점 명시)으로 — 실패 지점 특정·검증 용이.
- **증거 기반 감시 = 아키텍처가 안전망.** 타입·테스트 시임·명확한 경계가 곧 값싼 리뷰 — MySQL 가이드([[2026-07-23-mysql-survival-guide]])의 스키마·타입 규율이 여기서도 안전망.
