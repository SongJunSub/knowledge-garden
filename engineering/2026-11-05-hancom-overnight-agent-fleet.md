# 한글과컴퓨터, 오버나이트 에이전트 플릿(Overnight Agent Fleet) 구축 체크리스트

> 출처: [오버나이트 에이전트 플릿(Overnight Agent Fleet) 구축 체크리스트](https://tech.hancom.com/overnight-agent-fleet/) (한글과컴퓨터 기술블로그) · 정리일 2026-11-05

## 한 줄 요약

**여러 자율 에이전트를 격리된 환경에서 병렬로 실행해 밤사이 반복 업무를 처리하는 운영 방식을 체크리스트로 정리한 글. 사람은 최종 판단과 검토만 담당하고 기계는 실행을 전담하며, 오케스트레이션 계층이 다수 에이전트를 안전하게 관리하는 구조로 개발 생산성을 극대화한다.**

## 핵심 포인트

- ***여러 자율 에이전트를 격리된 환경에서 병렬로 실행***해 밤사이 반복 업무(버그 재현, 테스트, PR 초안 작성 등)를 처리하는 운영 방식.
- ***사람은 최종 판단과 검토를 담당***하고 ***기계는 실행을 전담***하는 분업 구조 — 설계·검증은 사람, 반복 실행은 에이전트.
- ***오케스트레이션 계층을 통해 다수의 에이전트를 효율적으로 관리***하고 안전한 작업 환경(격리)을 구축.
- Slack 발췌가 말미에서 끊겨 구체적인 체크리스트 항목(몇 개 에이전트를 어떤 기준으로 병렬화하는지, 실패 시 롤백 정책 등)은 확인하지 못함.

## 내 생각 · 적용점

### 핵심 전이 1 — "밤새 돌리고 아침에 리뷰"는 이미 레포에 있는 병렬 에이전트 패턴의 변주

여러 에이전트를 격리된 워크트리/환경에서 병렬 실행하고 사람이 최종 리뷰만 담당한다는 구조는 [[2026-08-08-orca-parallel-coding-agents-ade]], [[2026-08-08-paseo-coding-agent-orchestrator]], [[2026-09-26-ordewell-multi-agent-orchestrator]]와 같은 계열이다. 차이는 **"오버나이트"라는 시간 축을 명시**한 것 — 사람이 자는 시간을 에이전트의 가동 시간으로 쓴다는 운영 철학이 추가됐다. 이건 이 가든을 돌리는 이 스케줄 루틴 자체와도 같은 발상이다: 매일 저녁 7시에 자동으로 트리거되어, 사람이 없는 동안 수집·정리·커밋까지 끝내고, 사람은 다음 날 결과만 검토한다.

### 핵심 전이 2 — 오케스트레이션 계층이 "안전한 작업 환경"을 책임진다는 전제

사람이 매번 각 에이전트의 권한·격리를 점검하지 않고 오케스트레이션 계층에 위임한다는 구조는 [[2026-08-28-general-vm-not-enough-agent-isolation]]이 지적한 "VM만으로는 에이전트 격리가 충분하지 않다"는 경고와 맞닿아 있다. 체크리스트가 구체적으로 공개되지 않아 확인은 못 했지만, 이 글의 전제(격리+오케스트레이션=안전)가 실제로 얼마나 엄격한 샌드박싱을 의미하는지는 검증이 필요한 지점이다.

## 호스피탈리티 / CRS 적용 포인트

직접 적용 가능성이 있다. CRS/PMS 운영에서도 "야간 배치"는 이미 익숙한 개념(night audit, 요금 재계산, 재고 동기화)인데, 이를 **자율 에이전트 플릿**으로 대체하는 모델로 재해석할 수 있다. 예: 야간에 여러 에이전트가 각 채널(OTA)별 재고 불일치를 격리된 환경에서 병렬로 점검·재조정하고, 사람은 아침에 예외 케이스만 검토하는 구조. 다만 호텔 재고·요금 데이터는 되돌리기 어려운 사업 영향(오버부킹, 요금 오류)을 낳을 수 있어, 체크리스트의 "격리·검증·롤백" 기준이 CRS 맥락에서는 훨씬 엄격해야 한다.
