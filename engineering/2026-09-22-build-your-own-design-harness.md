# 나만의 디자인 하네스 만들기

> 출처: [GeekNews 토픽](https://news.hada.io/topic?id=34096) (원문 매체·저자 특정 실패) · 정리일 2026-09-22
>
> **출처 한계**: `news.hada.io` egress 차단으로 원문 접근 불가. Slack GN⁺ 발췌만으로는 원문 저자·매체를 특정하지 못했다. WebSearch로 "디자인 하네스" 관련 여러 국내 사례(Buzzvil, wannysim 등)를 확인했으나 이 GeekNews 토픽 원문과 정확히 일치하는 글은 찾지 못해, Slack 발췌 중심으로 재구성했다.

## 한 줄 요약

**디자인 하네스는 에이전트의 행동 규칙과 디자인 기준을 담은 텍스트 폴더를 기반으로, 캔버스와 클릭 가능한 HTML 프로토타입과 실제 코드를 오가며 작업하는 환경이다 — 빈 화면에서 시작하지 않고 실제 제품 컴포넌트에서 출발해 AI로 여러 변형을 만들고, 캔버스에서 비교·수정하며 하나의 방향으로 좁혀나가는 것이 핵심이다.**

## 핵심 포인트

- **행동 규칙 + 디자인 기준을 텍스트 폴더로 관리** — 디자인 하네스는 에이전트의 ***행동 규칙과 디자인 기준을 담은 텍스트 폴더***를 기반으로, 캔버스와 HTML 프로토타입, 실제 코드를 오가며 작업하는 환경이다.
- **규칙 파일은 세션마다 교정하되 오래된 맥락은 정리** — 규칙 파일과 디자인 참조 파일에 ***도구 사용법, 금지 사항, 디자인 토큰과 작업 방식***을 기록하고, 세션마다 교정 내용을 반영하되 오래된 맥락은 정리해야 한다 — 즉 규칙 파일 자체도 살아있는 문서로 계속 다듬어야 한다는 뜻이다.
- **빈 화면이 아니라 실제 컴포넌트에서 출발** — 빈 화면 대신 ***실제 제품 컴포넌트에서 출발해 AI로 여러 변형을 만들고***, 캔버스에서 비교하고 직접 수정한 뒤 하나의 방향으로 좁혀간다.
- **클릭 가능한 HTML 프로토타입으로 실제 상호작용을 경험** — 클릭 가능한 HTML 프로토타입으로 ***호버, 스크롤, 전환을 직접 경험…*** (발췌 절단) — 정적 목업이 아니라 실제 인터랙션을 체감할 수 있는 프로토타입을 만드는 것이 목표로 이어지는 것으로 보인다.

## 인상 깊은 문장

## 댓글

**확인 불가.** hada 댓글 수를 대조하지 못했다. "디자인 하네스"라는 개념 자체가 아직 표준화되지 않은 신조어라, 원문이 개인 실무 경험담인지 특정 도구(캔버스 기반 디자인 툴)의 홍보 콘텐츠인지 판단할 근거가 부족하다.

## 내 생각 · 적용점

### 핵심 전이 — 가든의 "코딩 하네스" 원칙이 디자인 영역으로 확장된 구체적 사례

가든에는 이미 [[2026-04-28-agent-harness-engineering]], [[2026-06-08-harness-engineering-jaehong]], [[2026-08-06-harness-engineering-for-self-improvement]] 등 "에이전트를 위한 규칙 파일 + 반복 개선"이라는 하네스 엔지니어링 원칙을 코딩 영역에서 다룬 노트가 많이 쌓여 있다. 이 글은 같은 원칙(규칙 파일, 세션마다 교정, 오래된 맥락 정리)을 ***디자인·프로토타이핑 워크플로에 그대로 이식***한 사례다 — "빈 화면에서 시작하지 않고 실제 컴포넌트에서 출발한다"는 원칙은 [[2026-06-08-design-with-claude-more-than-figma]]가 다룬 "Claude로 디자인하기"의 실무 팁과도 정확히 연결된다.

### 클로드 사용자 관점에서 — 이 가든 저자가 직접 참고할 만한 워크플로

이 저자가 Claude(Claude Code, Artifact 등)로 프로토타입을 만들 때, 매번 새 화면을 요청하기보다 "기존 컴포넌트를 기준점으로 주고 변형을 요청 → 캔버스/Artifact에서 비교 → 하나로 좁히기"라는 워크플로를 그대로 따라 해볼 만하다. 또한 CLAUDE.md 같은 규칙 파일을 "한 번 쓰고 방치"하지 않고 세션마다 다듬되 오래된 지시는 정리하라는 조언은, 이 가든 자체의 CLAUDE.md 운영 방식에도 그대로 적용되는 원칙이다.

## 호스피탈리티 / CRS 적용 포인트

CRS·PMS UI를 새로 디자인할 때, 기존 화면 컴포넌트를 기준으로 AI에게 변형안을 여러 개 만들게 하고 클릭 가능한 HTML 프로토타입으로 실제 호버·전환을 체험한 뒤 방향을 좁히는 워크플로는, 디자이너 리소스가 부족한 조직에서 빠르게 여러 대안을 검증하는 데 유용할 수 있다. 다만 "행동 규칙·디자인 토큰을 텍스트 파일로 관리"하는 부분은 사내 디자인 시스템 문서와 중복되지 않도록 정리해야 한다.
