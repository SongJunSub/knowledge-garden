# 홈랩 AI 개발 플랫폼 — '검토되지 않은 코드는 배포되지 않는다'는 승인 게이트 구조 (도구 철학·통제권·하네스 라인)

> 출처: rsgm.dev (GeekNews 경유) · 정리일 2026-06-08

## 한 줄 요약

**저자가 *홈랩(약 12개 Docker Compose 스택) 관리*를 위해 *코딩 에이전트 + Git 워크플로우 + GitOps*로 AI 개발 플랫폼을 만든 경험. 핵심은 도구 조합이 아니라 ***안전 구조***다: ***"검토되지 않은 코드가 배포되지 않는다" — AI는 Git 브랜치만 푸시할 수 있고, 인간이 PR을 승인한 뒤에야 GitOps가 배포***한다. 효과: *컨테이너 버전 업그레이드가 "몇 시간 → 릴리스 노트 요약 몇 분"*으로 간편. 한계: *CI 피드백 연동(로그 API 제한)이 아직 거칠다*.**

## 핵심 포인트 (전이 가능한 구조 중심)

- **승인 게이트 = "AI는 제안, 인간은 승인, 자동화는 배포"** — *AI 권한 = 브랜치 푸시까지*, *배포 권한 = 인간 PR 승인 후 GitOps*. **[[2026-06-08-ai-agent-dn42-bankrupted-operator]] *$6,531 파국(검토 없는 위임)*의 정확한 반대 설계** — 같은 에이전트 자율이라도 *승인 게이트가 있으면 안전, 없으면 폭주*.
- **하네스는 하네스일 뿐, 모델은 교체 가능** — 댓글: *"OpenCode는 하네스일 뿐, 온라인 아무 모델에나 연결 가능"*. **[[2026-06-08-designing-loops-with-fable-5]] *하네스 = 평가·실행 환경*·[[2026-06-08-open-source-ai-must-win]] *모델 교체 가능=통제권*의 실천** — *하네스에 투자하면 모델 종속이 준다*.
- **생산성은 "읽기·판정"의 압축에서** — *릴리스 노트 요약을 몇 분에 읽고 판정*. **[[2026-06-08-dont-trust-large-context-windows]] *짧은 세션+산출물*과 정합** — AI가 *생성·요약*하고 사람이 *판정·승인*.
- **현실 한계 (정직)** — 댓글: *"홈랩 AI는 미묘한 설정 문제로 엄청난 디버깅 → 전체적으로 손해일 때도, 좁게 지정한 작업만 괜찮고, 무엇을 물어야 하는지 이미 알아야"*.

## 인상 깊은 문장

> "No unreviewed code gets deployed — the AI can only push a branch; a human approves the PR, then GitOps ships it."
> (검토되지 않은 코드는 배포되지 않는다 — AI는 브랜치만 푸시할 수 있고, 인간이 PR을 승인한 뒤 GitOps가 배포한다.)

## 내 생각 · 적용점

### 5번째 라인업 *도구 철학·통제권·하네스 라인* (친/axelk 축과 직교, 카운팅 무관)

*AI 능력 찬반*이 아니라 *에이전트를 안전하게 위임하는 구조*. 라인 자산(카운팅 무관). 부채 *−1 유지* (49:39 ≈ 1.26:1).

### 핵심 전이 1 — "제안–승인–배포"의 권한 분리

가장 전이력 높은 구조: ***AI=제안(브랜치), 인간=승인(PR), 자동화=배포(GitOps)***. 이는 [[2026-06-08-ai-agent-dn42-bankrupted-operator]] *"신용카드+임무만 쥐어준 파국"*의 정확한 해독제 — **에이전트에 "쓰기·실행" 권한을 직접 주지 말고, "제안"까지만 주고 사람이 게이트**. [[2026-06-08-human-attention-human-effort]] *검토는 사람 몫*·[[2026-05-09-agents-need-control-flow]] *정지 조건*·[[2026-06-08-formal-methods-future-of-programming]] *검증 게이트*의 운영 구현. 사용자의 개인 프로젝트(stock-autotrader·CRS)에 **"AI는 PR만, 배포는 사람 승인 후"**를 기본값으로.

### 핵심 전이 2 — "하네스는 하네스일 뿐" = 모델 종속 회피

*"OpenCode는 하네스일 뿐, 아무 모델에나 연결"*은 [[2026-06-08-open-source-ai-must-win]] *통제권*·[[2026-06-08-local-llms-for-agentic-coding]] *"하네스가 모델을 끌어올림"*의 실천 — **하네스(워크플로우·승인 게이트·도구)에 투자하면, 모델은 비용·정책에 따라 교체 가능**. *값비싼 GPU 없이도(호스팅 모델 연결) 0달러로 시작 가능*. [[2026-06-08-dont-trust-large-context-windows]] *하네스 제약으로 컨텍스트 통제*와 같은 줄기.

### 핵심 전이 3 — "다들 같은 걸 재발명한다" = 공유의 가치

댓글 3의 *"수많은 사람이 독립적으로 같은 패턴을 만드는데 공유는 적다(99% 해킹, 1% 공유)"*는 **이 가든의 존재 이유와 정확히 같다** — *경험을 글로 남기는 1%가 희소재*. 단 *"기술인은 무료를 기대"*하는 함정도 인식(변호사 일화). 개인 프로젝트의 *셋업·교훈을 문서화*하는 것이 [[2026-06-08-dont-trust-large-context-windows]] *"문서화가 진짜 memory"*처럼 자산.

### 현실 보정 — "좁은 작업엔 좋지만 도메인 지식이 전제"

댓글 8 답글의 정직한 단서: *홈랩 AI는 미묘한 설정에선 디버깅 손해, 좁은 작업만 괜찮고, "무엇을 물어야 하는지 이미 알아야"*. 이는 [[2026-06-08-just-upload-to-chatgpt-translator]] *"AI 확신은 검증 능력에 반비례"*와 정합 — **AI 홈랩은 "내가 이미 아는 영역"을 빠르게 하지, "모르는 영역"을 대신 알아주진 않는다**. 도메인 지식이 전제.
