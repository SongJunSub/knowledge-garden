# 덜한 것이 더 낫다, 대체로 (jakub.kr) — 'AI는 추가를 쉽게 만들지만 제거는 여전히 인간의 영역', 무엇을 만들지 말아야 할지 아는 것이 가장 핵심 능력

> 출처: [Less is More, More or Less](https://jakub.kr/writing/less-is-more) (jakub.kr) · 정리일 2026-07-06

## 한 줄 요약

**AI 시대에 "더 많이 만드는 것"과 "더 잘 만드는 것"은 별개다. 뇌는 에너지 절약 기계라 단순한 것을 선호하며(처리 유창성), AI는 기능 추가를 극도로 쉽게 만들지만 "의도적 판단을 통한 제거"는 여전히 인간의 영역이다. 코드량보다 이해·판단·취향이 핵심 역량이 되며, "무엇을 만들지 말아야 할지 아는 것"이 가장 중요한 능력이다.**

## 핵심 포인트

- **단순함의 가치** — 뛰어난 제품은 작은 결정과 디테일이 쌓여 만들어짐. "완벽함은 더 이상 더할 것이 없을 때가 아닌, 더 이상 뺄 것이 없을 때다"(생텍쥐페리).
- **처리 유창성(Processing Fluency)** — 뇌는 에너지 절약 기계. 처리하기 쉬운 것일수록 친숙하고 **더 신뢰할 만하게** 느껴짐.
- **AI의 양날의 검** — AI는 코드 추가를 매우 쉽게 만들지만, **제거는 의도적이고 깊은 이해가 필요**. "진정한 단순함은 불필요한 것을 없애는 게 아니라 복잡함에 질서를 부여하는 것"(조니 아이브).
- **macOS 컨텍스트 메뉴 사례** — 하루 200회 사용되는 메뉴에 300ms 애니메이션 적용 시 **연간 6시간 이상**을 애니메이션 대기에 소비. 사용 패턴을 이해해야 올바른 설계 결정 가능.
- **엔지니어의 역할 변화** — 코드 생산량이 아닌 **코드 품질 판별 능력**이 중요. `+688−3,073` 같은 삭제 중심 리팩토링을 축하하는 문화(Interfere 사례).
- **AI와 함께 작업하는 7가지 원칙**:
  1. 에이전트에 사고를 아웃소싱하지 않기
  2. 모든 산출물에 비판적 태도 유지
  3. 추가된 각 코드 줄의 목적 이해하기
  4. 최종 결과 개선 여부 검토하기
  5. 에이전트는 당신의 연장선
  6. 맥락 최대한 제공하기
  7. 이해 안 되는 부분은 AI에게 설명 요청하기

## 내 생각 · 적용점

### 핵심 전이 1 — "삭제 중심 리팩토링을 축하하는 문화"가 CRS 코드 리뷰 문화에 직접 적용 가능

`+688−3,073` 같은 diff를 축하하는 문화는, [[2026-06-30-code-review-purpose-maintainability]]의 "이해하기 어려운 코드를 찾는 것"과 정확히 같은 방향이다. **CRS PR 리뷰에서 코드 추가보다 코드 제거를 더 높게 평가하는 명시적 문화를 도입하면, AI가 쉽게 만들어내는 불필요한 코드 증식을 견제할 수 있다.**

### 핵심 전이 2 — 7가지 원칙이 [[2026-07-03-short-leash-ai-coding-method]]·[[2026-07-03-agent-autonomy-levels]]와 통합된다

"에이전트에 사고를 아웃소싱하지 않기", "추가된 각 코드 줄의 목적 이해하기"는 지난주 정리한 "짧은 목줄" 방법론·"에이전트 자율성 수준"의 실무적 체크리스트와 정확히 겹친다. **이 7가지 원칙을 CRS 팀의 AI 코딩 가이드라인 문서로 정식화하는 것이 실무적으로 유용하다.**

### 핵심 전이 3 — macOS 애니메이션 사례가 [[2026-07-06-if-youre-a-button-one-job]]과 정확히 대구를 이룬다

지난번 정리한 "버튼이라면 할 일은 하나뿐" 글의 "애니메이션은 사용자를 구속하는 수단이 아니다"라는 원칙과, 이 글의 "하루 200회 사용에 300ms 애니메이션=연 6시간 낭비"라는 구체적 계산이 서로를 보강한다. **CRS 관리자 UI에서 반복적으로 쓰이는 모든 애니메이션 요소에 이 계산법("사용 횟수 × 애니메이션 시간 = 연간 누적 손실")을 적용해볼 가치가 있다.**
