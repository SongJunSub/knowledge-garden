# tar-codec - uv가 도입한 빠르고 안전한 Rust tar 파서 (GeekNews)

> 출처: [GeekNews](https://news.hada.io/topic?id=36141) · Slack `#개발-뉴스-dev-news`(GeekNews 자동봇) 경유 · 정리일 2026-10-28

> **출처 한계**: `news.hada.io` 이 세션에서 egress 전면 차단(WebFetch `getaddrinfo ENOTFOUND` 확인). GitHub 저장소 자체도 열람하지 못해, 이 노트는 Slack 자동봇 발췌 3줄(마지막 줄 끊김)만으로 작성했다. 실제 벤치마크 환경, tar-codec의 구체적 모호성 해소 규칙, 실제로 이 취약점을 이용한 공격 사례가 있었는지는 확인하지 못했다.

## 한 줄 요약

**Python 패키지 관리자 uv를 만든 Astral이, 같은 tar 아카이브를 도구마다 다르게 해석하는 문제를 보안 위협으로 보고 Rust 라이브러리 tar-codec을 새로 개발했다 — 조작된 아카이브가 패키지 인덱스의 검사 단계에서는 정상 파일로 보이지만 실제 설치 도구에서는 다른 파일이나 악성 내용을 추출하게 만드는 "파서 간 불일치 공격"을 막기 위해, 첫 헤더에서 형식 계열을 고정하고 모호한 혼용을 거부하도록 설계했다. uv 자체 벤치마크에서 기존 구현보다 약 2배 빨라 uv 0.13부터 기본으로 쓰인다.**

## 핵심 포인트

- **동기는 속도가 아니라 보안** — tar는 여러 형식(ustar, GNU, pax 등)과 확장이 누적된 포맷 계열이라, ***헤더의 크기·이름을 어떤 순서로 해석하느냐에 따라 같은 파일에서 다른 결과가 나올 수 있다***. 패키지 인덱스의 검사 도구와 실제 설치 도구가 서로 다른 파서를 쓴다면, 검사는 통과하지만 설치 시점에 다른(악성) 내용이 풀리는 공격이 가능해진다.
- **설계 원칙 — 모호함 자체를 거부** — tar-codec은 ***첫 헤더에서 형식 계열을 한 번 고정하고, 이후 모호한 형식 혼용을 거부***하도록 만들어졌다. "더 정확하게 해석한다"가 아니라 "해석이 갈릴 수 있는 입력 자체를 걸러낸다"는 방향이다.
- **부수적 성능 이득** — uv 자체 벤치마크에서 기존 구현보다 ***약 2배 빠르며***, uv 0.13부터 ***기본값***으로 적용된다.

## 내 생각 · 적용점

**핵심 전이 — [[2026-06-08-aur-supply-chain-malware]]와 "검증 신호가 실제 동작을 보장하지 않는다"는 같은 구조.** 그 글은 AUR 패키지 공격에서 ***git 커밋의 author 이름이 인증이 아니라 자기 신고일 뿐***이라, 신뢰 신호(메인테이너 이름) 자체를 검증 없이 위조할 수 있었다는 걸 짚었다. tar-codec이 막으려는 문제는 메커니즘은 다르지만 같은 패턴이다 — ***검사 도구가 "정상"이라고 판정한 신호가, 실제 실행 시점의 동작을 보장하지 않는다***는 것. AUR 사례는 신뢰 신호(이름)가 위조됐고, 이 사례는 해석 결과(파일 내용) 자체가 도구마다 갈린다. 둘 다 "검증 단계와 실행 단계가 분리돼 있으면 그 틈이 공격 표면이 된다"는 공급망 보안의 일반 원칙을 각자의 층위에서 보여준다.

## 호스피탈리티 / CRS 적용 포인트

**직접 적용은 제한적이다** — 온다 CRS가 tar 아카이브를 직접 파싱하는 경우는 드물다. 다만 전이 가능한 원칙은 있다: CI/CD 파이프라인에서 서드파티 패키지·아카이브를 다룰 때 "검사 단계의 도구"와 "실제 설치/배포 단계의 도구"가 같은 파서·같은 해석 규칙을 쓰는지 점검하는 것 — 이 둘이 다르면 tar-codec이 막으려 한 바로 그 틈이 생긴다.
