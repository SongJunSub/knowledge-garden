# Git 2.56과 3.0을 내다보며

> 출처: [Git 2.56과 3.0을 내다보며](https://news.hada.io/topic?id=34124) (LWN.net, GeekNews 경유) · 정리일 2026-09-23
>

## 한 줄 요약

**Git 2.56(9월 말 출시 예정)은 이력 편집과 브랜치 관리 편의성을 높이는 `git history drop`, `git branch --delete-merged`, `git add --resolved`를 추가하고, 아직 논의 중인 Git 3.0은 새 저장소의 기본 해시를 SHA-1에서 SHA-256으로 전환할 예정이라 주요 호스팅 서비스·외부 도구의 지원 여부가 전환 시점을 좌우한다.**

## 핵심 포인트

- **Git 2.56은 9월 말 출시 예정, 700개 이상의 non-merge 커밋** — WebSearch 확인으로는 700개가 넘는 non-merge 커밋을 담았으며, 다음 버전을 Git 3.0으로 낼지는 아직 논의 중이다.
- **`git history drop`으로 특정 커밋을 이력에서 제거** — 특정 커밋을 이력에서 제거하는 ***`git history drop`***이 추가됐다. 지정한 커밋 이후의 모든 커밋을 재생하는 방식이며, 아직 실험적(experimental) 단계로 ***병합 커밋이 있는 이력에서는 실패***한다.
- **병합된 로컬 브랜치를 정리하는 `git branch --delete-merged`** — 병합된 로컬 브랜치를 정리하는 ***`git branch --delete-merged`***, 충돌을 해결한 파일만 스테이징하는 ***`git add --resolved`***가 추가됐다 — 둘 다 이미 서드파티 도구들이 채워왔던 편의 기능을 코어에 흡수한 사례다.
- **Git 3.0의 핵심은 새 저장소 기본 해시를 SHA-256으로 전환** — Git 3.0은 새 저장소의 기본 해시를 ***SHA-1에서 SHA-256으로 전환***할 예정이며, 주요 호스팅 서비스와 외부 도구의 지원이 전환 시점을 좌우한다.
- **브랜치·태그 정보를 저장하는 기본 방식도…** [GeekNews 발췌 문장 잘림]. WebSearch 확인으로는 `refs/` 파일 기반 저장 방식에서 `reftable` 같은 참조 저장 방식으로의 전환 논의도 진행 중인 것으로 보인다.

## 인상 깊은 문장

## 내 생각 · 적용점

### 핵심 전이 — Git 코어가 서드파티 도구의 편의 기능을 계속 흡수하는 패턴

가든에는 [[2026-09-21-worktrunk-git-worktree-cli]](Git worktree를 감싸는 서드파티 CLI 도구)가 있다. 이번 Git 2.56의 `--delete-merged`, `--resolved` 추가는 정확히 그런 서드파티 도구들(`git-delete-merged-branches` 같은 PyPI 패키지 등)이 오래 메워온 틈을 코어가 흡수하는 흐름을 보여준다 — 생태계에서 반복적으로 필요성이 검증된 기능이 결국 코어로 승격되는 패턴은 Git뿐 아니라 여러 성숙한 도구 생태계에서 반복된다.

## 호스피탈리티 / CRS 적용 포인트

직접 적용은 CRS 도메인과 거리가 있지만, 개발 인프라 관점에서는 두 가지를 점검할 만하다. 첫째, 이미 서드파티 스크립트로 `--delete-merged` 유사 기능을 쓰고 있다면 Git 2.56 릴리스 이후 코어 명령으로 교체할 수 있는지 확인. 둘째, Git 3.0의 SHA-256 전환은 아직 먼 이야기지만 CI/CD·저장소 훅이 커밋 해시 길이(40자 SHA-1)를 하드코딩하고 있지 않은지 미리 점검해두면 향후 전환 비용을 줄일 수 있다.
