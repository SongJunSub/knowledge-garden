# 병목은 결코 코드가 아니었다

> 출처: [The Typical Set — Thoughts on Coding Agents](https://www.thetypicalset.com/blog/thoughts-on-coding-agents) · 레퍼러: [GeekNews 29238](https://news.hada.io/topic?id=29238) · 정리일 2026-05-07

## 한 줄 요약
코딩 에이전트가 *코드 생산*은 가속했지만, 진짜 병목은 *"무엇을 만들지"에 대한 합의·공유 맥락·조직 일관성*이었다. AI는 새 능력을 추가한 게 아니라 **조직의 기존 문제를 드러내는 도구**.

## 핵심 주장

### 1. 진짜 병목 — *코드가 아니라 협상*
- *코드 작성*은 표면. *무엇을 만들 것인가에 대한 합의*가 본질
- 명확한 명세·수락 기준·설계 문서가 *새 제약*
- 에이전트가 구현 속도를 올리자 *관리자가 명세 생산을 따라가지 못함*

> "소프트웨어는 인간들이 무엇을 만들어야 할지 서로 협상한 후 남은 것이다."

> "협상, 합의, 우리가 무엇을 만드는지에 대한 공유 이해가 실제 일이 되었다."

### 2. 제번스 역설 (Jevons Paradox)
- 코드 작성 비용 10x ↓
- *같은 결과에 10%만 투자*가 아니라 → **전에는 가치 없던 기능까지 만들기 시작**
- → *집중의 규율*이 더 중요해짐

> *Steve Jobs (1997)*: "초점은 거절함을 의미한다."

### 3. 맥락 = 새 통화 (Context as Currency)
- 에이전트는 *옆에 있기, 회의 참석, 새벽 2시 장애 함께 겪기*로 학습 못함
- *문서화되지 않은 것*이 조직 속도를 결정하는 새 제약

> "에이전트는 침투할 수 없다. 대화를 옆에서 듣거나 새벽 장애를 함께 처리하며 맥락을 얻지 못한다."

### 4. 다음 10년의 경쟁 우위
- *최고의 모델 보유* X
- ***조직 일관성을 유지하면서 산출을 늘리는 회사*** O
- 도구는 기존 역량의 *배수* — 좋은 조직은 더 좋아지고, 나쁜 조직은 *빠르게 망함*

> "좋은 조직은 더 나아졌고, 나쁜 조직은 빠르게 망했다."

### 핵심 하나 — *"맥락은 침투할 수 없다"*
이 한 줄이 [Glaser의 *Loop Intelligence*](2026-05-07-when-everyone-has-ai-but-company-learns-nothing.md)·[Mattpocock의 *CONTEXT.md*](../ai/2026-04-29-mattpocock-skills-vs-mangolove.md)·[의도 부채](2026-04-24-technical-cognitive-intent-debt.md)를 한 번에 묶는다:
- 새벽 장애 함께 처리한 경험은 *문서화 불가*
- 그러나 *문서화 시도라도 안 하면* 에이전트 시대에 *조직 속도 한계가 그것*
- → **CONTEXT.md / ADR / 운영 노트의 가치가 *돈으로 환산 가능한 자산*이 되는 순간**

### *제번스 역설*이 호스피탈리티에 적용되는 방식
*가속이 *덜 만들기*로 이어지지 않고 *더 많이 만들기*로 이어진다*는 통찰:
- CRS Admin 화면 추가가 *쉬워지면* → *전에 없던 화면도 추가*
- OTA 통합이 *쉬워지면* → *전에 안 했을 통합도 시도*
- *총 복잡도는 *증가*한다 — [Ding의 *코드 줄 수 = 비용*](../ai/2026-05-07-claude-code-not-making-your-product-better.md)이 같은 결론

→ **거절(refuse)이 더 비싸진 시대**. *덜 만드는 의사결정*이 *제품 차별 자산*이 됨 (= [Ferrari 라인](../ai/2026-05-07-claude-code-not-making-your-product-better.md))

### *조직 일관성*은 호스피탈리티의 핵심 자산
- 호텔 체인은 *수십 년 운영 일관성*이 브랜드 자산
- *AI 가속이 일관성을 깨면* → 단기 효율 < 장기 신뢰 손상
- *공정 데이터·정확 정산·SLA*가 [No One's Happy의 *신뢰 자산*](../ai/2026-05-07-appearing-productive-in-the-workplace.md)과 정확히 같은 결

### *다음 10년 = 조직 일관성 유지 회사가 이긴다*
이 결론이 가장 무겁다 — *기술적 우위*가 아니라 *조직 운영 우위*로 회귀:
- [Probabilistic Founder](../career/2026-05-05-rise-of-the-probabilistic-founder.md): 70% 실험 + Agent-Default Posture
- [Glaser 3축](2026-05-07-when-everyone-has-ai-but-company-learns-nothing.md): Operations / Loop / Capabilities
- 이 글: 조직 일관성 유지 + 산출 증가
- **세 글이 같은 결론** — *AI 시대 승자는 *조직력이 좋은 회사*다*

### MangoLove 적용 후보 — *Spec 우선* 강화
이 글이 [MangoLove `/strict` Spec 단계](../ai/2026-04-29-mattpocock-skills-vs-mangolove.md)의 *이론적 근거*를 강화한다:
- 분석 → **Spec → Spec 적대적 리뷰** 단계가 *과한 절차*가 아님
- 코딩이 빨라질수록 *Spec 명확성*이 진짜 병목
- *Spec 적대적 리뷰*를 *기본*으로 (현재 Medium 트랙은 옵션) 격상 검토

### 호스피탈리티 *Spec 부채* 점검 후보
- CRS·Connectivity·PickMe의 기존 기능 중 *Spec이 명확한 것*과 *암묵적인 것* 분류
- 암묵적인 것 = *AI 가속 시 가장 위험* — 에이전트가 다르게 해석
- 우선순위: *결제·재고·요금·환불·OTA 컨트랙트* — Spec 명문화 가치 큼

### 반론·균형점
- *"맥락은 침투할 수 없다"*는 *현재 AI* 한계. 5년 후엔 *지속 컨텍스트 + 전사 연결*로 일부 침투 가능 ([Long-running agents](../ai/2026-05-04-long-running-agents.md) 흐름)
- *조직 일관성 강조*가 *변화 회피의 핑계*로 변질될 위험 — *일관성 ≠ 정체*
- *제번스 역설*이 *모든 영역*에 적용되진 않음 — 일부 *내부 도구*에선 가속 = 단순 효율 향상

## 즉시 시도할 액션 3가지
1. **MangoLove `/strict`에 *Spec 적대적 리뷰* 단계를 *Medium에서 기본*으로 격상 검토**
2. **CRS·Connectivity·PickMe의 *Spec 부채* 영역 5개 식별** (결제·재고·요금·환불·OTA 컨트랙트 우선)
3. **PR 머지 직전 자문 추가**: *"이 변경이 거절(refuse)이 아닌 추가(add)라면, 왜 추가가 정답인가?"* — 제번스 역설 백신
