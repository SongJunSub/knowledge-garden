# Safari 27.3 베타에 Adaptive Dark Mode 도입(GeekNews)

> 출처: [GeekNews 토픽](https://news.hada.io/topic?id=36549) (원문 매체 미확인) · 정리일 2026-11-04
>
> **출처 한계**: `news.hada.io` 접근이 이번 세션에서 egress 차단으로 막혀 원문을 직접 열람하지 못했다. WebSearch로 "Safari 27.3 Adaptive Dark Mode"를 검색했지만 **2026년 11월 시점의 베타 릴리스 노트나 WebKit 블로그 원문을 찾지 못했다** — 검색 결과는 대부분 2018~2022년의 과거 "웹사이트별 다크모드" 관련 오래된 기사였다. 이 노트는 Slack 발췌에 전적으로 의존하며, 기술적 세부(특히 `color-scheme`의 `only` 키워드 미지원 범위)는 1차 원문 대조 없이 Slack 발췌 그대로 옮긴 것이다. 이 배치에서 확인 수준이 가장 낮은 노트다.

## 한 줄 요약

**Safari 27.3 베타의 Adaptive Dark Mode는 사용자가 활성화하면 다크 모드를 지원하지 않는 밝은 웹사이트를 색조는 유지한 채 밝기만 반전시켜 어둡게 바꿔주는 기능으로, 다크 모드를 이미 지원하는 사이트는 그대로 두고 텍스트 명도 대비를 WCAG 4.5:1 기준으로 맞춘다.**

## 핵심 포인트

- **지원 선언 사이트는 건드리지 않는다** — `color-scheme`으로 ***다크 모드 지원을 선언한 사이트나 이미 어두운 페이지는 그대로 두고***, 페이지 색상을 분석해 밝은 페이지에만 변환을 적용한다.
- **색조는 유지, 밝기만 반전** — ***색조를 유지하면서 밝기를 반전***시켜, 브랜드 색상 등 사이트 고유의 색감은 최대한 보존하려는 방식이다.
- **텍스트 대비는 WCAG 기준으로 재조정** — 텍스트는 ***WCAG 명도 대비 4.5:1***을 목표로 조정해, 단순 색 반전보다 접근성 기준을 신경 쓴 설계다.
- **개발자 제외 옵션은 아직 미완성** — 개발자가 `color-scheme`으로 자체 다크 스타일 적용 범위나 변환 제외 의도를 지정할 수 있지만, 제외에 필요한 **`only` 키워드는 Safari 27.3 베타 1에서 아직 지원하지 않는다**.

## 내 생각 · 적용점

레포를 Grep/Glob으로 직접 검색했지만, Safari의 "사이트 미지원 시 강제 변환"이라는 이번 메커니즘과 직접 겹치는 노트는 찾지 못했다. **직접 연결되는 기존 노트는 없다** — 억지로 연결하지 않는다.

## 호스피탈리티 / CRS 적용 포인트

**직접 적용은 멀다.** CRS 웹 UI가 브라우저의 Adaptive Dark Mode에 영향을 받을 수는 있지만(다크모드 미지원 페이지가 강제로 변환될 때 브랜드 색상 대비가 의도와 달라질 가능성), 이는 Safari 사용자 비중이나 실제 CRS 프런트엔드가 `color-scheme`을 선언했는지에 따라 달라지는 가정적 영향이다. 전이 가능한 원칙만 남기면: 웹 서비스가 `color-scheme: light`를 명시적으로 선언해 두면 브라우저가 임의로 강제 변환을 적용하는 상황을 피할 수 있다는 점은 체크리스트에 넣을 만하다.
