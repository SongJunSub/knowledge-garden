# D2Coding 1.4.0 릴리즈 (네이버 D2)

> 출처: [D2Coding 1.4.0 릴리즈 소식](https://d2.naver.com/news/7193556) (네이버 D2, Slack TechArticles 경유) · 정리일 2026-10-07

> **출처 한계**: `d2.naver.com` egress 차단으로 원문 미열람. WebSearch로 "D2Coding 1.4.0", GitHub `naver/d2-coding-font` 릴리즈를 교차확인했으나, 검색 결과가 확인한 최신 버전은 1.3.2~1.3.3(메타데이터 전용 릴리즈)까지였고 1.4.0을 다룬 독립 소스는 전혀 찾지 못했다(검색 인덱스에 아직 반영 안 됐거나, 세션 WebSearch 범위 밖일 가능성). 따라서 이 노트의 "핵심 포인트"는 Slack 발췌 세 불릿("...(이하 절단)"으로 끝남) 그 자체가 유일한 근거이며, 그 이상의 세부(정확한 릴리즈 날짜, 변경 파일 범위, 마이그레이션 영향)는 확인하지 못했다.

## 한 줄 요약

**D2Coding 1.4.0이 빗금 없는 점 형태의 0을 고를 수 있는 옵션을 추가하고, 일부 크기에서 틀어지던 기준선을 힌팅으로 보정하고, 코드 의미를 왜곡할 수 있는 마침표 리거처를 제거하는 등 가독성·정확성 중심의 소소한 개선을 담은 개발자 전용 모노스페이스 폰트 업데이트다.**

## 핵심 포인트

- ***빗금 없는 점 형태의 0 선택 기능*** 추가 — 기존에는 0과 O를 구분하기 위해 흔히 빗금(슬래시)이나 점을 넣는데, D2Coding은 이제 점 형태를 선택할 수 있게 됐다. 빗금 버전과 점 버전 중 어느 쪽이 기본값인지는 발췌에 없어 확인 불가.
- ***일부 글꼴 크기에서의 기준선 정렬 문제를 힌팅 보정으로 해결*** — 특정 포인트 크기에서 문자 기준선이 어긋나던 문제를 힌팅(hinting) 테이블 조정으로 고쳐 가독성을 개선했다고 한다.
- ***코드의 의미를 왜곡할 수 있는 마침표 관련 리거처 제거*** — 예를 들어 `...`나 `..`처럼 마침표가 연속될 때 리거처(여러 글자를 하나의 결합 글리프로 바꿔 보여주는 기능)가 적용되면 실제 문자 개수를 착각하게 할 수 있는데, 이런 위험한 리거처를 뺐다.
- ***한글 주석 내 리거처 적용 최적화*** — 한글 주석 안에서 리거처가 어색하게 적용되던 부분을 다듬었다고 하나, 구체적으로 어떤 리거처·어떤 상황인지는 발췌에 없다.
- 발췌가 "...(이하 절단)"으로 끝나 이 네 가지가 1.4.0의 전체 변경 목록인지 일부인지 알 수 없다.

## 내 생각 · 적용점

가벼운 개발자 도구 픽이라 억지로 전이를 만들지 않는다. 짚을 만한 연결은 하나다.

### 핵심 전이 1 — 한글 개발자 폰트라는 축에서 [[2026-07-06-jetendard-font-korean-devfont]]와 나란히 놓인다

Jetendard가 "JetBrains Mono Nerd Font + Pretendard"로 영한 혼용 코드 가독성을 노린 서드파티 조합 폰트였다면, D2Coding은 네이버가 직접 만들어 오래 유지보수해온 1차 공급자 폰트다. 이번 1.4.0의 "마침표 리거처 제거"는 Jetendard 노트가 지적했던 "한글 fallback에서 박스드로잉이 어긋나는" 류의 문제와 결이 비슷하다 — 둘 다 "의미를 왜곡하거나 깨지는 특수 글리프 처리"를 손보는 디테일이다.

## 호스피탈리티 / CRS 적용 포인트

**직접 적용은 거의 없다.** 개발자 코드 에디터 폰트라 CRS 제품의 사용자 대면 UI와는 무관하다. 억지로 끌어오자면 "0과 O처럼 혼동되는 문자를 명확히 구분하는 선택지를 준다"는 원칙 정도는, 예약번호·객실코드처럼 숫자·문자가 섞인 CRS UI에서 폰트 선택 시 참고할 만한 일반론으로만 남겨둔다.
