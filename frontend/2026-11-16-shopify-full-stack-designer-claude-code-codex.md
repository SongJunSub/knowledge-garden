# 새로운 풀스택 디자이너

> 출처: [The New Full-Stack Designer](https://www.sean-weldon.com/blog/2026-10-29-the-new-full-stack-designer) (Sean Weldon, Shopify Product Design Studio 사례) · GeekNews 경유 · 정리일 2026-11-16

## 한 줄 요약
**AI 코딩 도구가 구현을 대신 떠맡으면서, 디자이너의 일은 "그리기"에서 "직접 만들고 써보고 판단하기"로 확장되고 있다 — 단, 프로토타입 코드는 끝까지 프로덕션에 들어가지 않는다.**

## 핵심 포인트
- Shopify 제품 디자인 스튜디오(Marvin Schwaibold 주도)는 ***Figma를 정적인 스케치판으로, Codex·Claude Code를 "완성·실행" 담당***으로 역할을 재배치했다.
- 디자이너가 직접 작동하는 데모를 만들어 보여주는 쪽이 와이어프레임보다 ***아이디어 공유와 조직 합의를 더 빠르게 끌어낸다***.
- 그럼에도 ***"이건 프로덕션 코드가 아니다"***라는 선이 명확하다 — 프로토타입은 설득의 도구일 뿐, 실제 구현은 별도 엔지니어링을 거친다.
- 작업 단위를 복잡한 전체가 아니라 ***구성 요소로 쪼개고, 반복적으로 검토***하는 과정에서 시각적 품질과 상호작용의 최종 판단은 여전히 사람이 내린다.
- Shopify는 관리자 화면 리디자인과 동시에, Sidekick(AI 에이전트)과의 대화로 스토어를 직접 조작하는 경험도 병행 탐색 중이다.

## 내 생각 · 적용점
이 글은 가든의 "AI 코딩 도구가 역할을 재편한다" 계열([[2026-05-10-claude-code-html-effectiveness]])의 **디자인 직군 버전**이다. 지금까지 가든은 "개발자가 AI로 무엇을 잃고 얻는가"를 주로 다뤘는데, 이 글은 같은 재편이 디자이너에게도 번지고 있음을 보여준다 — 다만 "최종 판단은 사람"이라는 선은 [[2026-10-06-design-lead-is-not-the-decider]]가 다루는 "디자인 리드는 결정권자가 아니다"는 조직론과 결이 다르다(저긴 권한 구조, 이건 도구 활용 구조). 두 글을 나란히 두면 "디자이너의 영향력이 느는 축(직접 만들기)"과 "디자이너의 권한이 줄어드는 축(조직 결정권)"이 동시에 진행 중임이 드러난다.

## 호스피탈리티 / CRS 적용 포인트
온다의 CRS Admin·B2B 대시보드 디자인 과정에 적용 가능성 있음: 신규 화면 기획 시 Figma 와이어프레임 대신 Claude Code로 바로 작동하는 클릭 가능한 프로토타입을 만들어 세일즈·CS 팀과 공유하면, "말로 설명 → 상상"의 간극을 줄일 수 있다. 단, "프로토타입 코드 ≠ 프로덕션 코드"라는 Shopify의 선을 그대로 가져와야 한다 — 그렇지 않으면 프로토타입이 그대로 배포되어 기술 부채가 될 위험.
