## 한 줄 요약

**CSS 쪽 결과는 예상대로다. Anchor Positioning이 전년 대비 사용률 +15%로 조사 항목 중 최대 증가폭을 냈고, `:has()`(83.7%)·`aspect-ratio`(81.3%)·CSS Nesting(70.6%)은 이미 주류다. 프레임워크에서는 Tailwind가 1,854명으로 1위지만 "프레임워크 없음"이 1,042명으로 Bootstrap(982명)을 제치고 2위에 올랐고, CSS-in-JS는 미사용이 2,073명으로 가장 많다. 불만 1위는 인지 과부하(자유응답 86건)인데 CSS 만족도는 5점 만점 4.0으로 오히려 상승 추세다. 그런데 이 가든 입장에서 가장 값진 숫자는 따로 있다. AI로 생성한 CSS 비중이 평균 28%이고, 응답자 3,732명 중 980명(26%)이 0%라고 답했다. 다른 개발 영역과 정반대 방향이고, 응답자들의 설명은 "AI가 아직 좋은 CSS를 잘 못 만든다"였다.**

## 핵심 포인트

- **표본**: **4,902명**, **2026-05-15 ~ 06-29**, **17개 언어.** 완료율이 언어별로 **2%(히브리어)에서 81%(중국어 간체)**까지 벌어진다.
- **올해의 기능**: **Anchor Positioning.** 전년 대비 **사용률 +15%**로 조사 항목 중 **최대 증가폭**. 동시에 **브라우저 미지원 때문에 회피하는 기능 1위**이기도 하다. 같은 기능이 양쪽 1위다.
- **주류 진입**: **`:has()` 83.7% 사용**(긍정 51.8%), **`aspect-ratio` 81.3%**, **CSS Nesting 70.6%**(만족 48.6%).
- **인지도와 사용의 격차**: **Gap Decorations는 사용 3.7%인데 응답자의 55%가 "읽을 것 목록"에 넣었다.**
- **프레임워크**: **Tailwind CSS 1,854명(1위)**, **"프레임워크 없음" 1,042명(2위)**, **Bootstrap 982명(3위)**. 무프레임워크가 Bootstrap을 넘었다.
- **전처리기·CSS-in-JS**: **CSS-in-JS 미사용 2,073명**으로 최다, **Sass/SCSS 2,032명**은 여전히 강세.
- **AI 채택률이 이 설문의 이례값**: **AI 생성 CSS 평균 28%**, **3,732명 중 980명(26%)이 0%.** 자유응답의 요지는 ***"AI가 아직 좋은 CSS 코드를 잘 만들지 못한다"***.
- **없어서 아쉬운 기능**: **Mixins 43건**, Form Elements Styling 23건, Input 요소 문제 22건. **요청 총량 자체가 계속 줄고 있다.** Masonry는 새 `display: grid-lanes` 문법으로 해결되는 중.
- **불만**: **인지 과부하 1위(자유응답 86건)**, 브라우저 벤더 79건, 툴링 52건. **Grid 관련은 193건**으로 가장 많은데 채택률이 높으면서 학습 곡선이 남아 있는 탓.
- **만족도**: **CSS 만족도 5점 만점 4.0**, 뚜렷한 상승 추세. 웹 기술 전반은 3.8. 최다 응답(1,144명)은 ***"일부 기능을 알고 직접 시험해봤다"***.
- **설문 결론**(CSS 엔지니어 Sunkanmi Fafowora): ***"JavaScript 가 하던 일을 이제 CSS 가 할 수 있다."*** 그리고 **"웹 플랫폼 우선 접근"**을 권한다.

## 내 생각 · 적용점

### 핵심 전이 1: AI 채택률이 CSS 에서만 낮다는 게 이 설문의 진짜 기록이다

**가든의 8월은 거의 전부 AI 코딩 축이었다.** 27만 8,790건의 리뷰 대화, PR 102만 건, "AI 가 중산층을 없앤다", "AI 사용을 그만둔다". **그 흐름에 계속 없던 게 반례 데이터다.** 여기 있다: **평균 28%, 그리고 4분의 1은 아예 0%.**

**왜 CSS 만 다른가.** 가장 설득력 있는 설명은 **검증자 구조**라고 본다. 다른 영역에는 **값싼 자동 검증자**가 있다. 테스트가 돌고, 컴파일러가 잡고, 린터가 짚는다. **CSS 에는 그게 없다.** "이게 맞나"의 판정자는 사람의 눈이고, **그 판정자는 루프에서 뺄 수 없다.**

**그러면 이번 시즌 반복한 원칙이 여기서 강제된다.** [[2026-08-06-harness-engineering-for-self-improvement]]의 **"평가자는 루프 외부에"**가 CSS 에서는 선택이 아니라 물리적 조건이다. 그리고 [[2026-08-13-human-ai-synergy-agentic-code-review]]가 **"AI 는 결함 선별을 규모 있게 할 수 있다"**고 했는데, **CSS 에는 선별할 결함 신호 자체가 없다.** 신호가 없으니 규모의 이점도 없다.

**[[2026-07-22-taste-cannot-be-delegated]]의 설문 데이터이기도 하다.** 그 글이 주장으로 세운 걸 이 설문이 채택률로 잰다. **취향이 산출물의 판정 기준인 영역에서 AI 채택률이 실제로 낮다.**

**단서를 붙여야 한다.** ***"AI 가 아직 좋은 CSS 를 못 만든다"***는 **응답자의 자기 설명**이고, 다른 설명이 살아 있다: CSS 는 코드량 자체가 적어서, 이미 디자인 시스템이 있어서, **눈으로 고치는 게 프롬프트를 쓰는 것보다 빨라서.** 마지막 설명이 특히 그럴듯한데, 그렇다면 이건 **모델 능력 문제가 아니라 인터페이스 문제**이고 **시간이 지나면 사라질 이례값**이다. 이 설문은 그 둘을 구분하지 않는다.

### 핵심 전이 2: "프레임워크 없음"이 Bootstrap 을 제쳤다

**[[2026-07-20-what-happened-to-the-frontend]]가 8단계 44미터를 파내려간 끝에 도착한 결론이 "2026년 최전선은 서버 HTML·최소 JS·웹 플랫폼 활용"이었다.** 이 설문이 그 데이터다. **무프레임워크 1,042명 > Bootstrap 982명**, **CSS-in-JS 미사용이 최다(2,073명)**, 그리고 설문 결론이 문자 그대로 **"웹 플랫폼 우선 접근"**을 권한다.

**[[2026-05-17-jvns-moving-away-from-tailwind]]의 n=1 이 여기서 집계가 됐다.** Julia Evans 가 "추상화 도구가 학습 보조였다가 학습이 추상화를 넘어서면 짐이 된다"고 쓴 그 곡선을, 1,042명이 같은 방향으로 서 있다.

**단 과장하면 안 된다.** **Tailwind 는 여전히 1위이고 1,854 대 1,042 는 큰 격차**다. 정확한 서술은 "탈 프레임워크"가 아니라 **"무프레임워크가 진지한 선택지로 올라왔다"**이다. 그리고 위 감안 ①대로 **이 표본이 웹 플랫폼 신기능을 따라가는 집단에 치우쳐** 있어서, 그 방향으로 편향될 이유가 구조적으로 있다.

### 핵심 전이 3: 복잡도 불만 1위와 만족도 상승은 모순이 아니다

**인지 과부하가 불만 1위인데 만족도는 4.0에 상승 추세다.** 같은 사람들이 "너무 복잡해졌다"와 "더 만족한다"를 동시에 말한다.

**해석: 복잡도의 총량이 준 게 아니라 자리가 옮겨갔다.** 외부 도구(CSS-in-JS, Bootstrap, 빌드 체인)에 있던 복잡도가 **플랫폼(브라우저 표준)으로 이동**했다. CSS-in-JS 미사용 최다와 무프레임워크 2위가 그 이동의 흔적이다.

**그러면 [[2026-08-10-postgresql-mvcc-tradeoffs]]의 "비용은 사라지지 않고 자리만 옮긴다"에 한 줄을 더할 수 있다: 자리가 어디냐에 따라 체감이 다르다.** 플랫폼 복잡도는 **표준이라 오래 가고**, 도구 복잡도는 **몇 년마다 버려진다.** **같은 양의 복잡도라도 재학습 주기가 짧은 쪽이 훨씬 아프다.** 사람들이 CSS 가 복잡해졌다고 불평하면서도 만족도가 오르는 건, **배운 것이 이번에는 남는다고 믿기 때문**이라고 본다.

**[[2026-07-20-what-happened-to-the-frontend]]의 흉터 조직 은유와 맞물린다.** 모든 도구는 진짜 문제 위에 생긴 흉터인데, **흉터가 플랫폼에 나면 표준이 되고 도구에 나면 다음 세대에 도려낸다.**

### 핵심 전이 4: 원하는 것과 쓸 수 있는 것의 격차가 수치로 잡혔다

**Anchor Positioning 이 선호 1위이면서 브라우저 미지원 회피 1위다.** 그리고 **Gap Decorations 는 사용 3.7% 인데 55% 의 읽을 것 목록에 있다.** 두 숫자가 같은 걸 말한다. **알고 원하지만 못 쓴다.**

**이번 시즌 반복해서 확인한 형태의 프론트엔드 판본이다.** [[2026-08-11-meta-muse-glimmer-30b-local-agentic]]은 "생태계 지원이 대부분 예정", [[2026-08-13-qwen38-2-4t-a95b-open-weights]]에서는 "공개판이 서비스판과 다르다"였다. **공통 형태: 발표는 되는 것을 말하고 안 되는 것은 말하지 않는다.** 그런데 **이 설문의 값은 정반대다.** 안 되는 것을 **수치로 세어서 되는 것 옆에 놓았다.** 발표문이 아니라 설문이라서 가능한 일이고, **그게 이 자료를 도입 판단에 쓸 수 있게 만든다.**

## 호스피탈리티 / CRS 적용 포인트

- **신규 화면에서 웹 플랫폼 기능을 먼저 검토할 근거가 생겼다.** `:has()` 83.7%, `aspect-ratio` 81.3%, CSS Nesting 70.6% 는 **더 이상 실험적 선택이 아니다.** 다만 **브라우저 지원이 여전히 1차 제약**이므로, 파트너사 관리자 화면처럼 **구형 브라우저 비중이 있는 곳은 우리 실제 접속 분포를 먼저 보고 결정한다.**
- **AI 코딩 생산성 기대치를 영역별로 다르게 잡는다.** CSS/시각 산출물의 AI 채택률이 낮은 건 업계 공통이고, **여기에 다른 영역과 같은 생산성 목표를 걸면 안 된다.**
- **어제 세운 구분에 한 줄을 더한다.** [[2026-08-14-the-human-is-the-loop]]에서 "산출물이 코드인 일의 마찰은 제거해도 되고, 산출물이 이해인 일의 마찰은 제거하면 산출물이 사라진다"고 적었다. **여기에 "산출물이 보이는 것인 일"을 추가한다.** 판정자가 눈이면 자동 검증이 없고, **자동 검증이 없으면 AI 위임의 이점이 얇아진다.**
- **인지 과부하는 개인이 아니라 층으로 흡수한다.** 불만 1위가 인지 과부하라는 건 **개인의 학습 부족이 아니라 구조 신호**다. 디자인 토큰과 컴포넌트 규약이 그 부담을 흡수하는 층이다([[2026-08-05-future-of-design-systems-context]]).
- **설문 수치를 근거로 쓸 때 표본을 함께 말한다.** n=4,902 자기선택 표본이라는 걸 빼고 "83.7% 가 쓴다"만 인용하면 과대 진술이 된다.
