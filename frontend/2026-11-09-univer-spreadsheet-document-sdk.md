# Univer - 웹앱에 스프레드시트와 문서 편집기를 넣는 오픈소스 SDK

> 출처: [Univer](https://news.hada.io/topic?id=36853) (GeekNews, 제작사 dream-num) · 정리일 2026-11-09

## 한 줄 요약

**Univer는 셀 서식·수식 엔진·실행취소까지 포함한 스프레드시트·문서 편집 환경을 웹앱에 그대로 이식하는 오픈소스(Apache-2.0) SDK로, 편집 화면과 애플리케이션 코드가 같은 데이터를 공유해 수식 결과가 자동 갱신된다.**

## 핵심 포인트

- **통합 데이터 모델**: 편집 화면과 애플리케이션 코드가 ***같은 데이터를 다루며, 수식 결과도 자동으로 갱신***됨(Slack 발췌).
- **스프레드시트 편집**: 셀 서식, 병합, 틀 고정, 이미지, 실행 취소. 수식 계산·정렬·필터·데이터 검증·조건부 서식. `SUM`, `IF`, `XLOOKUP`, 동적 배열 등 다양한 함수 지원.
- **문서 편집**: 리치 텍스트, 문단 서식, 목록, 링크, 댓글. API로 셀·범위를 읽고 수정하며 변경 이벤트를 애플리케이션과 연결 가능.
- **아이소모픽 구조(WebSearch 교차확인)**: GitHub(`dream-num/univer`) 공식 설명에 따르면 서버·클라이언트 양쪽에서 동작하는 풀스택 SDK로, Node.js 런타임에서 헤드리스 처리도 지원. v1.0에서 Sheets·Docs·Slides·Boards·Bases·PDF 6종 에디터를 하나의 프로그래머블 Office SDK로 통합.
- **라이선스 경계(불확실)**: 핵심 SDK·플러그인 시스템·렌더링·수식 엔진·Facade API는 Apache-2.0 오픈소스라는 설명과, 파일 import/export 같은 핵심 워크플로는 커머셜(Pro) 티어에 있다는 설명이 소스마다 엇갈려 정확한 오픈소스/Pro 경계는 확인하지 못했다.

## 내 생각 · 적용점

### 핵심 전이 1 — "10단계를 직접 만들기" vs "이미 만들어진 것을 가져오기"

가든은 [[2026-08-02-10-levels-of-building-a-data-grid]]에서 데이터 그리드를 단계별로 직접 구현하는 실측 여정(가상 스크롤, 셀 편집, 서식, 정렬·필터 등)을 다뤘다. Univer는 바로 그 전체 과정 — 서식·병합·수식 엔진·실행취소까지 — 을 이미 패키징해 SDK로 제공한다. 두 노트를 나란히 놓으면 "복잡한 그리드/시트 UI가 필요할 때, 처음부터 10단계를 직접 밟을 것인가, 이미 그 단계를 거친 SDK를 평가할 것인가"라는 구체적인 빌드-vs-바이 결정 지점이 선명해진다.

## 호스피탈리티 / CRS 적용 포인트

**적용 가능성 있음.** 온다 CRS 운영 콘솔에서 호텔별 요금표·재고 캘린더를 운영자가 엑셀처럼 직접 편집하게 하는 기능이 필요하다면, [[2026-08-02-10-levels-of-building-a-data-grid]]가 보여준 복잡도(서식·정렬·필터·실행취소를 전부 새로 구현)를 감수하는 대신 Univer 같은 임베디드 스프레드시트 SDK를 빌드-vs-바이 후보로 평가해볼 가치가 있다. 다만 ①오픈소스/Pro 라이선스 경계(특히 import/export가 상용 호텔 데이터 마이그레이션에 필요할 가능성이 큼), ②실시간 요금 엔진과의 데이터 동기화 안정성, ③번들 크기·성능은 별도 기술 검증(PoC) 없이는 그대로 도입할 수 없다.
