# Datatype — JS·이미지 없이 폰트만으로 차트를 그리는 OpenType 가변 폰트

> 출처: [Datatype — A variable font for charting data](https://github.com/franktisellano/datatype) · GeekNews 정리일 2026-05-19

## 한 줄 요약
**78KB짜리 가변 폰트 하나**가 `{b:30,70,50,90}` 같은 *순수 텍스트*를 막대·스파크라인·파이 차트로 즉시 렌더링한다 — *JS·SVG·캔버스·차트 라이브러리·이미지 일체 불필요*하고, *본문·표·로그·이메일 어디든* 텍스트가 들어가는 자리면 그대로 동작하는 *가장 가벼운 차트 인프라*.

## 핵심 포인트

- **데이터를 타이포그래피로** — *data as type*. 차트가 *그림*이나 *컴포넌트*가 아니라 *글자 그 자체*가 되는 발상의 전환. 합자(ligature) 치환이라는 OpenType의 오래된 기능이 *외부 의존성 없는 시각화*로 재해석됨.
- **3가지 차트, 1가지 폰트** — 막대 `{b:...}`, 스파크라인 `{l:...}`, 파이 `{p:...}` 세 형식을 단일 폰트가 처리.
- **극도로 경량** — WOFF2 78KB. *전체 차트 라이브러리(Chart.js, D3, Recharts) 대비 1/100 ~ 1/1000* 수준.
- **본문 인라인 가능** — 글자 사이에 끼워 넣을 수 있어 *문장 한가운데*, *표 셀 안*, *로그 메시지 끝*에 차트를 직접 박을 수 있음. *별도 렌더링 영역 불필요*.
- **2개 가변 축** — 너비(width)·굵기(weight)로 막대 두께·간격 등 시각 스타일을 *CSS 한 줄*로 조정.
- **15개 프리셋 인스턴스** — 용도별 Named instance가 미리 들어있어 *디자인 결정 비용 0*.
- **광범위 브라우저 지원** — Chrome 62+, Firefox 62+ (2018년 이후). *대부분의 production 환경에서 즉시 적용 가능*.
- **다중 배포 채널** — 웹 폰트, 데스크톱 앱(Figma·키노트 등에서 동작), Google Fonts 모두 지원 → *제품 구간·디자인 도구 구간을 동시에 커버*.
- **xguru 도입 후기 — 텍스트 기반 경량 솔루션 우선 정책** — GeekNews 운영자가 *이미지 사용을 최소화하고 텍스트 기반 경량 솔루션을 우선 도입*하는 운영 원칙을 갖고 있고, 4년 전 도입한 Noto Emoji 폰트가 여전히 잘 동작하는 점을 사례로 듦. *폰트 기반 솔루션의 수명이 길다*는 관찰.

## 인상 깊은 문장

> "데이터를 타이포그래피로(data as type) — JS·이미지·렌더링 라이브러리 없이 **텍스트만으로 차트 표시**"

> "글자 사이에서도 렌더링 가능해서 본문 중간, 표 안, 로그 메시지 등 텍스트가 들어가는 모든 곳에 그대로 동작"

## 내 생각 · 적용점

### 가든의 *가벼운 도구 발견 자산* — 의도적으로 작게 잡는다

가든의 최근 자산이 *5층 추상화·40칸 매트릭스·25칸 체크리스트* 같은 *큰 메타 프레임* 위주로 쌓이고 있다. Datatype은 *작은 도구 한 점* — 큰 프레임에 억지로 끼워 맞추기보다 **작은 도구 발견을 작은 자산으로 정직히** 기록한다. 가든이 *큰 프레임만 비대해지는 편향*을 견제하는 작은 무게추.

이 *작은 자산을 작게 다루는 규율*은 **10번째 자가 진단 — *자산 크기 다양성 시험***으로 추가한다:
> *가든의 자산 크기가 *대(메타 프레임)·중(논문/장문)·소(도구 발견)·미(한 줄 인용)*로 *고르게* 분포하는가, 한쪽으로 쏠려있는가?*

### [[2026-05-18-gruber-ai-is-technology-not-product]] *AI=기술이지 제품이 아니다* — Datatype은 *Gruber 명제의 작은 증거*

Gruber는 *AI가 무선 네트워킹처럼 모든 곳에 침투하는 보편적 기반 기술*이라고 했다. **Datatype은 *차트 영역에서 같은 일을 텍스트(글꼴) 단위로 수행***한다:
- *차트*라는 분리된 카테고리가 아니라 *폰트라는 인프라*가 됨
- *별도 컴포넌트*가 아니라 *모든 텍스트가 들어가는 곳에 침투*
- *마케팅 키워드가 아니라 기술*로 가치 제공

가든 안에서 Gruber 명제의 *프론트엔드 작은 사례*로 짝.

### [[2026-05-17-jvns-moving-away-from-tailwind]] *Tailwind 졸업*과 짝 — *빼는 추상화*

Julia Evans는 *Tailwind라는 추상화*에서 *직접 CSS*로 *내려갔다*. Datatype은 *Chart.js·D3 같은 차트 라이브러리 추상화*에서 *폰트라는 더 낮은 층*으로 *내려간다*. **두 자산 모두 *빼는 추상화*의 사례** — 도구 졸업의 두 가지 방향:
| 자산 | 졸업의 방향 |
|---|---|
| JVNS | 추상화 *밖으로* — Tailwind → CSS |
| Datatype | 추상화 *아래로* — 라이브러리 → 폰트(타입시스템) |

*빼는 추상화*가 *프론트엔드의 한 흐름*임을 두 자산이 함께 증명. **2026 프론트엔드 의사결정에서 *추상화를 빼는 옵션*을 디폴트 후보에 포함**.

### [[2026-05-17-ascetic-computing-ratfactor]] *Ascetic Computing* — Datatype은 *금욕 컴퓨팅의 모범 사례*

ratfactor는 *JS·이미지·외부 의존성을 줄여라*고 했다. Datatype은 *그 처방을 차트 영역에 정확히 시연*:
- JS = 0
- 이미지 = 0
- 외부 라이브러리 = 0
- 의존성 = 폰트 파일 1개 (78KB)

가든의 *Ascetic 자산*이 *추상적 처방*에서 *구체적 실행 사례*로 한 단계 내려옴. **다음 가든 정리 시 *Ascetic 친화 도구 모음 인덱스*를 별도로 만드는 후보**.

### [[2026-05-14-naur-programming-as-theory-building]] 약한 짝 — *작은 도구가 큰 이론을 단순화*

Naur는 *프로그램이 이론*이라 했다. **차트 시각화라는 도메인 이론을 *합자 치환 한 줄*로 표현**한 게 Datatype. *이론이 단단할수록 도구가 작아진다*는 Naur의 함의를 *극단까지 밀어붙인 사례*. (가든에서 Naur는 큰 자산이고 Datatype은 작은 자산 — 작은 자산이 큰 자산의 *작은 증거*로 기능.)

### CRS / 사이드 프로젝트 *즉시 적용 후보 3건*

1. **CRS 운영 대시보드 인라인 막대 그래프** — *주말 객실 점유율* 등을 운영팀 대시보드 텍스트 표에 인라인으로 박기. *별도 차트 컴포넌트 도입 없이*. (지금 표는 숫자만 있고 시각 신호가 약함.)
2. **[[project_bugsip]] 코드 리딩 통계 표시** — 사용자의 *연속 학습일·세션 길이* 등을 *프로필 화면 텍스트 줄 안에* 인라인 스파크라인으로. *별도 차트 라이브러리 의존성 추가 없이* CMP 빌드 크기 절약.
3. **로그·운영 알림 메시지 인라인 차트** — Slack 알림 메시지 텍스트에 *최근 N분 트래픽 추이*를 직접 박는다. *지금은 외부 이미지 첨부*인데 *텍스트만으로*. (Slack은 이 폰트가 안 먹지만, *Notion·이메일·내부 위키*는 적용 가능.)

### *적용 안 할 곳* — 정직한 한계

- **접근성** — 스크린리더가 *합자로 치환된 그래프*를 어떻게 읽는지 불확실. *공개용 차트* 또는 *접근성 의무 화면*에는 *aria-label로 별도 텍스트 제공* 필요.
- **인쇄·PDF** — 폰트 임베딩이 보장되어야 함. *법적 보고서·계약 첨부 차트*에는 부적합.
- **정확한 값 표시** — 막대·스파크라인은 *경향*용. *정확한 수치 비교*는 별도 표가 필요.
- **상호작용** — 호버·툴팁·드릴다운 불가. *탐색용 차트*에는 부적합, *읽기용 인디케이터*에 적합.

이 한계를 *정직히 기록*하는 게 [[feedback_self_verification]]의 *영향범위·엣지케이스 검증* 6단계의 적용.

### *작은 자산의 큰 가치* — 가든 운영 원칙 보강

이번 정리는 *큰 메타 프레임으로 환원 불가능한 작은 발견*이다. 그래도 가든은 *작은 자산*도 *큰 자산과 같은 정성*으로 정리한다 — 이유:
1. *작은 도구가 작은 의사결정을 바꿈* (CRS 운영 대시보드 결정)
2. *작은 자산이 큰 자산의 검증 사례가 됨* (Gruber·JVNS·Ascetic의 작은 증거)
3. *큰 메타 프레임 편향* 견제 (자가 진단 10번)

→ **가든 운영 원칙: *작은 자산을 의도적으로 정리한다*. 큰 자산만 쌓이면 *추상화 비대증*이 된다.**
