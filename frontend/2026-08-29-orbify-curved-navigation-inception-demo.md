# Orbify — 《인셉션》처럼 도로를 접어 보여주는 곡면 내비게이션 데모

> 출처: [Orbify — Next-Generation Navigation Visualization](https://www.orbify.eu/demo/) (Orbify) · 정리일 2026-08-29
> **출처 한계**: `news.hada.io`와 `www.orbify.eu` 모두 이 세션에서 egress 차단되어 WebFetch 불가. 아래 내용은 Slack 발췌와 WebSearch 스니펫(HN 스레드 `id=49477564` "Inception-style curved map for turn-by-turn directions" 포함) 교차검증으로 재구성했다 — hada 댓글 원문, HN 정확한 포인트·댓글 수, published_at의 정확한 시각은 확인하지 못했다. published_at은 같은 배치로 올라온 htmx 4.0 발표일(2026-08-28, 원문 확인됨)에 맞춰 추정한 값이다.

## 한 줄 요약
**Orbify는 3D 지도 공간을 곡면으로 휘어, 가까운 도로는 운전자 눈높이 시점으로 멀리 있는 경로는 위에서 내려다보는 지도처럼 한 화면에 이어 붙인 웹 데모를 내놓았다** — 내비게이션이 시점을 바꿀 때마다 공간 감각이 끊기는 문제를, 모드 전환 없이 곡면 하나로 풀려는 개념 증명(proof of concept)이다.

## 핵심 포인트
- 문제의식: 기존 차량 내비게이션은 운전 시점·하향식 2D 지도·거리뷰를 오가는데, 이 전환마다 사용자는 "지금 내가 지도의 어디에 있고 어디로 가는지"를 다시 계산해야 한다.
- 해법: 특허 출원 중인 워핑(warping) 알고리즘으로 3D 지도 모델을 곡면에 투영한다 — Orbify 자체 설명으로는 ***"눈높이 시점과 항공 뷰 맥락을 하나로 융합한 단일 곡면 뷰"***(WebSearch로 확인)이며, 가까운 구간은 원근감 있는 도로로, 먼 구간은 세워진 지도처럼 보여준다.
- 웹에서 WASD 이동과 마우스 조작으로 직접 체험할 수 있는 데모 형태이며, 실제 차량 탑재 제품이 아니라 시각화 콘셉트 단계.
- HN 댓글 중 실사용성 비판이 눈에 띈다 — ***회전 직전 구간에서는 회전이 끝나기 전까지 그 다음 경로 정보가 사실상 보이지 않아, 골목이 연쇄로 이어지는 구간에서는 오히려 정보가 부족해질 수 있다***는 지적(WebSearch로 확인, 원문 댓글 전체는 미확인).

## 인상 깊은 문장
> "영화 《인셉션》에서 도시가 위로 접혀 올라가는 장면처럼, 차량 앞쪽의 지형과 도로를 곡면으로 휘어 보여주는 내비게이션 콘셉트." (Slack 발췌)

## 내 생각 · 적용점
"시점을 바꿀 때마다 사용자가 공간 모델을 처음부터 다시 세워야 한다"는 이 데모의 출발 문제는 [[2026-04-30-laws-of-ux]]에서 정리한 Cognitive Load·Working Memory 항목과 느슨하게 맞닿는다 — 화면(모드)이 바뀔 때마다 이전 화면에서 쌓은 공간적 맥락이 작업 기억에서 리셋되는 비용을, Orbify는 "화면을 하나로 유지"하는 방식으로 줄이려 한 것으로 읽을 수 있다. 다만 이 노트는 원문을 직접 확인하지 못한 데모 소개 수준이라 억지로 더 깊은 전이를 세우지는 않는다 — 리소스성 글로 가볍게 남겨둔다.

## 호스피탈리티 / CRS 적용 포인트
직접 적용은 멀다 — 온다는 차량 내비게이션과 무관한 B2B 호스피탈리티/CRS 도메인이다. 다만 전이 가능한 원칙 하나는 있다: CRS Admin에서도 예약 캘린더·객실 배치도·리스트뷰처럼 같은 데이터를 다른 시점으로 오가는 화면이 있고, 이 전환 지점마다 사용자가 "지금 무엇을 보고 있는지" 다시 파악해야 하는 비용이 생긴다. Orbify처럼 화면을 완전히 하나로 합치는 것까지는 과할 수 있어도, 전환 시 이전 컨텍스트(선택한 날짜·객실 등)를 유지하는 정도의 원칙은 참고할 만하다.

## 연관 자료
- [[2026-04-30-laws-of-ux]] — Cognitive Load·Working Memory 항목이 "모드 전환 시 공간 맥락 재구성 비용"이라는 이 데모의 문제의식과 느슨하게 겹친다.
