# 버튼이라면 할 일은 하나뿐 (unsung.aresluna.org) — '반복 탭을 기억하는 iPhone vs 무시하는 Nothing Phone', 애니메이션은 사용자를 구속하는 수단이 아니다

> 출처: [If You're a Button, You Have One Job](https://unsung.aresluna.org/if-youre-a-button-you-have-one-job/) (unsung.aresluna.org) · 정리일 2026-07-06

## 한 줄 요약

**사진 회전 버튼처럼 단순한 UI 요소도 반복 입력 처리 방식에 따라 사용자 경험이 크게 갈린다. iPhone은 빠른 연속 탭을 기억해 애니메이션 완료 후 순차 실행하지만, Nothing Phone/Android는 애니메이션 진행 중 새 탭을 무시한다. 버튼은 사용자를 애니메이션 종료까지 기다리게 하기보다 탭 버퍼링이나 애니메이션 중단·가속으로 입력을 처리해야 한다.**

## 핵심 포인트

- **플랫폼 간 차이** —
  - **iPhone**: 빠른 연속 탭 입력을 기억, 애니메이션 완료 후 대기 중인 다음 회전을 순차 실행 — 사용자가 애니메이션 대기 없이 연속으로 누를 수 있음.
  - **Nothing Phone/Android**: 햅틱·소리로 탭 확인 제공하지만, 이전 애니메이션 진행 중 새 탭은 **무시** — 애니메이션 종료까지 기다려야 함.
- **설계 원칙** — "버튼은 사용자를 애니메이션 종료까지 기다리게 하기보다, 탭 버퍼링이나 애니메이션 중단·가속으로 입력을 처리해야 한다." 캐주얼 UI도 반복 작업 상황에서는 강한 입력 처리가 필요.
- **상황적 장애(Situational Disability) 개념** — 누구나 특정 상황(여러 장 사진을 빠르게 회전해야 하는 등)에서 제약을 경험할 수 있음.
- **실제 사례** — 여러 장 문서 사진을 촬영 후 각각 회전해야 하는 상황에서, 예측 가능한 버튼 동작이 더 효율적이고 즐거운 경험 제공.

## 내 생각 · 적용점

### 핵심 전이 1 — CRS 예약 UI의 반복 클릭 상황 점검

CRS·PickMe 예약 화면에서 "날짜 선택", "인원 증감" 같은 반복 클릭 요소가 애니메이션 중 입력을 무시하는지, 버퍼링하는지 점검할 필요가 있다. **사용자가 여러 개 객실을 예약하며 인원수를 빠르게 여러 번 조정하는 상황(상황적 장애의 실제 사례)에서, 입력이 무시되면 "왜 안 눌리지"라는 좌절감을 만든다.**

### 핵심 전이 2 — "상황적 장애" 개념이 접근성 논의의 프레임을 넓힌다

파킨슨병 같은 영구적 장애만이 아니라, "급하게 여러 장 사진을 찍는 상황"처럼 **누구나 일시적으로 겪는 제약**까지 포함하는 이 개념은 CRS UI 접근성 점검에 유용한 확장된 관점을 제공한다. 호텔 프론트 직원이 바쁜 체크인 시간대에 여러 예약을 빠르게 처리해야 하는 상황도 상황적 장애의 일종이다.

### 핵심 전이 3 — "애니메이션은 구속 수단이 아니다"라는 원칙을 CRS 관리자 UI에 적용

Opera PMS 연동 화면이나 CRS 관리자 대시보드에서, 로딩 애니메이션이 끝날 때까지 사용자의 다음 액션을 강제로 막는 패턴이 있다면 이 글의 원칙을 재검토할 기회다. **입력을 버퍼링하거나 애니메이션을 가속하는 것이 훨씬 나은 사용자 경험을 만든다.**
