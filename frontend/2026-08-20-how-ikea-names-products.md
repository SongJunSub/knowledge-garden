# IKEA는 제품 이름을 어떻게 지을까 (IKEA 공식)

> 출처: [How does IKEA name its products?](https://www.ikea.com/se/en/customer-service/knowledge/articles/6f564c4d-2ccc-46de-b643-545a3948dc79.html) (IKEA 공식 문서 · GeekNews 경유, 제출자 GN⁺) · 정리일 2026-08-20
> **성격**: **가벼운 자료**다. 가든 원칙대로 짧게 남기되 **명명 규칙에서 읽히는 것**만 적는다.
> **hada 댓글 1개 + HN 큐레이션.** **댓글이 본문보다 재밌고, 규칙의 실제 상태를 보여준다.**

## 한 줄 요약

**창업자 Ingvar Kamprad 가 숫자를 잘 못 외워서 이름을 붙이기 시작했고, 그게 브랜드 정체성이 됐다. 규칙은 둘이다. 제품에는 스웨덴어 이름을 쓴다. 소파는 스웨덴 지명, 책장은 남자 이름, 아동 제품은 동물과 자연. 그리고 그 밖의 모든 것, 그러니까 서비스와 기능과 커뮤니케이션에는 운영 국가의 현지어로 서술적 이름을 쓴다. 명명 기준도 명시돼 있다. 실제 단어여야 하고, 4~12자여야 하고, 가능하면 Å Ä Ö 를 포함하고, 발음이 듣기 좋아야 하고, 상표나 성씨는 피한다. 후보는 다른 언어에서 바람직하지 않은 의미나 정치·종교적 연관이 없는지 검토를 거친다. 규모는 매년 약 2,000에서 3,000개다. 그런데 댓글이 재밌다. PAX 옷장은 3글자라 4~12자 규칙 위반이고 1992년부터 있었고, JERKER 책상은 부정적 의미 회피 정책 이전 제품이고, Svalka 와인잔은 다국어 검토를 한다면서도 발트·슬라브 슬랑 의미를 놓쳤다.**

## 핵심 포인트

- **기원**: 창업자 **Ingvar Kamprad 가 숫자를 외우기 어려워해서** 시작했고, 그게 **브랜드 정체성과 장난기 있는 성격**의 중심이 됐다.
- **규칙 1**: ***"제품에는 스웨덴어 이름을 쓴다."*** 장소·자연·감정·일상 표현에서 가져온다.
  - **소파 → 스웨덴 지명**
  - **책장 → 남자 이름**
  - **아동 제품 → 동물과 자연**
- **규칙 2**(덜 알려졌는데 더 흥미롭다): ***"그 밖의 모든 것에는, 우리가 운영하는 나라의 현지어로 서술적 이름을 쓴다."*** 서비스·기능·커뮤니케이션처럼 **명료함이 필요한 것들.**
- **명명 기준**: **실제 단어**여야 하고, **4~12자**, **가능하면 Å·Ä·Ö 포함**, **발음이 듣기 좋아야** 하고, **상표나 성씨는 회피.**
- **검토**: 후보는 ***"다른 언어에서 바람직하지 않은 의미, 정치적·종교적 연관"***을 피하기 위한 검토를 거친다.
- **규모**: ***"매년 약 2,000~3,000개의 신제품에 이름을 붙인다."***

## 인상 깊은 문장

> ***"그 밖의 모든 것에는 운영하는 나라의 현지어로 서술적 이름을 쓴다."***
> **규칙 1보다 이게 값지다.** **기억돼야 하는 것과 이해돼야 하는 것을 갈랐다**(→ 전이 1).

> **매년 약 2,000~3,000개**

## 댓글

**hada 댓글 1개 + HN 큐레이션.** **본문보다 재밌고, 규칙이 실제로 어떻게 작동하는지 보여준다.**

- **Svalka 와인잔**: 다국어 검토를 한다고 하는데 **발트·슬라브권 슬랑 의미**를 놓쳤다.
- **PAX 옷장**: **3글자**라 명시된 **4~12자 규칙을 위반**한다. **1992년부터** 있었다.
- **JERKER 책상**: **부정적 의미 회피 정책 이전** 제품이다.
- **NATTBAD 블루투스 스피커**: 의도치 않게 웃긴 이름.
- 유럽 언어권 사용자들의 **스웨덴어 발음 어려움** 논의.

**읽을 때 감안**
- ①**IKEA 공식 문서**라 **잘 지켜지는 규칙으로 서술**된다. 예외와 실패는 댓글 쪽에만 있다.
- ②**검토 과정의 범위가 안 나온다.** ***"다른 언어에서"***라고만 하고 **몇 개 언어인지, 슬랑까지 보는지**가 없다(→ 전이 3).
- ③**HN 항목이 일화**다. Svalka 의 슬랑 의미가 실제로 문제가 됐는지 판매에 영향이 있었는지는 확인되지 않았다.

## 내 생각 · 적용점

**가벼운 자료라 길게 쓰지 않는다. 명명 규칙에서 읽히는 것 넷만.**

### 1. 규칙 2가 규칙 1보다 값지다: 기억용 이름과 이해용 이름을 갈랐다

**제품은 고유명(스웨덴어), 서비스·기능·커뮤니케이션은 서술명(현지어).** 이 구분이 정확하다.

**기억돼야 하는 것에는 고유명이 맞다.** BILLY 는 뜻이 없어서 오히려 **BILLY 라는 것 자체**가 된다. **이해돼야 하는 것에는 서술명이 맞다.** 배송 서비스 이름이 스웨덴어면 아무도 못 쓴다.

**그리고 어제 [[2026-08-19-cursor-origin-code-hosting]]에서 정리한 것과 같은 자리다.** HN 이 **Cursor 의 Origin 이라는 이름이 git 의 `origin` 과 겹쳐 LLM 해석에 모호성을 만든다**고 지적했고, 거기서 **"에이전트 시대에는 이름이 인터페이스"**라고 적었다.

**IKEA 는 그 구분을 제품군 단위로 제도화했다.** 그리고 소프트웨어에서도 같은 구분이 성립한다.

| | 고유명 | 서술명 |
|---|---|---|
| **소프트웨어** | 라이브러리·서비스·제품 이름 | 함수명·변수명·API 엔드포인트 |
| **판단 기준** | **기억되고 검색돼야 하나** | **읽고 바로 이해돼야 하나** |

**실무 규칙: 이름을 지을 때 이게 기억용인지 이해용인지 먼저 정한다.** 섞으면 둘 다 안 된다.

### 2. PAX 가 규칙 위반인데 남아 있다는 게 규칙 운영의 정답이다

**PAX 는 3글자로 4~12자 규칙을 어기고 1992년부터 있다. JERKER 는 회피 정책 이전 제품이다.**

**이걸 규칙 실패로 읽으면 안 된다고 본다.** **규칙이 나중에 생기면 기존 것은 위반이 아니라 그냥 이전 것**이다.

**그리고 [[2026-08-16-not-tech-debt-just-mess]]에서 세운 구분이 여기 걸린다.** 그 글의 기준이 **결정 시점에 비용을 알았느냐**였다. PAX 를 지을 때는 **규칙이 없었다.** 그러면 부채도 아니고 엉망도 아니고 **그냥 이전 결정**이다. 그리고 고치는 비용(30년 브랜드 자산 폐기)이 이득보다 훨씬 크다.

**실무 규칙: 명명 규칙이나 코딩 컨벤션을 새로 만들 때 소급 적용 범위를 명시한다.** 안 하면 **기존 코드 전부가 위반으로 보이고**, 그러면 **규칙 자체의 권위가 떨어진다.** 린터를 새로 켤 때 기존 파일을 예외 처리하는 게 같은 이유다.

### 3. Svalka 가 검증 범위의 문제를 보여준다

**IKEA 는 다국어 검토를 한다고 명시하는데도 발트·슬라브권 슬랑을 놓쳤다.** 그리고 **연간 2,000~3,000개를 모든 언어의 슬랑까지 검토하는 건 불가능하다.**

**그러면 이건 실패가 아니라 범위의 문제다.** **검증은 항상 유한한 범위에서 이뤄지고, 범위 밖은 사고로 발견된다.**

**이번 시즌에 같은 형태를 여러 번 봤다.** [[2026-08-13-tailscale-sqlite-wal-reset-bug]]의 **16년 동안 아무도 못 잡은 버그**, [[2026-08-16-graph-vs-loop-engineering]]의 **시스템 내부 검증으로는 부족하고 외부 증거가 필요하다**는 것.

**함의: "검토했다"는 말은 "범위 안에서 검토했다"는 뜻이고, 그 범위를 서로 알아야 한다.** IKEA 문서는 검토한다고만 하고 **범위를 안 밝힌다.** 밝히면 기대치가 맞는다.

### 4. 제약의 교집합이 매년 3,000개씩 고갈된다

**작게 덧붙인다.** 조건이 다섯이다. 실제 스웨덴어 단어 / 4~12자 / Å·Ä·Ö 선호 / 발음 좋음 / 상표·성씨 회피.

**그 교집합이 유한한데 매년 2,000~3,000개씩 쓴다.** 60년이면 누적이 상당하다.

**그러면 압력이 생기고, PAX 같은 예외가 그 압력의 흔적일 수 있다.** 또는 **어휘 범위를 넓히거나**(지명·인명·감정·일상 표현으로 계속 확장했다), **재사용하거나**. **(내 추론이고 문서에 없다.)**

**소프트웨어 쪽으로 옮기면 같은 문제가 있다.** 사내 서비스 이름, 마이크로서비스 이름, 기능 플래그 이름이 **누적되면 고갈되고 충돌한다.** IKEA 는 **제품군마다 다른 어휘 풀**을 배정해서 그 문제를 나눴는데, 그게 **네임스페이스**다.

## 호스피탈리티 / CRS 적용 포인트

**가벼운 자료라 적용도 가볍다.**

- **기능·화면 이름을 지을 때 기억용인지 이해용인지 먼저 정한다.** 파트너사 관리자 화면의 메뉴는 **서술명**이 맞고(무엇을 하는지 바로 알아야 함), 내부 서비스나 프로젝트 코드명은 **고유명**이어도 된다.
- **명명 규칙을 새로 만들면 소급 범위를 명시한다.** 기존 것 전부가 위반으로 보이면 규칙이 무시된다.
- **다국어 검토의 범위를 밝힌다.** 온다가 일본 등 해외로 가면 **기능명·오류 메시지·마케팅 문구**가 현지어 검토를 거치는데, **어디까지 봤는지**를 같이 적어두면 나중에 문제가 생겨도 원인을 안다.
- **네임스페이스를 미리 나눈다.** IKEA 가 제품군마다 다른 어휘 풀을 쓰는 게 **충돌 회피 설계**다. 사내 서비스·기능 플래그도 **도메인별 접두사**로 나누면 같은 효과가 난다. 어제 [[2026-08-18-flex-modules-agents-read-less]]에서 **경로에 도메인을 적는 것만으로 신호가 생긴다**고 정리한 것과 같은 원리다.
