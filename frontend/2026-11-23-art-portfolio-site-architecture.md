## 한 줄 요약

**방문자에게는 정적 사이트처럼 빠르게 제공하면서, 운영자는 웹 기반 CRUD UI로 작품과 메타데이터를 수정할 수 있는 미술 작품 사이트를 구현했다 — 핵심은 "쓰기 작업이 있을 때만" 전체 페이지 캐시를 무효화하는 것이다.**

## 핵심 포인트

- 방문자에게는 ***정적 사이트처럼 빠르게 제공***하면서, 운영자는 웹 기반 CRUD UI로 작품과 메타데이터를 수정하는 미술 작품 사이트를 구현했다.
- 서버에서 생성한 HTML을 ***Cloudflare에 30일간 캐시***하고, 작품 업로드나 태그 변경 같은 쓰기 작업이 발생하면 모든 페이지 캐시를 무효화한다.
- 이미지 축소본은 요청 시점이 아니라 ***업로드 시 운영자 브라우저에서 미리 생성***하며, 원본과 함께 Cloudflare R2에 저장한다.
- 작품 메타데이터는 ***단일 JSON 파일***로 관리하며, 서버의 페이지 생성과 클라이언트의 지도 등 읽기 전용 작업에서 함께 참조한다.

## 내 생각 · 적용점

이 아키텍처의 핵심 통찰은 "읽기가 압도적으로 많고 쓰기가 드문 콘텐츠"에는 정적 캐시와 CRUD UI가 공존할 수 있다는 점이다 — 쓰기 빈도가 낮다면 "쓰기 시 전체 무효화"라는 단순한 전략도 충분히 효율적이다. 이미지 축소본을 요청 시점이 아니라 업로드 시점(운영자 브라우저)에서 미리 생성하는 선택도 같은 철학이다 — 비용이 드는 작업을 드물게 일어나는 쪽(업로드)으로 옮겨서 자주 일어나는 쪽(조회)을 가볍게 만든다.

가든 내에 이 아키텍처 패턴(정적 캐시+낮은 빈도 쓰기 CRUD) 전용의 선행 노트는 없다 — 억지로 엮기보다 정직하게 "연결 없음"으로 둔다.

## 호스피탈리티 / CRS 적용 포인트

**적용 가능성 있음.** 호텔 콘텐츠(사진·객실타입·요율 설명)는 쓰기 빈도는 낮고 읽기는 집중되는 전형적인 패턴이다. "쓰기 시 전체 무효화 + 정적 캐시" 구조는 CRS 공개 페이지(객실 소개, 프로모션 랜딩)에 그대로 적용 가능성이 있고, 이미지 축소본을 업로드 시점에 미리 생성하는 방식도 객실 사진 관리에 바로 참고할 수 있다.
