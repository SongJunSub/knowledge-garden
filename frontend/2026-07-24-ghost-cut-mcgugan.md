# Ghost Cut 소개 — 잘라내기·붙여넣기는 왜 어디서나 망가졌을까 (Will McGugan)

> 출처: [Introducing Ghost Cut](https://ishmael.textualize.io/blog/ghost-cut/) (Will McGugan, Rich·Textual 제작자 / Ishmael TUI 소설 편집기 · GeekNews GN⁺ 요약 + HN 큐레이션) · 정리일 2026-07-24

## 한 줄 요약

**Textual·Rich를 만든 Will McGugan이 자기 소설 편집기 Ishmael을 만들다가, 잘라내기/붙여넣기라는 보편 프리미티브의 세 가지 결함을 짚고 대안(Ghost Cut)을 제시한 UX 설계 글. 결함: ①Cut은 완전히 되돌릴 수 없다(undo가 문서 텍스트는 복원해도 덮어쓴 클립보드는 영영 사라짐), ②Cut이 즉시 문서를 재배치한다(남은 텍스트가 당겨져 붙일 위치를 다시 찾아야 함), ③원자성이 없다(개념은 '한 번의 이동'인데 undo는 paste·cut 2단계+). Ghost Cut은 Ctrl+X로 선택 텍스트를 흐리게 비활성화하되 문서에 남기고(클립보드 미변경·되돌릴 것 없음), Ctrl+V로 원위치에서 제거해 커서에 삽입하는 단일 원자적 이동을 하며, Escape로 복원, 한 번의 undo로 전체를 되돌린다. AI 홍수 속에서 인간 크래프트가 보편 프리미티브를 다듬은 사례다.**

## 핵심 포인트

- **기존 Cut/Paste의 세 결함** — ①**되돌릴 수 없음**: *"undo 후에도 클립보드 변경은 남는다"* — Ctrl+Z가 문서는 복원해도 덮어쓴 클립보드 내용은 영구 소실. ②**즉시 재배치**: *"cut 후 문서가 재배치돼 붙일 위치를 다시 찾아야 한다"* — 이동의 흐름을 방해. ③**원자성 부재**: *"개념적으론 한 번의 이동인데 undo는 2단계+"* — paste 되돌린 뒤 cut까지 복원하려면 추가 undo, 사이에 편집이 있으면 더 복잡.
- **Ghost Cut 동작** — **Ctrl+X**: 선택 텍스트를 흐리게/비활성으로 표시하되 문서에 남김. 클립보드 미변경, 되돌릴 것 없음. **Ctrl+V**: 흐려진 텍스트를 원위치에서 제거하고 커서에 삽입 = **단일 원자적 이동**. **Escape**: 텍스트를 다시 활성으로 복원. *"한 번의 undo로 전체가 완벽히 되돌려지고 클립보드는 오염되지 않는다."*
- **설계 3원칙** — 원자성(논리적 이동=기술적 단일 작업), 완전한 가역성(클립보드 상태까지 포함한 진짜 undo), 문맥 보존(이동 중 문서 재배치 없음).
- **기존 의미가 필요하면** — Ctrl+C로 복사 후 Backspace로 삭제. McGugan: *"나는 cut 후 paste 안 하는 경우가 거의 없어 이건 명백한 이득."*
- **HN 찬반** — 우려: X11 선택/프라이머리 버퍼 표준(*"현대 앱이 X11이 제대로 한 걸 망친다"*), copy vs cut 구분(여러 번 붙여넣기·클립보드 유지의 실용성), Excel 유사성 비판(*"Excel처럼 동작하되 자주 당황"*·비직관), 클립보드는 앱 간 기능이라 텍스트편집기-로컬 ghost 모델의 경계 문제, *"다수 사용자의 기대·정상 흐름을 깰 가치는 없음"*. 긍정: 개념적 일관성·원자적 이동의 논리, Windows 탐색기 파일 이동과 유사.

## 내 생각 · 적용점

*(작은 UX 글이라 억지 전이 없이 진짜 연결 2가지만.)*

### 핵심 전이 1 — AI 홍수 속 '인간 크래프트·취향'의 사례: 무엇을 다듬을 가치가 있는가

이번 주가 온통 AI였는데, 이 글은 **한 사람이 보편 프리미티브(cut/paste)를 "이건 다듬을 가치가 있다"고 판단해 손으로 재설계한** 크래프트다. 이건 [[2026-07-22-taste-cannot-be-delegated]]의 *"무엇이 존재할 가치가 있는지 결정"*·[[2026-07-24-on-making-things-beej]]의 *"making"*의 실물 — McGugan은 30년 쓴 동작의 미묘한 인지 비용(재배치·비원자성·클립보드 소실)을 *알아채고* 대안을 *만들었다*. **평균(모두가 쓰는 cut/paste)을 거부하는 단일 판단**이 곧 이 개선이고, AI가 값싸게 못 만드는 종류의 것이다.

### 핵심 전이 2 — 정신 모델 재설계의 양날: Ghost Cut vs Passkey

Ghost Cut은 정신 모델을 **개선**하려 한다 — "이동은 하나의 원자적 사건"이라는 더 정확한 모델. 그런데 HN 우려(*"근육 기억·기대를 깬다"*)는 어제 정리한 [[2026-07-23-passkeys-consumer-psychology]]와 **정확히 같은 긴장**이다: 패스키는 정신 모델을 *나쁘게* 깼고, Ghost Cut은 *좋게* 고치려는데 둘 다 **"보편 프리미티브를 건드리면 근육 기억·기대와 싸운다."** 교훈: 정신 모델 개선이 개념적으로 옳아도, 보편 동작을 바꿀 땐 (a) 기존 의미를 옵트인으로 남기고(McGugan의 Ctrl+C+Backspace), (b) 경계 조건(앱 간 클립보드)을 명확히 해야 채택된다. **좋은 재설계도 이행 경로가 없으면 진다.**

## 호스피탈리티 / CRS 적용 포인트

작은 UX 글이라 적용도 가볍게 — 온다 UX 설계의 원칙으로만.

- **논리적 액션 = 하나의 undo(원자성).** CRS 화면에서 "한 번의 사용자 의도"(예: 예약 이동·정산 항목 이동)는 undo도 한 번이어야 — 여러 단계로 쪼개진 되돌리기는 인지 비용.
- **액션 중 문맥을 파괴하지 말 것.** 항목 삭제/이동 시 화면이 즉시 재배치돼 사용자가 위치를 잃지 않게(Ghost Cut의 문맥 보존).
- **보편 동작은 근육 기억을 존중.** 표준 단축키·패턴을 바꿀 땐 옵트인·명확한 경계로(패스키 교훈과 동일).
