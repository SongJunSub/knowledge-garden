## 한 줄 요약

**Cursor가 데스크톱·CLI·웹 앱을 구동하는 같은 런타임 위에서 팀 맞춤형 코딩 에이전트를 코드로 만들고 배포할 수 있는 Agent SDK를 공개했다 — 지침은 Markdown으로, 도구와 처리 로직은 TypeScript로 정의하고 AI의 판단을 결합하며, 에이전트가 결정하는 행동을 일반 코드처럼 버전 관리하고 팀에서 검토할 수 있다. Slack·PR·이슈 트래커 등 팀이 일하는 곳에 에이전트를 연결해, 팀 정책에 따라 도구를 실행하도록 구성할 수 있다.**

## 핵심 포인트

- **지침(Markdown)과 로직(TypeScript)을 분리하고 AI 판단을 결합** — Slack 발췌: "Markdown으로 지침을, TypeScript로 도구와 처리 로직을 정의하고 AI의 판단을 결합함." WebSearch로 확인한 공식 자료도 인덱싱·시맨틱 검색 기반 컨텍스트 관리와 MCP 서버를 통한 외부 도구·데이터 연결을 핵심 기능으로 든다.
- **에이전트의 행동을 "일반 코드처럼" 버전 관리** — 에이전트의 행동을 결정하는 파일을 일반 코드처럼 버전 관리하고 팀에서 검토할 수 있다는 설계는, 에이전트 설정을 PR 리뷰 대상으로 삼아 "에이전트가 왜 그렇게 행동하는지"를 코드 변경 이력으로 추적 가능하게 만든다.
- **실행 위치를 선택할 수 있다 — 로컬·클라우드·자체 호스팅** — WebSearch로 확인한 공식 설명에 따르면 에이전트를 로컬 머신, Cursor 클라우드의 전용 VM, 또는 ***자체 호스팅 워커***에서 실행할 수 있어 코드와 도구 실행을 회사 네트워크 안에 가둘 수 있다. 데이터 프라이버시가 중요한 조직에는 이 선택지가 실질적 차이를 만든다.
- **팀이 일하는 곳에 에이전트를 심는다** — Slack, PR, 이슈 트래커 등에 에이전트를 연결해 메시지나 업무 이벤트를 받아 필요한 정보를 찾고 팀 정책에 따라 도구를 실행하도록 구성할 수 있다. WebSearch로 확인한 실제 사용 사례도 CI/CD 파이프라인에서 직접 에이전트를 호출하거나 핵심 제품에 임베드하는 방식을 든다.

## 내 생각 · 적용점

**핵심 전이 — [[2026-10-16-strands-harness-sdk]]가 보여준 "하네스는 줄어들지 않고 이동한다" 원칙이 이번엔 Cursor에서 재현된다.** AWS의 Strands Harness SDK가 "맥락 관리·실행 제한·관측"을 프레임워크 레벨로 끌어올렸듯, Cursor Agent SDK는 "팀 지침·도구 호출·외부 서비스 연동·검토 가능한 버전 관리"를 코딩 에이전트 전용 하네스로 패키징한다. 다른 점은 Strands가 모델/클라우드 애그노스틱 로직 레이어를 지향한 반면, Cursor는 자사 코딩 에이전트 런타임에 결속된 하네스라는 것 — "에이전트 코드는 유지하되 백엔드는 자유롭게"라는 Strands의 약속과 "Cursor 런타임 위에서"라는 Cursor의 전제는 서로 다른 락인 구조를 만든다. 코딩 에이전트 프레임워크를 고를 때 이 벤더 종속성 차이를 먼저 따져야 한다.

## 호스피탈리티 / CRS 적용 포인트

**직접 적용 가능성 있음.** 내부 개발팀이 Claude Code 같은 코딩 에이전트의 동작(지침·도구 호출 범위·승인 정책)을 Markdown+코드로 명시하고 PR 리뷰 대상으로 삼는 패턴은, 지금 온다의 CRS 개발 조직에도 그대로 적용할 원칙이다 — 에이전트가 무엇을 할 수 있는지를 사람이 검토 가능한 파일로 고정해두면, "에이전트가 왜 이렇게 행동했는가"를 사후에 추적할 수 있다. 자체 호스팅 워커 선택지는 고객 데이터가 포함된 코드베이스를 다룰 때 특히 참고할 만하다.
