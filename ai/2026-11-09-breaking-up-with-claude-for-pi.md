# Claude와 작별하고 Pi로

> 출처: 원문 미확인 (GeekNews, id=36795) · 정리일 2026-11-09

> **출처 한계.** `news.hada.io`가 egress 차단되어 원문을 읽지 못했다. WebSearch로 "Claude와 작별하고 Pi로" 정확히 일치하는 글은 찾지 못했지만, Pi 에이전트 자체의 배경(창시자 Mario Zechner가 Claude Code의 빈번한 시스템 프롬프트·도구 정의 변경에 지쳐 2025년 11월 말 Pi를 공개했고, 2026년 4월 Earendil에 합류해 MIT 라이선스로 유지 중이라는 사실)은 복수 매체로 교차확인됐다. 이 글의 저자가 Zechner 본인인지, 아니면 Pi로 옮긴 또 다른 개발자인지는 Slack 발췌만으로는 특정할 수 없다 — Slack 발췌 자체가 1인칭 경험담 톤("Claude Code를 1년 넘게 써 온 개발자")이라 Zechner 본인의 글은 아닐 가능성이 더 높다(Zechner는 이미 2025년 11월에 이탈했으므로 "1년 넘게 써 왔다"는 시점과는 다소 안 맞는다).

## 한 줄 요약

**Claude Code를 1년 넘게 써온 한 개발자가 CLAUDE.md·AGENTS.md 간 복사/심볼릭 링크 관리, VS Code에서 세션 하나만 에디터와 연동되는 제약 등 누적된 불편 때문에 오픈소스 미니멀 코딩 에이전트 Pi로 주력 하네스를 옮기고, 아예 없던 멀티탭 연동 확장을 20분 만에 직접 만들었다.**

## 핵심 포인트

- Claude Code를 **1년 넘게 써온** 개발자가 작업 흐름을 방해하는 불편이 쌓이면서 주력 코딩 하네스를 오픈소스 코딩 에이전트 **Pi**로 옮겼다(Slack 발췌).
- 불편 사례: **CLAUDE.md와 AGENTS.md 사이의 복사/심볼릭 링크 관리**, VS Code에서 **한 세션만 IDE에 연결**할 수 있는 제약이 기존 작업 흐름을 방해했다(Slack 발췌).
- VS Code에서 Claude Code 터미널 세션을 여러 개 열어도, 에디터에서 선택한 코드를 자동으로 넘겨받는 세션은 **하나뿐**이었다 — Pi에서는 **여러 탭에서 이 기능을 쓸 수 있는 확장을 약 20분 만에 직접 만들었다**(Slack 발췌).
- "공식 VS Code GUI 확장은…" 부분에서 발췌가 절단돼, 공식 확장의 한계가 정확히 무엇이었는지는 알 수 없다.
- WebSearch 교차확인: Pi는 창시자 **Mario Zechner**가 Claude Code의 "릴리스마다 시스템 프롬프트·도구 정의가 바뀌어 자신의 워크플로우가 깨지는" 데 지쳐 2025년 11월 말 블로그 글과 코드를 함께 공개하며 시작됐다. 2026년 4월 Zechner가 Earendil에 합류한 뒤로도 **MIT 라이선스 핵심은 유지**되고 있다.
- WebSearch로 확인된 또 다른 관점: Pi를 시도해본 한 개발자는 "Pi가 Claude Code를 대체하기보다 내 워크플로우 옆에 나란히 자리 잡았다"고 결론 내렸고, 과금 방식에 대해서는 매체 간 서술이 상충한다(Anthropic 구독으로 Pi 세션까지 과금된다는 주장과, Pi가 기존 Claude Pro/Max 구독을 그대로 받는다는 주장이 공존) — 이 글의 저자가 과금 관련 불편을 언급했는지는 발췌에 없어 확인 불가.

## 내 생각 · 적용점

### 핵심 전이 1 — [[2026-10-02-pi-1-0-release-minimal-terminal-coding-agent]]와 연결: "미니멀"이라는 설계 철학이 실제 이주 사유로 작동

Pi 1.0 노트는 "Claude가 계획하고 GPT가 구현하고 Jev가 전환 시점을 판단"하는 멀티모델 조합과 미니멀리즘을 Pi의 특징으로 짚었다. 이 글은 그 미니멀리즘이 추상적 장점이 아니라, "공식 GUI 확장이 못 해주는 걸 20분 만에 직접 만들 수 있을 만큼 단순한 코드베이스"라는 구체적 이주 이유로 작동했음을 보여준다. 설계 철학(미니멀)과 실사용자 효용(커스터마이징 용이성)이 직접 연결되는 사례다.

### 핵심 전이 2 — [[2026-08-06-pi-minimalism-coding-harness]]와 연결: 미니멀리즘의 대가는 "직접 만들어야 하는 부분"

Pi의 미니멀리즘 철학 노트가 "작고 단순한 하네스"를 장점으로 짚었다면, 이 글은 그 이면 — 공식 확장이 다 갖춰지지 않아 사용자가 직접 20분짜리 확장을 만들어야 한다는 것 — 을 동시에 보여준다. 미니멀 하네스는 "기본 기능이 적다"는 단점과 "직접 고치기 쉽다"는 장점이 한 세트로 묶여 있다는 걸 실제 사례로 확인해준다.
