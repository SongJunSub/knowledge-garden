# WorldTUI - 터미널을 흉내 내는 3억 6천만 파라미터 AI 모델(원문 저자 미확인)

## 한 줄 요약

**WorldTUI는 실제 쉘이나 파일시스템 없이, 키 입력에 따라 다음에 뜰 터미널 화면을 예측하는 3.6억 파라미터 AI 모델이다 — Qwen2.5-Coder-0.5B를 실제 Docker 터미널 세션으로 미세조정했는데, 정답 화면만 학습시키는 대신 모델 자신이 만든 오류를 다음 입력에서 스스로 복구하도록 훈련해 긴 세션에서 오류가 누적되는 걸 줄였고, 화면의 여러 행을 병렬로 생성한 뒤 같은 모델로 검증하는 방식으로 M4 Mac 브라우저에서 `man test` 화면 갱신을 2.5초에서 약 0.9초로 단축했다.**

## 핵심 포인트

- **"실행"이 아니라 "예측"** — 실제 셸·파일시스템 없이 ***키 입력에 따라 다음 터미널 화면을 예측***한다. 파일을 만들고 vim으로 수정한 뒤 다른 tmux 창에서 읽는 동작까지 흉내 내고, 앞서 입력한 내용도 어느 정도 기억한다는 서술은, 이 모델이 단순 다음 글자 예측이 아니라 ***세션 전체의 상태(어떤 파일이 어떤 내용으로 존재하는가)를 암묵적으로 유지***하려 한다는 뜻이다.
- **작은 베이스 모델을 실제 세션으로 미세조정** — Qwen2.5-Coder-0.5B라는 ***작은 코드 모델***을 실제 Docker 터미널 세션 데이터로 파인튠했다. 프론티어급 모델이 아니라 0.5B급 베이스로도 터미널 흉내가 가능하다는 건, 이 과제가 범용 언어 이해보다 ***좁고 구조화된 분포(터미널 출력 형식)***를 학습하는 데 가깝다는 걸 시사한다.
- **핵심 설계 — 정답만 학습시키지 않고 "자기 오류에서 복구하기"를 학습시킨다** — 보통의 다음 토큰 예측 학습은 정답 시퀀스만 보여주는데, 이 모델은 ***자신이 만든 오류를 다음 입력에서 복구하도록*** 훈련시켰다. 긴 세션에서는 한 번의 작은 예측 오류가 다음 화면의 입력이 되어 오류가 누적되는 "노출 편향(exposure bias)" 문제가 생기는데, 이 설계는 그 누적을 직접 끊어내려는 시도다.
- **속도 최적화 — 병렬 생성 + 같은 모델로 자체 검증** — 화면의 여러 행을 ***병렬로 생성***하고 ***같은 모델로 검증***해 갱신 속도를 개선했다고 한다. M4 Mac 브라우저에서 `man test` 화면 갱신이 순차 생성 2.5초에서 약 0.9초로 단축됐다는 수치가 Slack 발췌에 있다(단, 원문 미확인).

## 내 생각 · 적용점

**핵심 전이 — [[2026-10-08-worldcrafter-video-world-model]]이 비디오 생성 축에서 보여준 "검증 가능성을 포기하고 그럴듯함을 사는" 월드 모델 계열에, WorldTUI는 터미널 텍스트 축의 같은 사례를 하나 더 추가한다.** WorldCrafter는 이미지 한 장에서 시작해 카메라를 돌렸다 돌아와도 "그 자리에 그대로 있는 것처럼 보이는" 공간을 영상으로 생성했는데, 그 노트의 핵심 구분은 ***"실제로 측정 가능한 좌표로 그 자리에 있는 것"과 "메모리로 그럴듯하게 복원하는 것"은 다르다***는 것이었다. WorldTUI는 완전히 다른 데이터 형식(텍스트 터미널 화면)에서 똑같은 질문을 던진다 — ***"파일을 만들고 다시 읽었을 때 그 내용이 그대로 있는 것처럼 보이는 것"과 "실제 파일시스템에 그 내용이 존재하는 것"은 다르다.*** 두 노트를 겹치면, 2026년 하반기의 "월드 모델" 유행이 영상·텍스트 등 형식을 가리지 않고 ***"그럴듯한 일관성을 학습으로 흉내 내는" 접근***으로 번지고 있다는 걸 보여준다. WorldTUI의 "자기 오류에서 복구하기" 학습 설계는, WorldCrafter의 3D 인식 메모리와 마찬가지로 ***그 그럴듯함이 깨지지 않도록 붙잡아두는 장치***라는 점에서 같은 역할을 한다.

## 호스피탈리티 / CRS 적용 포인트

**직접 적용은 멀다 — CRS 운영에 "가짜 터미널"이 쓰일 자리는 없다.** 다만 전이 가능한 원칙은 하나 있다.

- **"작은 모델을 좁은 분포로 파인튠해 저지연 로컬 추론을 노리는" 접근은 참고할 만하다.** WorldTUI가 0.5B급 베이스로 터미널이라는 좁은 출력 형식을 학습해 M4 Mac 브라우저에서 1초 미만 응답을 노린 것처럼, CRS 내부에서도 "범용 LLM API 호출" 대신 특정 좁은 작업(예약 상태 요약, 정해진 양식의 응답 생성)에는 작은 모델을 그 작업 분포로 파인튠해 지연·비용을 줄이는 선택지를 검토할 수 있다. 단, 이건 이 모델이 증명한 게 아니라 이 모델의 설계 방향이 시사하는 참고 원칙일 뿐이다.
