# 추론 칩을 바이브 코딩하기 (GeekNews, 1차 소스 특정 실패)

> 출처: GeekNews 발췌 · [GeekNews](https://news.hada.io/topic?id=37581) 경유 · 정리일 2026-11-22

## 한 줄 요약

**FPGA 개발 경험 없이 코딩 에이전트("Conductor")로 AWS FPGA 위에 LLM 추론 회로를 구현해 초당 213토큰(최초 구현보다 33배 빠름)에 도달했다는 보도이지만, WebSearch로 찾은 가장 근접한 후보 논문("Design Conductor 2.0", Verkor팀, 80시간·4-die XCVU29P FPGA)의 수치와 전혀 일치하지 않아 같은 사례인지 확정하지 못했다.**

## 핵심 포인트

- Slack 발췌: FPGA 개발 경험이 없는 상태에서 **회로 구성을 바꿀 수 있는 AWS FPGA**에 코딩 에이전트로 LLM 추론을 구현, 기준 출력과 비트 단위로 일치하는 최초 구현보다 ***약 33배 빠른 초당 213토큰***에 도달.
- Conductor에서 며칠간 실행한 에이전트는 수백 차례 실험하며 누적 약 **300만 줄의 코드**를 작성하고 3,000만 줄의 출력 파일을 분석, 토큰 비용으로 약 **1만 달러** 사용.
- 성능 향상은 한두 번의 큰 변화보다 **메모리 접근·병렬화·파이프라인·추론 디코딩**의 점진적 개선이 누적된 결과이며, 최종 속도는 213.13토큰/초.
- **출처 한계가 큼**: WebSearch로 찾은 가장 근접한 사례는 arXiv 논문 "Design Conductor 2.0"(Verkor팀, Ravi Krishna 등, 2026-05-07 공개) — 에이전트 "Conductor"가 가속기 "VerTQ"를 **80시간** 만에 설계, 대상 FPGA는 4-die XCVU29P였다. 하지만 이 논문에는 "AWS FPGA", "며칠간 실행", "300만 줄 코드", "$1만 비용", "213.13토큰/초", "33배 개선" 수치가 전혀 등장하지 않는다. 같은 Conductor 계열 시스템의 **별개 사례이거나 미검색된 최신 후속 버전**일 가능성이 있지만, 1차 소스로 특정하기엔 근거가 부족하다.
- arxiv.org 자체도 이 세션 네트워크에서 DNS 차단되어 원문 직접 확인은 못 했다.
