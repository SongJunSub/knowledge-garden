# [네이버] 뇌를 닮은 세컨드 브레인: 토큰 낭비 없는 RAG

> 출처: [뇌를 닮은 세컨드 브레인](https://d2.naver.com/helloworld/5087915) (Naver D2 · Slack 경유) · 정리일 2026-11-23
> **출처 한계를 먼저 밝힌다.** `d2.naver.com`이 이 세션에서 완전히 차단되어 원문을 읽지 못했다. WebSearch로도 이 글을 특정하지 못했고, 대신 일반적인 RAG 토큰 예산·설계 논의만 확인했다. "답변 재현율 99%"라는 수치는 **Slack 발췌에만 등장하는 주장이며 원문으로 검증하지 못했다.**

## 한 줄 요약

**네이버가 인간 뇌의 기억 구조(기억 저장 vs 작업 기억)를 모방한 차세대 메모리 아키텍처로, 기존 RAG의 토큰 낭비 문제를 해결하면서 답변 재현율 99%를 달성했다고 주장하는 사례.**

## 핵심 포인트 (Slack 발췌 기반, 원문 고유 디테일 아님 — "99%" 수치 미검증)

- 기존 RAG의 **토큰 낭비 문제를 해결**하고 뇌의 기억 구조를 모방한 차세대 메모리 아키텍처를 소개한다.
- **기억 저장과 작업 기억 단계를 분리**해 불필요한 토큰 사용을 줄였다고 밝힌다.
- ***실제 긴 대화와 코딩 과제에서 토큰 효율성을 검증하며 답변 재현율 99%를 달성***했다고 주장하지만, 이 수치의 평가 방법·테스트셋 규모는 원문 미확인으로 전혀 검증하지 못했다.

## 인상 깊은 문장

**없음.** 원문에 접근하지 못해 직접 인용을 제공할 수 없다.

## 댓글

GeekNews가 아니라 Slack TechArticles 봇 직링크라 hada 댓글 개념이 해당하지 않는다. "99% 재현율"은 **단일 출처(이 글 자체, 그것도 Slack 발췌)의 자체 주장**이라 숫자 그대로 받아들이기보다 "설계 방향성"으로만 읽는 게 안전하다.

## 내 생각 · 적용점

"기억 저장과 작업 기억을 분리한다"는 발상은 [[2026-09-02-memoryfields-agent-memory-file-format]]이 주장한 "에이전트 메모리는 하네스 종속 파이프라인이 아니라 재구성 가능한 파일 포맷이어야 한다"는 원칙과 맞닿아 있다 — 둘 다 "모든 걸 매번 다시 검색하지 말고, 자주 쓰는 것과 어쩌다 쓰는 것을 구조적으로 나누라"는 같은 통찰에서 출발한다. 또 [[2026-08-27-rag-is-simpler-than-you-think]]가 주장한 "RAG는 모델에게 많이 읽히는 게 아니라 꼭 필요한 것만 읽히는 설계"라는 원칙과도 정확히 같은 방향이다.

## 호스피탈리티 / CRS 적용 포인트

적용 가능성 있음 — CRS 상담 에이전트가 장기 고객 히스토리(과거 예약·클레임·선호도)를 매 응답마다 전부 다시 읽는 대신, "자주 참조하는 요약 기억"과 "이번 대화에서만 쓰는 작업 기억"을 분리해 저장하면 토큰 비용과 응답 지연을 함께 줄일 수 있다. 다만 "99% 재현율" 같은 벤더 주장은 그대로 들고 오지 말고, 실제 도입 전에 자체 평가셋으로 검증해야 한다.
