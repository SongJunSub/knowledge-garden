# Microsoft, Home·Code·Autopilot을 하나로 묶은 새 Copilot 발표

## 한 줄 요약

**Microsoft는 Chat·Cowork(Home)·자연어 앱 빌더(Code)·상시 실행되는 이름 붙은 에이전트(Autopilot)를 하나의 Copilot 앱으로 통합한 개편을 발표하며, Satya Nadella는 이를 ***"모든 모델·모든 폼팩터·모든 작업을 아우르는 업무용 새 OS"***라고 표현했다 — Home·Code는 Frontier 프로그램으로 곧 순차 출시되고, Autopilot은 이달 말 비공개 프리뷰로 들어간다.**

## 핵심 포인트

- **Home — Chat과 Cowork를 한 화면에** — 빠른 질문용 Chat과 장기 작업을 위임하는 Cowork를 한 곳에 모으고, Copilot을 벗어나지 않고 Word·Excel·PowerPoint 문서를 만들고 편집할 수 있게 한다.
- **Code — GitHub Copilot과 같은 기술 기반의 자연어 앱 빌더** — 비개발자도 조직 내부에서 안전하게 자체 솔루션(앱·자동화)을 만들 수 있도록 설계됐다고 소개된다. ***GitHub Copilot과 동일한 기술***을 쓴다는 점이 핵심 포인트.
- **Autopilot — 이름·역할·목표를 가진 상시 에이전트** — 소유자가 이름과 역할, 목표를 부여하는 에이전트로, ***아무도 쓰지 않을 때도 Microsoft 365 안에서 계속 작동***한다. 이달 말 비공개 프리뷰로 확장.
- **"업무를 위한 새 OS"라는 Nadella의 프레이밍** — ***"We're building Copilot as a new OS for work that spans every model, every form factor, and every task"*** — Anthropic·OpenAI를 겨냥한 채택률 확대 전략으로 다수 매체가 해석한다.
- **아이러니한 동시성 — Windows 11에서는 Copilot을 오히려 뺐다** — 여러 매체(Windows Latest 등)가 지적하듯, Microsoft가 Copilot을 "업무의 새 OS"로 선언한 바로 그 시점에 **Windows 11에서는 Copilot 통합 요소를 축소**하는 상반된 움직임이 함께 보도됐다 — 플랫폼 전략의 방향이 완전히 정렬돼 있지는 않다는 신호로 읽을 수 있다.

## 내 생각 · 적용점

### 핵심 전이 1 — "흩어진 에이전트를 하나로 모은다"는 같은 패턴이 벤더 제품에서도 반복된다

[[2026-09-24-stripe-kai-internal-ai-platform]]는 Stripe가 4,000개 넘는 중복 마이크로 에이전트를 공용 API·AgentStudio·공유 실행 환경 3층으로 통합한 사내 사례를 다뤘다. Microsoft의 이번 개편은 정확히 같은 통합 충동을, ***사내 도구가 아니라 외부 판매 제품*** 차원에서 보여준다 — Chat·Cowork·Code·Autopilot이라는 파편화된 기능들을 "하나의 OS"로 묶는다는 서사 자체가, 에이전트 생태계가 성숙할수록 반드시 거치는 "파편화 → 통합 플랫폼" 곡선의 또 다른 사례다. 다만 Stripe는 실사용 채택률(83%)이라는 내부 증거를 공개한 반면, Microsoft의 이번 발표는 아직 비전 선언에 가깝고 실제 채택 데이터는 없다는 차이가 있다.

### 핵심 전이 2 — "상시 실행 에이전트"라는 방향은 AWS Frontier Agents가 이미 걷고 있는 길과 같다

[[2026-08-28-aws-frontier-agents-devops-release-management]]가 다룬 AWS DevOps Agent는 "사람 개입 없이 상시 작동"하는 에이전트로 인시던트 대응에서 배포 전 게이트로 자율성을 넓혀왔다. Microsoft Autopilot이 표방하는 "아무도 쓰지 않을 때도 계속 작동하는, 이름·역할·목표를 가진 에이전트"는 같은 방향(상시성·위임 범위 확장)의 소비자/생산성 도구 버전이다 — 클라우드 인프라 영역과 오피스 생산성 영역에서 "상시 자율 에이전트"라는 같은 개념이 동시에 부상하고 있다는 신호로 읽을 수 있다.

## 호스피탈리티 / CRS 적용 포인트

**직접 도입은 시기상조다** — 온다는 Microsoft 365 생태계에 깊이 묶여 있지 않고, 이번 발표도 아직 프리뷰·순차 출시 단계라 구체 평가는 이르다. 다만 전이 가능한 원칙은 있다 — ***부서별로 흩어진 챗봇·자동화를 방치하면 결국 "하나의 플랫폼으로 통합"해야 하는 시점이 온다는 패턴을 Stripe Kai 사례와 함께 재확인***한다. CRS/PMS 내부 자동화가 늘어날 때, 대형 벤더처럼 사후에 통합하기보다 초기부터 공용 실행 계층과 부서별 거버넌스를 분리해 설계하는 편이 낫다는 원칙만 가져올 수 있다.
