# MCP는 처음부터 잘못된 아이디어였을까?

> 출처: [GeekNews 토픽](https://news.hada.io/topic?id=34059) (원문 매체·저자 특정 실패) · 정리일 2026-09-22
>
> **출처 한계**: `news.hada.io` egress 차단으로 원문 접근 불가. Slack GN⁺ 발췌(4개 불릿, 마지막이 "CLI의 장황한 JSON/XML 응답도 토큰을 낭비하지만, 별도…"에서 잘림)만으로는 정확한 원문을 특정하지 못했다. WebSearch로 확인한 Hacker News "MCP was always a bad idea?" 스레드(및 "MCP is a fad" 스레드)가 같은 시기 같은 논지를 다루고 있어 이를 근거로 문맥을 보강했으나, 정확히 동일한 글인지는 확정하지 못했다.

## 한 줄 요약

**MCP(Model Context Protocol)는 2024년 11월, 에이전트가 아직 신뢰할 수 없고 모델이 API 사용법을 스스로 파악하기 어렵던 시절의 발명품인데, 코드 실행과 CLI 탐색에 능숙해진 최신 모델에게는 기존 API를 다시 감싸는 MCP 서버가 오히려 컨텍스트만 낭비하는 불필요한 중간 계층이 되어가고 있다 — 다만 접근 권한을 엄격히 통제해야 하는 상황에서는 여전히 MCP의 존재 이유가 있다.**

## 핵심 포인트

- **전제가 바뀌었다** — MCP는 2024년 11월 25일 공개 당시 ***모델의 역량이 지금보다 제한적이고 Claude Code 같은 범용 에이전트 워크플로의 신뢰성이 낮던 시절***을 전제로 설계됐다(WebSearch 교차확인).
- **코드 실행 에이전트에는 재포장이 불필요** — 코드를 실행하고 API를 직접 호출할 수 있는 에이전트에는 ***기존 API를 다시 감싼 MCP 서버가 불필요***해졌으며, 필요한 기능이 이미 있는 HTTP API와 CLI를 직접 사용하면 된다.
- **MCP 서버가 늘수록 컨텍스트 과부하** — MCP 서버를 늘릴수록 ***도구 설명과 스키마가 컨텍스트를 과도하게 차지***하고, 이를 해결하려 도구 검색·서버 관리 시스템까지 추가되는 구조적 악순환이 생긴다.
- **최신 모델은 API를 스스로 탐색한다** — 최신 모델은 처음 접하는 API의 사용법을 파악하고, `--help`로 CLI를 탐색하며, ***여러 서비스를 스크립트로 묶어 실행***할 수 있다.
- **그럼에도 통제가 필요한 상황엔 MCP가 여전히 유효(WebSearch 보강)** — 에이전트에 무제한 권한을 주는 대신 접근을 제한해야 하는 경우, MCP는 ***접근 가능한 외부 서비스를 정밀하게 제한하고, API 키를 에이전트에 노출하지 않고 인증을 처리하며, 감사 로그를 제공***하는 거버넌스 도구로서 여전히 의미가 있다는 반론도 함께 다뤄진다.

## 내 생각 · 적용점

### 핵심 전이 — 가든의 "MCP는 죽었다, CLI/스킬이 이긴다" 계열과 정확히 같은 결을 반복하며 "거버넌스 예외"를 추가

가든에는 이미 [[2026-05-29-mcp-is-dead-cli-skills]]가 같은 논지("MCP는 죽었다, CLI 스킬이 대세")를 다뤘고, [[2026-08-23-mcp-new-roadmap-five-areas]]는 MCP 진영의 대응(새 로드맵)을 다뤘다. 이 글은 그 논쟁에 ***"통제·감사가 필요한 엔터프라이즈 상황에서는 MCP가 여전히 이긴다"***는 절충안을 더한다 — 즉 논쟁의 축이 "MCP냐 CLI냐"가 아니라 "신뢰할 수 있는 자율 에이전트냐, 통제가 필요한 제한된 에이전트냐"로 이동하고 있다는 뜻이다. 이는 [[2026-09-05-ask-hn-mcp-in-production]]이 실무자들 사이에서 이미 감지한 온도차와도 일치한다.

## 호스피탈리티 / CRS 적용 포인트

CRS·PMS 연동 에이전트를 설계할 때 이 절충안이 그대로 적용된다 — 사내 개발팀이 신뢰하는 자동화 스크립트는 API·CLI를 직접 호출하게 하되, 파트너사·외부 벤더에 노출하는 에이전트는 MCP처럼 접근 범위를 정밀하게 제한하고 감사 로그를 남기는 계층을 유지하는 것이 안전하다. "빠르고 유연한가"와 "통제 가능한가"는 다른 축의 요구사항이라는 점을 기억해야 한다.
