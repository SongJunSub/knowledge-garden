# Fable 5, 높은 추론 설정에도 실제 추론량이 줄었다는 분석

> 출처: [GeekNews 토픽](https://news.hada.io/topic?id=34081) (원문 매체·저자 특정 실패) · 정리일 2026-09-22
>
> **출처 한계**: `news.hada.io` egress 차단으로 원문 접근 불가. Slack GN⁺ 발췌(4개 불릿, 마지막이 "긴 작업에서 여러 호출에 걸쳐 쌓인 추론 토큰은 한 번에 깊게 추론한 양과 다르며, 에이전트를 더 많이 실행한…"에서 잘림)만으로는 원문 저자를 특정하지 못했다. WebSearch로 Claude Fable 5.1의 effort 레벨(xhigh/max) 공식 설명은 확인했으나, 이 구체적 분석(사용 기록 기반 8월 vs 7월 비교)의 원문 자체는 찾지 못해 Slack 발췌 중심으로 재구성했다. **이 글은 "Fable 5" — 이 가든 저자가 실제로 매일 쓰는 Claude Code 위의 모델(현재 세션은 Sonnet 5로 서빙되지만 harness는 Fable 5.1로도 폴백 가능) — 의 실사용 추론량을 다룬다는 점에서 다른 노트보다 직접적인 실무 함의를 가진다.**

## 한 줄 요약

**Claude Code에서 Fable 5의 성능 저하를 체감한 한 개발자가 자신의 사용 기록을 분석한 결과, 같은 높은 추론 설정(xhigh, max)에서도 8월의 추론 토큰이 7월보다 사용자 요청별 중앙값 기준 21.9% 감소했고, 심지어 개별 호출의 39.2%는 추론 토큰이 아예 0개였다 — 즉 "높은 추론 설정"이 실제로 깊게 추론한다는 것을 보장하지 않는다.**

## 핵심 포인트

- **같은 xhigh/max 설정에서도 8월 추론량이 7월보다 감소** — Claude Code에서 Fable 5의 성능 저하를 체감한 개발자가 사용 기록을 분석한 결과, ***같은 높은 추론 설정에서도 8월의 추론 토큰이 7월보다 감소***했다.
- **사용자 요청별 중앙값 21.9% 감소, 여러 통제 변수로도 유지** — 사용자 요청별 추론량 중앙값은 ***21.9% 감소***했으며, 날짜·세션·프로젝트별 사용량 차이를 반영하거나 개별 모델 호출을 비교해도 감소세가 유지됐다 — 즉 단순히 "사용 패턴이 바뀌어서"로 설명되지 않는다.
- **xhigh·max에서도 호출의 39.2%는 추론 토큰이 0개** — xhigh와 max 설정에서도 ***개별 호출의 39.2%는 추론 토큰이 없었고, 절반은 123개 이하***에 그쳤다 — 최고 수준의 추론 노력을 설정해도 모델이 매 호출마다 깊게 생각하는 것은 아니라는 뜻이다.
- **누적 추론 토큰과 "한 번에 깊게 추론"은 다른 개념** — 긴 작업에서 여러 호출에 걸쳐 쌓인 추론 토큰은 ***한 번에 깊게 추론한 양과 다르며, 에이전트를 더 많이 실행한…*** (발췌 절단) — 총 추론 토큰 수치가 늘어도 그것이 "각 판단을 더 깊게 했다"는 뜻은 아닐 수 있다는 방법론적 경고로 이어지는 것으로 보인다.

## 내 생각 · 적용점

### 핵심 전이 — "effort 설정값 = 실제 추론량"이라는 가정 자체를 의심해야 한다는, 이 가든에 가장 실무적으로 와닿는 경고

가든에는 [[2026-08-23-claude-code-reasoning-effort-ab-test]](effort 레벨 A/B 테스트), [[2026-09-18-harnesstax-coding-agent-harness-cost-study]](하네스 비용 연구), [[2026-09-02-aws-claude-code-token-economy-part1]]·[[2026-09-02-aws-claude-code-token-economy-part2]](토큰 이코노미) 등 Claude Code 사용 비용·효율을 다룬 노트가 이미 쌓여 있다. 이 글이 더하는 것은 ***"effort를 xhigh·max로 올려도 매 호출이 실제로 더 깊게 추론한다는 보장은 없다"***는 구체적 반증 사례다. 이는 [[2026-09-21-prompts-dont-exist]]가 경고한 "변경 전후 동작을 테스트로 비교해야 실제로 개선됐는지 알 수 있다"는 원칙과 정확히 같은 함정이다 — effort 설정값이라는 "다이얼"을 올렸다고 안심하지 말고, 실제 추론 토큰 소비량을 직접 계측해야 한다는 뜻이다.

### 클로드 사용자 관점에서 — 이 가든 저자가 직접 참고할 만한 글

이 저자(사용자)가 Claude Code를 매일 쓰는 입장에서, "effort를 max로 올렸는데 왜 얕게 답하지?"라는 체감이 든다면 이 분석이 그 원인 중 하나(모델·라우팅 계층의 동적 조절)를 가리킬 수 있다. 중요한 작업에서는 설정값보다 실제 출력의 추론 흔적(그리고 필요하다면 후속 질문으로 재확인)을 신뢰하는 습관이 더 안전하다는 실무적 시사점을 준다.
