# Tokenmaxxing은 죽었다, Tokenmaxxing 만세 (12gramsofcarbon.com) — '누적 오류에서 누적 정확성으로', 에이전트 루프가 경제성을 역전시키고 소프트웨어 팩토리가 온다

> 출처: [Tokenmaxxing is Dead, Long Live Tokenmaxxing](https://12gramsofcarbon.com/p/agentics-tech-things-tokenmaxxing) (12gramsofcarbon.com) · 정리일 2026-06-29

## 한 줄 요약

**Tokenmaxxing(토큰 사용량을 성과 KPI로 만든 기업 정책)의 초기 형태는 끝났지만, "누적 정확성(더 많은 토큰 = 더 나은 결과)" 패러다임이 등장하면서 에이전트 루프·소프트웨어 팩토리라는 새 형태로 부활 중이다. 핵심은 최고 모델 무제한 지출이 아닌 저렴한 오픈 모델을 루프로 반복하는 비용 구조다.**

## 핵심 포인트

- **Tokenmaxxing 정의** — 메타 등 기업이 직원 AI 토큰 사용량을 성과평가 KPI로 삼은 정책. 일부 직원이 "에이전트끼리 하루 종일 대화시키는" 형식적 사용을 했지만, 저자는 이를 AI 도입 저항을 뚫기 위한 의도적 강제화 전략으로 해석.
- **누적 정확성(Compounding Correctness)** — 과거: 장시간 에이전트 실행 시 오류가 쌓여 결과 악화. 현재: 토큰 투자 증가 → 결과 품질 향상. 사이버보안 사례: 시도당 100M 토큰($12,500) 투입 시 감소 신호 없이 계속 취약점 발견.
- **에이전트 루프** — 프롬프트 → 에이전트 실행 → 결과 재입력 → 반복. 누적 정확성 덕분에 반복할수록 개선. 인간 감시 없이 자율 실행.
- **두 가지 유형**:
  - **개발자용**: Claude Code 루프 → 엔지니어 생산성 향상 → 비용 정당화 가능
  - **파이프라인용**: 맞춤형 에이전트 → 품질 불안정 → 확인 에이전트 추가 → 토큰 비용 3배 증가 위험
- **비용 구조 전환** — 최상위 모델 무제한 지출 → 저렴한 오픈 모델 루프 반복이 실용적 중심:
  - GLM 5.2: $1.4/1M 토큰 (Haiku보다 강력, 더 저렴)
  - Claude Opus 4.X: $5/1M 토큰
  - Haiku 4.5: $1/1M 토큰
- **소프트웨어 팩토리 전망** — "명세서 입력 → 완성된 애플리케이션 출력". 코드 생성·리뷰·디버깅·테스트 자동화. StrongDM 목표: 엔지니어 1명당 $1,000/일 토큰 사용. 현실: 월 $600 수준.
- **규제** — OpenAI GPT 5.6·Anthropic Mythos 모두 정부 사전 승인 후 선별 배포. 국가가 산업 승자 결정에 개입하는 구조.

## 댓글 — HN 다양한 관점 (GN⁺ 큐레이션)

1. **의도적 전략 해석**: Tokenmaxxing = AI 도입 강제화 임시 조치. 목적 달성 후 폐기되는 성격.
2. **누적 정확성 의문**: 실제로 루프가 항상 개선을 가져오는가? 맥락 관리 부재로 루프가 오히려 엉뚱한 방향으로 발산할 수 있다는 지적.
3. **대기업 압박 구조**: 관리자들은 상위 압박으로 유행어 섞인 조치를 취할 뿐 — "AI 전략이 없어서 KPI로 대체한다"는 비판.
4. **빅데이터 붐 유사성**: 과거 하둡 도입 강제화와 동일 패턴. 도구 사용량 자체가 목표가 되는 함정.
5. **기업 리더십 낭비 사례**: 서버 이름 변경, AI 브랜딩 비용 등 실질 효과 없는 지출 사례들.

## 내 생각 · 적용점

### 핵심 전이 1 — Claude Code 루프 = 개발자용 Tokenmaxxing의 정당한 형태

"개발자용 Tokenmaxxing"이 가장 ROI가 명확하다. **Claude Code로 루프를 실행하면서 CRS·PickMe 기능을 구현할 때, 토큰 비용이 발생하지만 이것은 생산성 향상으로 직접 정당화된다.** 반면 "파이프라인용" — 에이전트를 자동화 파이프라인에 넣고 확인 에이전트를 추가하면 비용이 3배로 늘어나는 구조를 먼저 설계해야 한다. BugSip·stock-autotrader의 AI 파이프라인 설계에서 "확인 에이전트 추가 비용"을 미리 계산하고 시작해야 한다.

### 핵심 전이 2 — "누적 정확성 vs 누적 오류" 판단 기준

루프를 돌릴 때 "누적 정확성"이 작동하는 조건이 있다: 피드백 신호가 명확하고(사이버보안: 취약점 발견/미발견), 컨텍스트가 보존되며, 반복이 수렴하는 방향이 있을 때. **맥락 관리가 안 되는 루프는 오히려 "누적 오류"로 발산한다.** [[2026-06-29-decisions-and-dollars-ai-proof]]의 "쓰기 방어"와 연결 — 루프가 발산하는 방향으로 "쓰기"를 허용하면 돌이키기 어렵다.

### 핵심 전이 3 — 오픈 모델의 비용 효율이 벤더 종속 방지 전략이다

GLM 5.2($1.4/1M)가 Haiku보다 강력하면서 더 저렴하다는 것은 중요한 신호다. **"최상위 모델 API에 의존하는 서비스"는 벤더 가격 인상·정책 변경에 취약하다.** [[2026-06-28-physical-media-ownership]]의 "통제권이 소유권의 본질"처럼, 오픈 모델을 루프로 자체 운영하는 것이 장기적으로 더 안전한 구조다. [[2026-06-29-weekly-364]]의 규제 역설과도 연결 — 프론티어 모델 접근 제한이 강해질수록 오픈 모델의 가치가 더 커진다.
