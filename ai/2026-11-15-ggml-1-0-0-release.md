# ggml v1.0.0 — 폐기 API 정리와 FP8·RPC v9로 선언한 '1.0'

> 출처: [ggml v1.0.0 릴리스](https://github.com/ggml-org/ggml/releases) (ggml-org · GitHub Releases) · 정리일 2026-11-15
>
> **출처 한계**: news.hada.io는 이 세션에서 egress 차단되어 hada 댓글·반응은 확인 불가. 대신 GitHub 릴리스 페이지 원문을 직접 열람해 Slack 발췌보다 더 세부적인 변경 목록을 확인했다. 다만 릴리스 노트 자체가 CPU 백엔드 항목 중간에서 페이지네이션으로 잘려 있어(약 10만 자 지점), 그 이후 항목은 이 노트에 반영하지 못했다.

## 한 줄 요약

**llama.cpp의 텐서 연산 엔진 ggml이 사용 중단(deprecated) 공개 API와 레거시 `DIAG_MASK` 연산을 들어내고, RPC 프로토콜을 호환성 단절(v9)까지 감수하며 올리고, CUDA/Metal 양쪽에 FP8·MoE 성능 개선을 넣은 채로 버전 번호를 1.0.0으로 선언했다 — "로컬 추론 라이브러리가 이제 막 쓰기 시작해도 되는 API 표면을 가졌다"는 신호다.**

## 핵심 포인트

- ***사용 중단 API·`DIAG_MASK_INF`/`DIAG_MASK_ZERO` 연산 제거*** — pre-1.0 기간 내내 쌓인 레거시를 이번에 정리했다. `ggml_rope_set_truncate`/`get_truncate`로 YaRN 보정 경계의 반올림을 제어할 수 있게 됐고, `TRI` 연산의 backward 패스도 새로 구현됐다.
- **RPC 프로토콜 v9 — 이전 버전과의 연결을 명시적으로 거부.** v0.27.0의 v8에서 올라간 것으로, 더 빠른 로딩과 핸드셰이크 실패 시의 정상적인 실패 처리를 포함한다. ***분산 추론(원격 GPU 노드)에 RPC를 쓰는 환경은 클라이언트·서버를 동시에 업데이트해야 한다*** — 반쪽만 올리면 바로 끊긴다.
- **CUDA — OCP FP8 지원, 배치 2~24 전용 MMQ.** FlashAttention에 sm70 head-size-256과 MMA head size 40/72가 추가됐고, MoE 쪽은 빈 stream-k 타일을 건너뛰고 레이아웃을 선형화해 지연을 줄였다. VMM 풀 예약도 절반으로 줄이며 재시도 로직을 넣었다.
- **Metal — MoE 라우팅 연산을 하나의 command buffer로 융합.** 결정적(deterministic) radix Top-K, GROUP_NORM·FA 출력·SOLVE_TRI 커널의 범위 밖 접근 버그 수정 등 안정성 쪽 패치도 섞여 있다.
- **'1.0.0'이 상징하는 것** — 버전 번호 자체가 기능보다 ***API 안정성 선언***에 가깝다. pre-1.0 동안 FP8 E4M3 타입(v0.29.0)처럼 기능은 계속 들어왔지만 공개 API가 자주 흔들렸는데, 이번에 그 흔들림의 원인이던 레거시를 걷어내고서야 1.0을 붙였다.

## 내 생각 · 적용점

**핵심 전이 1 — 이 레포에서 "로컬 LLM이 쓸만해졌다"고 기록한 대부분의 글이 실은 이 라이브러리 위에 서 있다.** [[2026-10-05-strata-qwen38-flash-next-local-inference]]는 "엔진 자체와 기반 GGML/llama.cpp는 MIT"라고 명시했고, [[2026-10-17-ps5lm-ps5-llamacpp-home-model-server]]는 이름부터 llama.cpp 기반이다. 즉 이 레포가 쌓아온 "로컬 AI 진입장벽이 계속 낮아진다"([[2026-11-14-edge0-145b-local-model]] 등)는 서사의 상당수가, 표면적으로는 각기 다른 제품처럼 보여도 바닥에서는 같은 ggml 코드베이스의 성능 개선에 의존하고 있다.

**핵심 전이 2 — "API 안정화"는 기능 추가보다 늦게, 그리고 더 조심스럽게 온다.** 흥미로운 모델·벤치마크 뉴스(Qwen3.8-Flash-Next, Edge0 등)는 매주 쏟아지지만, 그걸 실제로 돌리는 하부 엔진이 "이제 공개 API를 믿고 써도 된다"고 선언하기까지는 수십 번의 pre-1.0 마이너 릴리스가 필요했다. 화려한 응용 계층 뉴스에 묻혀 눈에 잘 안 띄지만, 생태계 전체의 안정성은 이런 로우레벨 정리 작업이 받친다.

## 호스피탈리티 / CRS 적용 포인트

**직접 적용은 멀다.** 온다의 CRS는 클라우드 멀티테넌트 SaaS이고, ggml은 개인 하드웨어·온프레미스 로컬 추론을 위한 텐서 연산 라이브러리라 접점이 거의 없다. 다만 전이 가능한 원칙 하나는 남긴다 — ***FP8 같은 저정밀도 연산 지원이 늘수록 "민감한 예약·고객 데이터를 다루는 추론을 온프레미스/프라이빗 환경에서 돌리는 비용"이 계속 낮아진다.*** 지금은 멀더라도, 호스피탈리티 업계가 PII가 많은 CRS 데이터를 클라우드 LLM API 밖으로 내보내길 꺼리는 시점이 오면, 이런 로컬 추론 엔진의 성숙도가 "자체 호스팅 옵션을 제공할 수 있는가"를 가르는 변수가 될 수 있다.
