"최대 80%"라는 수사가 정확히 어느 모델·어느 인하를 가리키는지는 원문 미확보로 단정할 수 없다.

## 한 줄 요약

**OpenAI와 Anthropic이 지난 몇 달간(2026년 7월~10월) 모델 품질을 떨어뜨렸다는 뚜렷한 징후 없이 가격을 반복적으로 내렸고, 이 효과는 API 단가뿐 아니라 Codex·Claude Code 같은 구독형 코딩 에이전트 하네스에도 그대로 번졌다.** 이 가든이 그때그때 따로 정리해둔 개별 인하 발표들을 한 줄에 놓고 보면, 인하가 한 번의 사건이 아니라 **지속되는 경쟁 압력의 연속**이라는 게 드러난다 — 그리고 코딩 에이전트에서는 입출력 단가보다 **캐시 읽기 단가**가 실제 체감 비용을 훨씬 더 크게 좌우한다.

## 핵심 포인트

- **"몇 달" 동안 반복된 인하, 단발성이 아니다** — 7/30 GPT-5.6 Luna 80%·Terra 20% 인하 → 8/21 GPT-5.6 Sol 20% 인하(그 결과 Sol이 Anthropic Opus 5보다 입출력 모두 저렴해짐) → 9/1 Claude Fable 5.1 캐시 읽기 75% 인하 → (WebSearch로만 확인) 10/7 Claude Sonnet 5.5 캐시 읽기 추가 50% 인하. ***같은 패밀리 안에서 여러 차례 인하가 겹친다는 것 자체가 "일회성 프로모션"이 아니라 구조적 가격 압력의 신호***다.
- **캐시 읽기 단가가 체감 비용을 좌우한다** — 코딩 에이전트는 매 턴마다 시스템 프롬프트·도구 정의·레포 상태 같은 긴 접두사를 반복해서 다시 읽는다. [[2026-08-16-maximizing-claude-code-sessions]]와 [[2026-09-02-aws-claude-code-token-economy-part2]]가 공통으로 확인한 수치는 ***"캐시 적중 시 표준 입력 단가의 10%(즉 0.1배)"*** — 이 값이 깎이면 입출력 단가 변화보다 훨씬 큰 폭으로 실비용이 움직인다. 그래서 Anthropic이 Fable 5.1·Sonnet 5.5에서 **입출력가는 그대로 두고 캐시 읽기만 집중적으로 내린 것**은 "코딩 에이전트 사용자를 정확히 겨냥한 인하"로 읽을 수 있다.
- **입력/출력 단가만 보면 인하 폭을 놓친다** — Anthropic 자체 추산으로 Fable 5.1의 캐시 읽기 인하는 일반 작업에서 약 25%, 에이전트형 작업에서는 최대 약 45%까지 실질 비용을 낮춘다([[2026-09-02-claude-fable-5-1-mythos-5-1-release]]). 즉 "입력 $10/출력 $50 그대로"라는 표면적 숫자만 보면 아무 변화가 없어 보이지만, 캐시 적중률이 높은 실사용 워크로드에서는 체감 인하가 훨씬 크다.
- **구독형 하네스로도 번진 효과** — OpenAI는 Luna/Terra/Sol 인하를 API뿐 아니라 ChatGPT Work·Codex 크레딧에도 동일 적용했다([[2026-08-23-gpt-5-6-sol-price-cut-20-percent]]). Claude Code 쪽도 캐시 경제학이 그대로 적용되는 소비 구조([[2026-09-02-aws-claude-code-token-economy-part2]])라, API 가격 인하는 구독 요금제의 "실질 사용 가능량"을 늘리는 효과로 이어진다.
- **모델 교체 용이성 + 공개 가중치 압력** — OpenAI는 Sol 인하 배경으로 "Anthropic 및 중국계 AI 모델과의 경쟁 심화"를 스스로 명시했다([[2026-08-23-gpt-5-6-sol-price-cut-20-percent]]). 추론 제공업체가 늘고 DeepSeek·Qwen 같은 공개 가중치 모델이 저가 대체재로 자리잡으면서, 두 회사의 상호 견제뿐 아니라 "언제든 떠날 수 있다는 압력" 자체가 가격을 끌어내리는 레버리지로 작동한다는 해석이 여러 매체에서 공통으로 나온다(단, 이는 WebSearch로 교차확인한 2차 해석이며 hada 원문의 논지와 정확히 같은지는 확인 못함).
- **캐시 무효화라는 함정이 남아 있다** — [[2026-09-02-aws-claude-code-token-economy-part2]]가 짚었듯, 모델 전환·도구 설정 변경·소프트웨어 업그레이드는 캐시 키를 바꿔 다음 요청부터 대화 전체를 정가로 재프리필시킨다. 캐시 읽기 단가가 아무리 싸져도, 세션 중간에 이런 무효화가 반복되면 실제 절감 효과는 사용 습관에 크게 좌우된다.

## 내 생각 · 적용점

**핵심 전이 1 — [[2026-09-02-claude-fable-5-1-mythos-5-1-release]]와의 연결.** 그 노트에서 이미 "벤치마크보다 캐시 읽기 75% 인하가 실질적인 변화"라고 짚었는데, 이번 글이 그 개별 사건을 "몇 달간의 패턴"으로 묶어 보여준다. 개별 발표를 따로 볼 때는 안 보이던 흐름(인하가 반복되고, 특히 캐시 읽기에 집중된다는 것)이 시계열로 묶으니 드러난다 — 가든에 개별 노트를 쌓아두는 것의 효용을 보여주는 사례.

**핵심 전이 2 — [[2026-08-16-maximizing-claude-code-sessions]]와의 연결.** 그 노트가 확인한 "캐시 읽기 = 입력가의 0.1배"라는 수치가, 이번 글의 "입출력 단가만 보면 실제 인하 폭을 놓친다"는 주장의 산술적 근거가 된다. 평소 Claude Code를 쓸 때 체감하는 비용 변화가 공식 가격표의 입력/출력 숫자가 아니라 캐시 적중률에 훨씬 좌우된다는 걸 숫자로 다시 확인했다.

**핵심 전이 3 — [[2026-10-20-aws-ai-agent-token-economics-bedrock]]과의 연결.** 그 노트가 "토큰량이 비용의 좋은 대리 지표가 아니다"라고 했던 역설이, 이 글의 "표면적 단가 인하율만 보면 실제 절감을 놓친다"는 지점과 같은 축이다. 비용을 따질 때 리스트 프라이스가 아니라 실제 캐시 적중 패턴을 봐야 한다는 결론이 두 글에서 반복된다.

## 호스피탈리티 / CRS 적용 포인트

온다가 Claude Code·Claude API를 코드 리뷰·내부 자동화에 실제로 쓰고 있다는 전제에서, 이 글은 직접 체감 비용과 맞닿아 있다. CRS 자체(예약·재고·요금 로직)에 LLM을 박아넣는 설계는 아직 없지만, **에이전트 하네스를 운용할 때 "입력/출력 단가가 싸졌다"보다 "같은 작업을 반복하는 세션에서 캐시 적중률을 얼마나 유지하느냐"가 실제 비용을 좌우한다**는 원칙은 바로 적용 가능하다 — 모델·설정 전환을 세션 중간에 자주 하면 캐시가 무효화돼 겉보기 가격 인하 효과를 못 누린다는 점을 팀 내 Claude Code 사용 가이드에 반영할 만하다.
