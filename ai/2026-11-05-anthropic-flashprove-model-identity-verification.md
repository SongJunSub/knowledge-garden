# Anthropic, AI 응답이 어느 모델에서 나왔는지 검증하는 FlashProve 공개

> 출처: [Anthropic, AI 응답이 어느 모델에서 나왔는지 검증하는 FlashProve 공개](https://news.hada.io/topic?id=36617) (Anthropic · news.hada.io, 원문 블로그/논문 미확인) · 정리일 2026-11-05

## 한 줄 요약

**FlashProve는 모델 가중치를 공개하지 않고도, 응답이 사전에 지정한 모델의 실제 계산 결과와 일치하는지 암호학적으로 검증하는 오픈소스 연구 프로토타입. 모델 제공자가 가중치를 암호학적으로 확정해두면, 사용자는 모델을 직접 실행하지 않고도 "모델 바꿔치기"나 "응답 변조" 여부를 확인할 수 있다고 소개된다.**

## 핵심 포인트

- ***"가중치를 공개하지 않고도 응답이 사전에 지정한 모델의 계산 결과와 일치하는지 검증"*** — 핵심은 "신뢰"가 아니라 "증명"으로 바꾸는 것. 사용자가 모델을 직접 실행하지 않고도 모델 바꿔치기·응답 변조 여부를 확인 가능하다고 주장.
- **4비트 양자화 Llama 4 Maverick 400B**에서 H100 한 장으로 **초당 약 110토큰의 증명 처리량**을 기록. GPU 사용 시간은 vLLM 추론의 **약 70~95배**(증명 생성 비용이 추론보다 훨씬 비쌈을 시사).
- 현재는 **최대 1,024토큰 문맥**에서, 모델이 매번 확률이 가장 높은 토큰을 고르는 방식(결정적 디코딩)만 검증 가능 — Slack 발췌가 이 지점에서 절단되어 **그 이상의 한계(샘플링 디코딩 지원 여부 등)는 확인 불가**.
- WebSearch로 "FlashProve"라는 이름의 Anthropic 공식 발표를 찾지 못했다. 가장 근접한 연구는 Offchain Labs의 arXiv 논문("Towards Verifiable AI with Lightweight Cryptographic Proofs of Inference", arXiv:2603.19025)으로, **경량 암호학적 추론 증명**이라는 같은 문제의식을 다루지만 Anthropic 소속이 아니다 — 동일 프로젝트인지 완전히 다른 프로젝트인지 이번 조사로는 확정 불가.

## 댓글

**출처 한계가 이례적으로 크다.** news.hada.io 원문이 차단됐고, WebSearch로도 "FlashProve"라는 이름 자체를 확인하지 못했다(Anthropic 공식 블로그·논문·GitHub 어디서도 검색 결과에 나타나지 않음). 검색 결과는 대신 ZK-Receipt(NeurIPS, 모델 실행이 아니라 서명만 증명), Crovia Seal(Ed25519 서명 영수증, 실행 증명은 아님) 같은 인접 프로젝트, 그리고 가장 근접한 Offchain Labs의 경량 추론 증명 논문을 보여줬다. **이 노트는 Slack 발췌(그마저 말미가 절단됨)에 전적으로 의존해 작성했으며, "Anthropic"이라는 주체 확인조차 1차 소스로 못 했다는 점을 분명히 밝힌다.**

## 내 생각 · 적용점

### 핵심 전이 1 — 워터마킹과 FlashProve는 "같은 질문, 다른 증명 수준"

[[2026-08-16-how-ai-text-watermarking-works]]는 "워터마크는 '누가 썼다'가 아니라 '거쳐 갔다'를 뜻하고, 통계적 추정일 뿐"이라는 핵심 한계를 다뤘고, [[2026-08-12-claude-ai-content-marking]]은 "표시가 있어도 출처를 확정하지 못하고, 표시가 없어도 AI 생성을 배제 못 한다"는 한계를 짚었다. FlashProve가 주장하는 건 그 한계를 정면으로 넘어서는 것 — **통계적 추정이 아니라 암호학적 증명**. 하지만 비용이 vLLM 추론의 70~95배라는 수치는, "증명 가능성"과 "실용성" 사이의 전형적인 트레이드오프를 그대로 보여준다. 워터마킹 계열 노트들을 묶으면 **"모델/콘텐츠 출처 확인"이라는 하나의 문제를 통계적 추정 → 서명 → 암호학적 증명으로 점점 강한 보증을 요구하며 풀어가는 스펙트럼**이 보인다.

### 핵심 전이 2 — "모델 바꿔치기" 우려는 API 제공자 신뢰 문제의 연장선

사용자가 특정 모델을 호출했다고 믿지만 실제로는 다른(더 싸거나 성능이 낮은) 모델이 응답했을 수 있다는 우려는, 클라우드 추론 API 생태계 전반에 깔린 "제공자를 얼마나 신뢰할 것인가" 문제와 같다. 증명 비용이 매우 비싸다는 점에서, 당장은 "고신뢰가 필요한 소수 요청에만 선택적으로 증명을 요구"하는 형태로 쓰일 가능성이 높다.

## 호스피탈리티 / CRS 적용 포인트

**직접 적용은 멀다.** CRS에서 "어느 LLM이 이 응답을 생성했는가"를 암호학적으로 증명해야 할 규제·신뢰 요구는 현재로선 낮다. 다만 **원칙만 전이**: 외부 LLM API를 CRS 자동화에 쓸 때 "계약한 모델이 실제로 응답을 생성했는가"를 신뢰에만 의존하고 있다는 점을 인식하는 계기로 참고할 수 있다.
