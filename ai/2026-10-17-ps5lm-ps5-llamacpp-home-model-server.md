# PS5LM — 탈옥한 PS5를 llama.cpp 홈 모델 서버로 (Slack의 '55토큰/초, 모든 GGUF'는 WebSearch 교차확인과 어긋난다)

> 출처: GeekNews 토픽 [id=35496](https://news.hada.io/topic?id=35496) (원문 외부 링크 이번 세션에서 미확인) · Slack `#개발-뉴스-dev-news` 경유 · 정리일 2026-10-17

> **출처 한계를 분명히 밝힌다.** `news.hada.io` 전면 차단으로 원문을 열지 못했다. WebSearch로 PS5LM 프로젝트 자체(aiindigo.com 툴 목록, GitHub 추정 구조)는 확인했고, "relapse 브라우저 익스플로잇(펌웨어 7.00~13.60)으로 llama-server를 구동한다", "OpenAI 호환 API를 제공한다"는 Slack 요약의 핵심은 WebSearch와 일치한다. **다만 성능 수치는 어긋난다** — WebSearch로 찾은 자료는 "Qwen3.5 0.8B에서 13~21토큰/초, 2B에서 약 9토큰/초, 모델 용량 제한 1.6GB"라고 하는데, 이번 Slack 요약은 "PS5 Slim에서 Qwen 3.5 9B의 Q4_K_M 모델이 초당 55토큰"이라고 전한다 — **9B 모델이 0.8B보다 몇 배 더 빠르다는 것은 상식적으로 성립하지 않고, 1.6GB 제한과도 맞지 않는다.** 이 모순을 해소하지 못한 채, 두 수치를 그대로 나란히 적어 독자가 판단하게 한다.

## 한 줄 요약

**PS5LM은 탈옥한 PS5에 llama.cpp를 포팅해 Vulkan(RDNA 2) 백엔드로 GGUF 모델을 돌리고, OpenAI/Anthropic 호환 API와 브라우저 채팅까지 제공해 "콘솔을 가정용 AI 모델 서버로" 만드는 오픈소스 프로젝트다 — 다만 구체적인 성능 수치는 출처마다 크게 엇갈려, 이 노트 수준에서는 확정하지 못한다.**

## 핵심 포인트

- ***탈옥(jailbreak) 기반 구동*** — `relapse` 브라우저 익스플로잇(지원 펌웨어 7.00~13.60)으로 페이로드 로더를 올리고, 오픈소스 SDK `ps5-payload-dev`로 빌드한 `llama-server`를 띄우는 구조다(WebSearch로 확인). 정식 펌웨어 업데이트가 이 익스플로잇을 막으면 더 이상 동작하지 않게 될, 시한부 성격의 해킹이다.
- ***OpenAI/Anthropic 호환 API + 브라우저 채팅*** — Claude Code 같은 도구가 붙을 수 있는 OpenAI 호환 API를 제공하고, PS5 자체 브라우저에서 채팅 UI로 접근할 수 있다. 다만 WebSearch는 "Claude Code가 기대하는 Anthropic 호환 API와 PS5LM이 실제로 제공하는 OpenAI 호환 API 사이에 번역 계층이 필요할 수 있다"고 지적해, Slack 요약의 "Claude Code와 연결 가능"이 매끄러운 연동을 뜻하는지는 불확실하다.
- ***Vulkan 백엔드로 RDNA 2 GPU 활용*** — llama.cpp의 Vulkan 백엔드를 PS5의 RDNA 2 GPU에 연결해, 모델과 컨텍스트에 공유 메모리 11.4GB까지 쓸 수 있다는 것이 Slack 요약의 주장이다. WebSearch에서는 "Homebrew가 16코어 중 5개, 메모리 약 6GB를 쓰고 모델 용량 제한이 1.6GB"라는 다른 숫자가 나와, 11.4GB와 1.6GB 중 어느 쪽이 최신/정확한 제약인지 확정하지 못했다.
- ***성능 수치의 근본적 불일치 (정직하게 기록)*** — Slack: "PS5 Slim, Qwen 3.5 9B Q4_K_M, 55토큰/초". WebSearch: "Qwen3.5 0.8B 13~21토큰/초, 2B 약 9토큰/초". 9B 모델이 0.8B보다 압도적으로 빠르다는 것은 동일 하드웨어에서 성립할 수 없다 — 둘 중 하나가 오기이거나, 서로 다른 버전/최적화 단계의 PS5LM을 가리키거나, Slack 요약이 다른 프로젝트·다른 기기의 수치를 혼동했을 가능성이 있다. 이 노트는 어느 쪽이 맞는지 판정하지 않고 모순 자체를 기록한다.
- ***라이선스와 적용 범위*** — GPL-3.0, 자신이 소유한 PS5(펌웨어 13.60 이하)에서만 동작. 지원 모델 범위는 llama.cpp가 지원하는 아키텍처·양자화 형식을 그대로 따른다.

## 내 생각 · 적용점

이 글은 레포의 [[2026-09-17-ps5-linux-theflow-quits-llm-vibe-coding]](PS5 Linux 홈브루 개발자 theflow가 LLM 바이브 코딩에 질려 그만뒀다는 글)과 같은 "PS5 홈브루 + LLM" 생태계를 다루지만 톤이 대조적이다 — 한쪽은 개발자가 LLM 코딩 도구에 지쳐 떠난 이야기, 이쪽은 PS5 자체를 LLM 서버로 바꾸는 이야기로, 같은 커뮤니티 안에서 "AI를 향한" 방향과 "AI로 만든" 방향이 공존한다는 대조가 흥미�다. 더 일반적인 교훈은 ***"극적인 성능 수치는 같은 글 안에서도 내부 일관성을 먼저 체크해야 한다"***는 것 — 9B가 0.8B보다 빠르다는 건 한 번만 비교해봐도 드러나는 모순인데, 이런 수치가 교차검증 없이 그대로 퍼지는 걸 보면 "소스가 흥미로우면 수치를 덜 의심하게 되는" 흔한 함정을 보여준다.

## 호스피탈리티 / CRS 적용 포인트

CRS에 **직접** 적용은 없다 — 탈옥 콘솔을 모델 서버로 쓸 일은 없다. 다만 전이 가능한 교훈은 명확하다: ***"벤더/파트너가 제공하는 성능 수치를 받아들일 때, 그 수치가 같은 문서 안의 다른 수치와 내부적으로 일관적인지 먼저 확인한다"***는 검증 습관이다. 예를 들어 OTA 연동 파트너가 "처리량이 2배 늘었다"고 보고할 때, 그게 동시에 "평균 응답시간이 줄었다"는 다른 보고와 양립 가능한지를 교차 확인하는 식으로 적용할 수 있다.
