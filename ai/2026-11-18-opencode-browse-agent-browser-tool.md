## 한 줄 요약

**Chromium 확장 + MCP 서버로 에이전트가 평소 쓰던 브라우저의 로그인 상태를 그대로 빌려 쓰고, 사용자 작업이 필요한 순간엔 탭을 사람에게 넘기는 "위임-회수" 구조다.**

## 핵심 포인트

- **로그인 상태 재사용** — Chromium 확장 프로그램과 MCP 서버를 연결해, 에이전트가 ***평소 쓰던 브라우저의 로그인 상태와 확장 프로그램을 그대로 이용***한다. 별도 세션·헤드리스 브라우저 로그인 과정이 필요 없다.
- **읽기·조작·캡처 삼종** — 페이지 읽기, 클릭, 입력을 수행하고 스크린샷·탭 녹화·네트워크 트래픽 캡처가 가능해, 디버깅·테스트 재현에도 쓸 수 있는 범위다.
- **사람에게 넘기는 명시적 핸드오프** — 로그인·2FA·결제처럼 ***사용자 작업이 필요한 단계에서는 탭을 사용자에게 넘기고***, 사용자가 `Continue`를 클릭해야 에이전트가 이어간다. 민감 작업에 대한 동의 경계를 UI로 강제한다.
- **탭 그룹 격리** — 에이전트가 연 탭은 백그라운드 탭 그룹에 모이고, 사용자가 이미 열어 둔 탭도 툴바 버튼으로 넘기고 되돌릴 수 있다 — 에이전트 작업 공간과 사용자 작업 공간을 시각적으로 분리한다.

## 내 생각 · 적용점

### 핵심 전이 1 — "빌려 쓰고 돌려주기"는 BrowserSkill과 동일한 신뢰 경계 설계다

[[2026-09-28-browserskill-logged-in-browser-agent]]가 다룬 Tencent BrowserSkill은 "로그인된 실제 브라우저의 탭을 빌려 쓰고 작업 후 원래 창으로 반환, 차용 시 기본 확인요청"이라는 동일한 패턴을 썼다. OpenCode Browse는 여기에 "탭 그룹으로 공간을 분리"하는 UI적 장치를 더했다 — 같은 문제(에이전트에게 사용자 권한을 빌려주되 신뢰 경계는 유지)를 둘러싼 설계가 수렴하고 있다는 뜻이다.

### 핵심 전이 2 — "Continue 버튼"은 비가역 액션 앞의 체크포인트 패턴이다

로그인·2FA·결제 앞에서 멈추고 사람에게 넘기는 방식은, 이 레포가 반복해서 강조해 온 "되돌릴 수 없는 액션 앞에서는 에이전트가 자율성을 내려놓아야 한다"는 원칙의 구체적 구현이다.

## 호스피탈리티 / CRS 적용 포인트

**적용 가능성 있음(제한적).** OTA·파트너 포털에서 재고·요금을 조회하는 읽기 작업은 에이전트에게 맡기고, 예약 확정·결제·취소 같은 비가역 액션 앞에서는 OpenCode Browse의 "탭 핸드오프 + Continue" 패턴처럼 사람에게 명시적으로 통제권을 넘기는 UX를 CRS 운영 콘솔에도 적용할 수 있다. 다만 이 도구 자체를 그대로 도입하는 건 아니고, 그 "핸드오프 지점 설계" 원칙만 가져올 만하다.
