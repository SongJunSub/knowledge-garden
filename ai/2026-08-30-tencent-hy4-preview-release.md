# Hy4 프리뷰 공개 (Tencent Hunyuan)

## 한 줄 요약

**Tencent가 차세대 플래그십 Hy4의 프리뷰를 가중치 통째로(Apache 2.0) 공개했다. 770B 총 파라미터 중 토큰당 49B만 활성화하는 MoE로, 사내 163명 전문가가 203개 실무 엔지니어링 과제를 블라인드 평가한 결과 Hy4가 평균 2.99/4.00으로 GLM-5.3(2.92)·Kimi K3(2.94)를 근소하게 앞섰다고 주장한다. 그런데 GLM-5.3 대비 승률 46.8%·무승부 12.8%·패배 40.4%, Kimi K3 대비 승률 51.2%·무승부 7.9%·패배 40.9%라는 원자료를 보면 "근소 우위"라기보다 사실상 삼파전 동률에 가깝고, 평가를 설계·집행한 게 Tencent 자신이라는 점도 감안해야 한다.**

## 핵심 포인트

- **스펙 — 770B 총합 / 49B 활성 MoE** — 78개 레이어 중 첫 레이어만 표준 dense FFN, 나머지 77개 레이어가 MoE로 각각 ***"256개의 라우팅 전문가와 1개의 공유 전문가"***를 두고 토큰마다 상위 8개 라우팅 전문가 + 공유 전문가를 활성화한다. hidden size 6,144, attention head 64개, **Gated DeepSeek Sparse Attention** 아키텍처 채용. 컨텍스트는 100만 토큰.
- **평가 방법 — 163명 전문가·203개 과제 블라인드 평가** — Hy4 preview 2.99/4.00, GLM-5.3 2.92/4.00, Kimi K3 2.94/4.00. 다만 **GLM-5.3 대비 승-무-패 46.8%-12.8%-40.4%, Kimi K3 대비 51.2%-7.9%-40.9%**라는 세부 수치는 평균 점수 차이가 시사하는 것보다 훨씬 팽팽한 삼파전임을 보여준다. Code Arena WebDev(AutoEval)에서는 ~1633점으로 전체 ~5위, 오픈모델 중 ~3위(전작 Hy3는 전체 31위·오픈 7위) — 이건 사후 집계형 벤치마크라 상대적으로 독립적이다.
- **라이선스·배포 — Apache 2.0, vLLM/SGLang 권장** — OpenAI 호환 API로 배포, 권장 파라미터 `temperature=0.9, top_p=1.0`. Tencent Cloud TokenHub·OpenRouter로 API 접근 가능(입력 $0.834/M, 출력 $2.501/M로 보도), WorkBuddy·CodeBuddy에서 2주간 무료 제공, Yuanbao·ima 등 자사 제품에도 통합.
- **정직한 자기 고백 — "불필요하게 오래 생각한다"** — README가 스스로 밝힌 한계: ***"조기 버전으로 복잡한 작업에 불필요하게 오래 소요되는 경향"***이 있다고 명시했다. 벤치마크 우위를 자랑하는 발표문에 이례적으로 미세조정 전 프리뷰의 약점을 직접 적었다는 점은 짚어둘 만하다.
- **타깃 — 코딩·오피스·게임 개발·과학 연구** — 장문맥이 필요한 코드 이해·디버깅·검증, 문서/스프레드시트/프레젠테이션 오피스 워크플로, 자연어에서 게임 엔진 프로토타입 생성까지를 실사용 시나리오로 제시.

## 내 생각 · 적용점

### 핵심 전이 1 — "자체 벤치마크로 근소 우위 주장"이 이번 시즌 중국 오픈웨이트 릴리스의 공통 패턴이 됐다

이틀 전 [[2026-08-29-glm-5-3-open-weights-release]]도 Z.ai Code Bench·Terminal Bench 같은 자체·준자체 지표로 "오픈웨이트 최고"를 주장했고, 이번 Hy4도 자체 블라인드 평가로 GLM-5.3·Kimi K3를 근소하게 앞섰다고 주장한다. 두 릴리스를 나란히 놓으면 재미있는 순환 구조가 보인다 — Hy4는 GLM-5.3을 근소하게 이겼다고 주장하는데, 그 GLM-5.3도 같은 방식(자체 지표)으로 자신의 우위를 주장했었다. **누구 벤치마크를 기준으로 삼든 "우리가 근소 우위"라는 결론이 나온다는 것 자체가, 이 세대 오픈웨이트 MoE 플래그십들이 실제로 성능 오차범위 안에 몰려 있다는 방증**에 가깝다. 규모도 비슷하다 — GLM-5.3 744B-A40B, Hy4 770B-A49B로 총합·활성 파라미터 모두 같은 자릿수.

### 핵심 전이 2 — Kimi K3가 이번에도 비교 기준점으로 등장한다: [[2026-07-20-the-kimi-k3-moment]]의 "패리티 서사"가 세 번째 재현

7월에 정리한 그 노트의 핵심은 "일상 코딩에서 Kimi K3와 Claude 최상위 모델이 구별 안 될 만큼 가깝다"는 1인칭 체험이었다. 이번엔 Tencent 자신이 "Hy4가 Kimi K3와 승-무-패 51.2%-7.9%-40.9%로 사실상 동률"이라고 공식 발표에 적었다 — **오픈웨이트 진영 내부에서도 서로가 서로를 "패리티" 기준점으로 인용하는 단계**에 들어섰다는 뜻이다. 다만 그 노트의 핵심 전이 2("그냥 갈아타면 된다는 건 하필 패리티가 성립하는 쉬운 영역에서만 참")가 여기도 그대로 적용된다 — 203개 "엔지니어링 과제"라는 범위가 어떤 난이도대인지 이 노트에서 확인 못했다.

### 핵심 전이 3 — [[2026-08-03-us-open-model-paradox]]가 짚은 "미국은 닫고 중국은 연다" 구도에 또 하나의 데이터 포인트

그 노트는 Qwen의 오픈모델 미세조정 점유율이 2024년 1월 1%에서 2026년 2월 69%로 뛰었다는 수치로 "오픈 계층에서는 중국 의존도가 커진다"는 역설을 다뤘다. Hy4(Tencent)·GLM-5.3(Z.ai)·Kimi K3(Moonshot)·Qwen(Alibaba)까지 겹쳐 놓으면, 중국 4대 랩이 거의 동시에 최상위급 가중치를 Apache/MIT류 라이선스로 계속 풀고 있다는 흐름이 뚜렷해진다. 다만 와우테일 등 국내 매체가 이 릴리스를 정확히 그 프레임("미국은 닫고 중국은 연다")으로 보도했다는 점은, **이게 이제 개별 모델 뉴스가 아니라 반복되는 지정학적 서사의 소재로 소비되고 있다**는 뜻이기도 하다 — 서사가 굳어질수록 개별 릴리스의 실제 성능 차이는 덜 중요해지고 "또 나왔다"는 빈도 자체가 메시지가 된다.

## 호스피탈리티 / CRS 적용 포인트

- **직접 도입 판단은 멀다.** 770B-A49B는 [[2026-08-13-qwen38-2-4t-a95b-open-weights]]에서 세운 규칙("오픈웨이트≠로컬 실행 가능")대로 자가호스팅 문턱이 매우 높은 계열이다 — BF16 기준 수 테라바이트급 서빙 인프라가 필요해 온다 규모에서 검토할 대상이 아니다.
- **API 경로(Tencent Cloud TokenHub·OpenRouter)로 접근한다면 [[2026-07-20-the-kimi-k3-moment]]의 전이 3("모델 선택 순서: 단가가 마지막")이 그대로 적용된다** — 중국계 API를 예약·결제 데이터 경로에 쓰려면 데이터 학습 활용 정책부터 확인해야 하고, 코드 보조 같은 민감정보 없는 경로와는 분리해서 판단해야 한다.
- **오픈소스로서의 참고 가치**: 무료화 프로모션(WorkBuddy·CodeBuddy 2주)으로 실사용 데이터가 빠르게 쌓일 텐데, 그 실사용 리뷰가 독립적 성능 검증에 가장 가까운 신호가 될 것이다. 지금은 그 단계가 아니다.
