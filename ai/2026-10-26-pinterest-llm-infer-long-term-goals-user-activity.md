# Pinterest, 사용자 활동에서 장기 목표를 추론하는 LLM 구축

> 출처: [Identify User Journeys at Pinterest](https://medium.com/pinterest-engineering/identify-user-journeys-at-pinterest-b517f6275b42) (Pinterest Engineering, Medium) · GeekNews(id=36011) 경유 · 정리일 2026-10-26
>
> **출처 한계**: `news.hada.io`와 `medium.com` 둘 다 이번 세션에서 DNS 실패로 접근 불가해 원문을 직접 열지 못했다. Slack 발췌(Qwen3 4B, L40S GPU 약 100개, 초당 약 775건이라는 구체적 수치 포함)를 뼈대로, Pinterest 커뮤니티 포럼 공지(원문의 존재와 "4B 파라미터 미세조정 LLM"이라는 표현을 재확인)와 ZenML LLMOps 데이터베이스의 요약(이메일 클릭률 +88%·푸시 오픈율 +32%·긍정 피드백 +23%라는 성과 지표)으로 교차확인했다. 다만 **이 성과 지표는 Pinterest 원문을 제3자가 요약한 것을 재인용**한 것이라 정확한 비교 기준(어떤 기간·세그먼트 대비인지)은 확인하지 못했고, Qwen3 4B라는 베이스 모델명·GPU 수·처리량 수치는 Slack 발췌 외에 독립적으로 재확인하지 못했다.

## 한 줄 요약

**Pinterest는 사용자의 검색·저장 기록을 읽고 '주방 리모델링'이나 '사워도우 배우기'처럼 사용자가 이루려는 목표("journey")를 추론해 추천과 알림에 활용한다.** 키워드 추출 후 묶어 이름 붙이던 다단계 파이프라인을, 활동 기록에서 목표 목록과 우선순위를 직접 생성하는 미세조정 LLM 하나로 대체했고, 대형 모델이 만든 학습 데이터로 Qwen3 4B를 학습시켜 비용을 줄였다.

## 핵심 포인트

- **"journey"의 정의** — 특정 시점에서 사용자의 관심사·의도·맥락이 교차하는 지점을 가리키며, ***여러 세션에 걸쳐 이어지는 목표***(결혼 준비, 집 리모델링, 새 기술 배우기 등)를 뜻한다. 한 번의 검색이 아니라 시간을 두고 이어지는 활동 패턴을 하나의 단위로 묶는 게 핵심이다.
- **파이프라인 전환 — 다단계 클러스터링에서 LLM 하나로** — 기존에는 ***키워드를 추출한 뒤 묶어서 이름을 붙이는*** 여러 단계의 처리였다면, 새 방식은 ***미세조정한 LLM 하나가 활동 기록에서 목표 목록과 우선순위를 직접 생성***한다. 분리된 여러 모델·단계를 하나의 생성형 모델로 합친 셈이다.
- **비용을 줄이는 증류 전략** — 대형 모델이 만든 학습 데이터를 ***Qwen3 4B***에 학습시켜, 추론 비용이 큰 대형 모델 대신 작은 모델로 서비스를 돌린다. 품질은 대형 모델 수준에 최대한 가깝게, 비용은 소형 모델 수준으로 낮추는 전형적인 distillation 패턴.
- **따로 분리됐던 관심사를 하나의 목표로 묶는다** — 과거 방식에서는 별개 키워드·카테고리로 흩어졌을 활동들을, LLM이 ***사용자 언어로 구체적인 이름을 생성***해 하나의 "journey"로 재구성한다. 예: 여러 날에 걸친 타일·조명·수납 검색을 "주방 리모델링"이라는 하나의 목표로 합친다.
- **인프라 규모** — ***L40S GPU 약 100개로 초당 약 775건을 처리***한다는 수치가 Slack 발췌에 있다. 다단계 파이프라인을 단일 모델 추론으로 바꾸면서도 이 정도 처리량을 내려면 소형 모델 선택과 서빙 최적화가 맞물려야 한다는 뜻으로 읽힌다(구체적 서빙 스택·배치 전략은 원문 미확보로 확인 못함).
- **활용처** — 추천과 알림(이메일·푸시) 두 곳에 쓰인다. ZenML 요약에 따르면 journey 기반 알림이 관심사 기반 알림 대비 ***이메일 클릭률 88% 상승·푸시 오픈율 32% 상승·긍정 피드백 23% 상승***을 냈다고 한다(제3자 재인용, 원문 수치 직접 대조는 못함).

## 인상 깊은 문장

> "여러 세션에 걸쳐 이어지는 사용자의 의도를 하나의 '여정'으로 묶는다" — Pinterest 커뮤니티 포럼이 소개하는 journey 개념의 핵심이다. 단일 쿼리·단일 세션 단위로 사용자를 모델링하던 기존 추천시스템의 틀을 넘어, **시간에 걸친 목표**를 1급 단위로 다룬다는 점이 특징이다.

## 댓글

GeekNews hada 댓글 수와 HN/Lobsters 큐레이션 여부는 원문 접근 불가로 확인하지 못했다. Pinterest 자사 블로그라 성과 지표(클릭률·오픈율 상승)는 벤더가 직접 고른 수치라는 점, 그리고 그 수치 자체도 원문이 아니라 ZenML의 재인용이라는 이중의 출처 한계를 밝혀둔다.

## 내 생각 · 적용점

**핵심 전이 1 — [[2026-09-23-kakao-personalization-ranking-model]]와의 연결.** 카카오의 랭킹 모델 개발기는 "세그먼트 기반의 한계를 유저 히스토리로 넘는다"는 문제의식이었는데, Pinterest의 journey도 같은 방향이다 — 다만 카카오는 랭킹(정렬) 문제로 풀었고 Pinterest는 생성(목표 이름·목록을 직접 써내는) 문제로 풀었다는 접근의 차이가 있다. 유저 히스토리를 "분류"가 아니라 "서술"로 다루는 쪽이 더 유연한 표현력을 준다는 가설을 세워볼 만하다.

**핵심 전이 2 — [[2026-09-01-musinsa-unified-embedding-push-ctr]]와의 연결.** 무신사가 통합 임베딩으로 모델마다 따로 학습하던 유저 이해를 하나의 공유 자산으로 합쳐 푸시 CTR을 올렸다는 구조와, Pinterest가 다단계 파이프라인을 LLM 하나로 합쳐 알림 성과를 올렸다는 구조가 같은 패턴이다 — ***"유저 이해를 여러 모델에 흩어두지 않고 하나로 합치면 알림 성과가 오른다"***는 명제가 서로 다른 회사·다른 기술(임베딩 대 생성형 LLM)에서 반복 확인되는 셈이다.

**핵심 전이 3 — [[2026-09-14-garry-tan-open-weight-distillation]]와의 연결.** 그 노트는 "프론티어 모델 증류를 정책적으로 허용해야 한다"는 미국 내 논쟁을 다뤘는데, Pinterest의 사례는 그 증류가 실무에서 이미 일상적으로 쓰이고 있다는 걸 보여주는 구체적 적용 사례다 — 정책 논쟁의 추상적 쟁점과, 실제 서비스가 비용을 줄이는 방식으로 증류를 쓰는 현실이 맞물린다.

## 호스피탈리티 / CRS 적용 포인트

온다(B2B 호스피탈리티/CRS)에 직접 적용하긴 멀다 — Pinterest의 journey는 B2C 콘텐츠 플랫폼의 탐색·저장 기록을 다루는 문제라, 호텔 예약·재고 관리라는 B2B 도메인과는 데이터 성격이 다르다. 다만 전이 가능한 원칙은 있다: **투숙객이나 파트너 호텔의 "여러 세션에 걸친 의도"(예: 특정 기간 반복적으로 비슷한 날짜·지역을 조회하는 패턴)를 단일 쿼리 단위가 아니라 누적된 목표로 묶어 보는 관점**은, 예약 전환이나 맞춤 추천을 설계할 때 참고할 만한 프레임이다. 다만 Pinterest 규모의 journey 추론 LLM을 바로 들여오는 건 과한 투자일 가능성이 크다.
