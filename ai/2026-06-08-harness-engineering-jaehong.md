# 하네스 엔지니어링 (박재홍 종합) — 'Agent = Model + Harness', 경쟁력은 모델이 아니라 '마구'·환경 설계에서 나온다 (AI 도구 설계 라인)

> 출처: [하네스 엔지니어링: AI 에이전트 시대, 경쟁력은 모델이 아니라 '마구'에서 나온다](https://wikidocs.net/blog/@jaehong/9481/) (박재홍의 실리콘밸리, wikidocs) · 정리일 2026-06-08

## 한 줄 요약

**AI 에이전트의 성능을 좌우하는 건 *모델의 지능*이 아니라 ***그 지능을 감싸는 시스템 설계 = 하네스(harness, 馬具)***라는 종합 글. 공식: ***"Agent = Model + Harness"*** (LangChain Vivek Trivedy) — *모델이 아닌 모든 것(시스템 프롬프트·도구 정의·샌드박스·오케스트레이션·피드백 루프·메모리·훅)이 하네스*. 증거: *OpenAI Codex 팀이 3명·5개월·**수작업 코드 0줄**로 100만 줄 프로덕션 앱(PR 1,500개, 수작업 대비 1/10 시간)*, *LangChain이 모델 그대로 두고 하네스만 고쳐 Terminal Bench 2.0에서 30위권→5위권(52.8→66.5)*. 개념 명명자 *Mitchell Hashimoto: "에이전트가 실수할 때마다, 그 실수가 다시는 발생하지 않도록 엔지니어링하는 것"*(Ghostty AGENTS.md). 결론: 엔지니어의 일이 ***"코드를 작성하는 것"에서 "AI가 코드를 올바르게 작성할 수 있는 환경을 설계하는 것"***으로 이동(Chad Fowler "엄밀함의 재배치"). 처방: ***"모델을 탓하기 전에 하네스를 점검하라 — 모델은 아마 괜찮다, 하네스의 문제일 뿐이다(HumanLayer)."*****

## 핵심 포인트

- **왜 모델만으론 부족한가** — LLM은 *텍스트→텍스트 함수*. 혼자선 *상태 유지·코드 실행·실시간 정보·환경 구성*을 못 함. *"채팅"조차 하네스의 산물(while 루프)*. Anthropic이 Opus 4.5에 "claude.ai 클론 만들어" 시켰을 때 두 실패: ①*다 한 번에 하려다 컨텍스트 고갈→절반만 구현* ②*"다 됐네" 조기 종료*. **비유: 인수인계·진행보드·테스트환경 없이 매번 교대하는 엔지니어** — 아무리 뛰어나도 일 못 함.
- **하네스 5대 축** — ①**파일시스템·지속 저장소**(Anthropic `claude-progress.txt`+Git 로그로 세션 간 핸드오프) ②**코드 실행·샌드박스**(bash=범용 도구, 격리 실행) ③**컨텍스트 관리·부패 방지** ④**서브 에이전트·컨텍스트 격리** ⑤**훅·백프레셔**.
- **컨텍스트 부패(Context Rot)가 핵심 전장** — *Chroma 연구: 컨텍스트가 길수록 추론 능력 하락(질문-정보 의미 유사도 낮을수록 더 가파름)*. 대응: *컴팩션·도구 출력 오프로딩·**Skills(점진적 노출)***. HumanLayer 교훈: *전체 테스트 4,000줄 통과결과가 컨텍스트 범람* → ***"성공은 조용히, 실패만 시끄럽게"*** 한 줄로 극적 개선. [[2026-06-08-dont-trust-large-context-windows]]·[[2026-06-08-anthropic-skills-building-guide]] *점진적 공개*와 직결.
- **서브 에이전트 = "컨텍스트 방화벽"** — *역할 분담("프론트/백엔드")용으로는 잘 안 됨(HumanLayer)*. 진짜 가치는 *조사·탐색의 노이즈를 흡수하고 상위엔 최종 결과만 전달*. 비용 통제도: *상위=Opus, 하위=Sonnet/Haiku*. ***"큰 컨텍스트 윈도우는 더 큰 건초더미일 뿐 — 필요한 건 더 긴 컨텍스트가 아니라 더 나은 컨텍스트 격리."***
- **훅·백프레셔 = 가장 레버리지 높은 투자** — *훅(작업 끝마다 타입체크·포매터 자동, 에러면 되돌림)*, *백프레셔(에이전트가 자기 작업을 스스로 검증: 테스트·커버리지·브라우저 E2E)*. HumanLayer 단언: ***"작업 성공 확률은 자기 검증 능력과 강하게 상관."*** Anthropic도 *Puppeteer로 실제 사용자처럼 테스트시키니 코드만으론 못 찾던 버그를 직접 수정*. [[2026-06-08-agentic-code-review]]·[[2026-06-08-ai-demands-more-engineering-discipline]]와 정합.
- **실전 원칙 4** — ①***실패에서 시작하라*** (이상적 하네스 미리 설계 X, "출하 편향: 실제 실패 때만 하네스 건드려라") ②***적게 넣어라*** (ETH Zurich: 138개 설정파일 중 *LLM 생성은 성능↓+비용 20%↑, 사람 작성도 4%만 개선*; 코드베이스 개요·디렉터리 목록은 무용 — 에이전트가 알아서 탐색) ③***도구 과연결 금지*** (MCP 많을수록 "인스트럭션 예산" 잠식 → HumanLayer는 Linear MCP 대신 경량 CLI; *훈련데이터에 있는 도구(GitHub/Docker/DB)는 CLI 프롬프트가 나음* — [[2026-05-29-mcp-is-dead-cli-skills]]) ④***점진적 작업 강제*** (한 번에 한 기능 + 끝나면 Git 커밋·진행노트).
- **모델·하네스 공진화의 역설** — *모델은 자기 하네스에서 후훈련(Claude=Claude Code, Codex=Codex)* → 특정 하네스에 *과적합*(Codex의 `apply_patch` 결합). 역설: *Opus 4.6이 Claude Code에선 33위, 다른 하네스에선 5위*. **→ "기본 하네스가 최선이 아닐 수 있다. 작업 특성에 맞게 커스터마이징하면 의미 있는 향상."**
- **미래: 하네스 = 새 골든패스 + 기술 선택 기준이 "AI 친화성"으로** — *애플리케이션 유형별 하네스 템플릿*(Böckeler), *"개발자 경험 좋은 프레임워크"가 아니라 "좋은 하네스 갖춘 프레임워크"가 선택 기준*. 레거시 vs 에이전트-네이티브 코드베이스 격차. LangChain 미래: *수백 에이전트 병렬·자기 개선 루프·적응형 하네스*.

## 내 생각 · 적용점

### AI 도구 설계 라인 (친/axelk 축과 직교, 카운팅 무관)

*AI 능력 찬반*이 아니라 ***"레버리지가 모델이 아니라 하네스(환경 설계)에서 나온다"***는 도구 설계 철학. 바로 앞 [[2026-06-08-anthropic-skills-building-guide]](Skills=하네스의 한 부품)·[[2026-04-28-agent-harness-engineering]](같은 주제 선행글)의 **상위 종합**. 라인 자산(카운팅 무관). 부채 *−2 유지* (53:43 ≈ 1.24:1).

### 핵심 전이 1 — "실패에서 시작하라 + 적게 넣어라"가 CLAUDE.md/AGENTS.md 운영 원칙

가장 즉시 적용되는 통찰: ***이상적 하네스를 미리 설계하지 말고, 에이전트가 실제로 실패할 때만 그 재발을 구조적으로 막아라(출하 편향)*** + ***보편 최소 지침만(ETH Zurich: 과한 설정은 성능↓·비용↑)***. 내 CLAUDE.md·이 가든의 운영 의례가 정확히 이 패턴 — *반복된 실수(표지 날짜 누락, 메모리 wikilink, 커밋 author)마다 규칙 한 줄씩 누적*. **"다음부터 잘해"(프롬프트)가 아니라 구조적 재발 방지(훅·스크립트·체크리스트)** — [[2026-06-08-anthropic-skills-building-guide]] *"검증은 결정적 코드로"*와 같은 결. 단 *코드베이스 개요·디렉터리 목록 같은 무용 지침은 빼라*는 게 핵심(적게).

### 핵심 전이 2 — 백프레셔(자기 검증)가 최고 레버리지 + 컨텍스트 격리

***"성공 확률은 자기 검증 능력과 강하게 상관"*** → 내 작업에 직접: *에이전트에게 "잘 해"가 아니라 타입체크·테스트·E2E·린터를 훅으로 박아 스스로 검증하게*. 그리고 ***"성공은 조용히, 실패만 시끄럽게"*** 는 로그/출력 설계 원칙 그 자체 — 마침 직전 정리한 [[2026-06-08-kakaopay-clickstack-log-platform]] *"필요한 신호만 남기는 컨텍스트 절제"*와 같은 줄기. *서브 에이전트=컨텍스트 방화벽(노이즈 흡수+저렴한 모델)* 은 내가 무거운 탐색(grep 스윕·로그 정리)을 서브에이전트로 빼는 위임 패턴의 근거.

### 핵심 전이 3 — MangoLove = "하네스 엔지니어링의 일반화"이자 정체성 선언

이 글은 내가 만드는 **MangoLove(방법론 주입 CLI)** 의 *존재 이유를 가장 또렷이 설명한 1차 종합*이다 — ***Agent = Model + Harness*** 에서 MangoLove는 *Harness 레이어(방법론·제약·피드백 루프)를 일반화한 제품*. [[2026-06-08-anthropic-skills-building-guide]] Skills가 "하네스의 한 부품(점진적 노출)"이라면, MangoLove는 *그 부품들(시스템 프롬프트·도구 선택·검증 루프·점진적 작업 강제)을 방법론으로 묶어 주입*. 설계 체크리스트로 그대로 전이: ***실패에서 시작·적게 넣기·도구 과연결 금지·백프레셔 내장·점진적 작업 강제·하네스 커스터마이징(기본값 과적합 회피)***. 그리고 미래 통찰 *"기술 선택 기준이 AI 친화성(좋은 하네스)으로"* 는 MangoLove의 포지셔닝 근거.
