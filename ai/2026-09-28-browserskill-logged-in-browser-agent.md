# BrowserSkill (Tencent) — 로그인된 내 브라우저를 AI 에이전트가 빌려 쓰고 되돌려주는 도구

## 한 줄 요약

**Tencent가 공개한 CLI와 브라우저 확장 프로그램 BrowserSkill은, 이미 로그인된 사용자의 Chrome·Edge에서 별도 "Agent Window"를 열어 AI 에이전트가 기존 로그인 세션 그대로 작업(문서 읽기·양식 작성·웹 탐색)을 수행하게 하고, 작업이 끝나면 빌려 쓴 탭을 원래 창으로 되돌려준다 — 별도 자동화 브라우저에 다시 로그인할 필요가 없다는 게 핵심이다.**

## 핵심 포인트

- **문제의식 — "빈 브라우저"가 아니라 "내 브라우저"** — 기존 브라우저 자동화 도구 대부분이 에이전트에게 빈 자동화 브라우저를 주고 처음부터 로그인시키는 반면, BrowserSkill은 ***사용자가 이미 로그인해 쿠키가 살아 있는 실제 브라우저의 탭을 빌려 쓴다***는 데서 출발한다.
- **3층 아키텍처** — 에이전트가 셸에서 호출하는 ***`bsk` CLI***, 프로세스 간 메시징을 처리하는 ***로컬 데몬***, 실제 자동화를 수행하는 ***브라우저 확장*** 세 층으로 구성된다. 에이전트는 브라우저와 직접 통신하지 않고, 요청이 CLI → 데몬 → 확장을 거쳐 localhost 웹소켓으로 전달된다.
- **별도 창에서 작업, 사용자는 방해받지 않음** — 에이전트는 ***"Agent Window"라는 별도 창***에서 작업하므로, 사용자는 다른 창에서 하던 일을 그대로 계속할 수 있다.
- **기존 탭 차용 시 기본적으로 확인 요청** — 에이전트가 이미 열려 있는 탭을 가져와 쓸 때는 ***기본적으로 사용자 확인을 요청***하며, 작업이 끝나면 원래 창으로 반환한다. 이 자동화 설정은 브라우저 확장 설정에 있어 플래그로 우회할 수 없게 돼 있다.
- **폭넓은 에이전트 연동** — Claude Code, Codex, Cursor, OpenClaw, CodeBuddy, WorkBuddy, Pi, Hermes Agent 등 ***셸 명령을 실행할 수 있는 에이전트***와 연동한다. 모델·플랫폼은 사용자가 이미 쓰던 에이전트를 그대로 쓴다.
- **프라이버시·감사** — 필수 클라우드 서비스나 제품 텔레메트리가 없고, 웹사이트 디버깅용 증거는 브라우저 프로필에 저장돼 30일 후 만료된다. 작업 감사 로그는 선택적으로 `BSK_HOME/audit`에 남길 수 있다.
- **규모** — 이 세션 확인 시점 기준 ***GitHub 스타 7.7k, 포크 549개, 커밋 690개, MIT 라이선스***로 확산 속도가 빠른 편.

## 내 생각 · 적용점

### 핵심 전이 1 — 같은 "브라우저 에이전트" 계열이지만 정반대 설계 철학

[[2026-09-20-stagehand-v4-browser-automation]]의 Stagehand v4는 브라우저 확장을 **페이지 옆에서 프레임워크 로직을 실행해 지연을 줄이는 용도**로 쓴다 — 여전히 자동화용 브라우저 환경이 전제다. BrowserSkill은 확장을 **사용자의 실제 로그인 세션에 접근하는 통로**로 쓴다는 점에서 정반대 방향이다. 같은 "브라우저 확장 기반 에이전트 도구"라는 기술 형태를 공유하면서도, 하나는 "속도"를, 다른 하나는 "인증 재사용"을 목적으로 삼는다는 점에서 이 계열 도구가 갈라지는 두 축을 보여준다.

### 핵심 전이 2 — "에이전트에게 무엇을 보여줄 것인가"라는 같은 질문의 정반대 답

[[2026-08-26-key-amnesia-agent-secrets]]는 "에이전트가 시크릿을 쓰되 절대 보지 못하게" 프로세스 경계를 설계한 도구였다 — 위협 모델을 "내 프로젝트를 읽는 에이전트 자신"으로 재정의한 사례다. BrowserSkill은 정확히 반대 방향을 택한다 — 에이전트에게 **사용자의 실제 로그인 세션 전체를 보여주고 쓰게** 한다. 두 도구를 나란히 놓으면 "에이전트에게 자격 증명을 노출할 것인가"라는 같은 질문에 대해 업계가 아직 통일된 답을 찾지 못했다는 게 드러난다 — key-amnesia는 격리를, BrowserSkill은 확인 절차(컨펌 요청)와 감사 로그로 신뢰를 관리한다.

## 호스피탈리티 / CRS 적용 포인트

OTA·파트너 포털처럼 API가 없거나 부실하고 담당자가 이미 로그인해 쓰는 외부 시스템에서 데이터를 조회하거나 문서를 찾는 용도로 직접 적용 후보다. [[2026-09-20-stagehand-v4-browser-automation]] 노트에서 이미 짚은 "예약·요금처럼 되돌리기 어려운 액션은 자연어 명령이 실행하게 두지 않는다"는 원칙이 여기서는 더 중요해진다 — BrowserSkill은 실제 담당자의 로그인 세션을 그대로 쓰므로, 잘못된 액션이 실행되면 자동화 브라우저의 가짜 계정이 아니라 **실제 업무 계정**에서 벌어진다. 탭 차용 시 기본 확인 요청과 감사 로그 기능을 반드시 켠 채로, 읽기 전용 조회·문서 검색부터 검증하는 것이 안전하다.
