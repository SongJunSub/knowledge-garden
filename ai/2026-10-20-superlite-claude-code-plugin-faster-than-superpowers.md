## 핵심 포인트

- **Superpowers 대비 "반복 승인·순차 실행 축소"** — Claude Code의 개발 절차를 체계화하는 Superpowers를 바탕으로 하되, ***반복 승인과 순차 실행을 줄인*** 플러그인. 명세를 넘기면 계획부터 ***병렬 구현, 테스트와 리뷰***까지 진행한다고 주장.
- **승인 방식 선택 가능 + 결정 기록** — 사람이 계획을 한 번 승인하거나 AI가 스스로 결정하며 진행하는 방식을 ***선택 가능***하며, 결정한 내용과 이유를 기록한다. ***사용자 없이 푸시하거나 병합하지 않는다***는 안전장치를 명시.
- **작업 단위 분리 → 병렬 실행** — 작업별 파일·인터페이스·테스트를 미리 정해 ***독립적인 작업을 병렬 실행***한다. 이는 작업 간 의존성을 사전에 끊어야 병렬화가 가능하다는 뜻으로, 설계 단계의 비중이 커진다는 암시이기도 하다.
- **모델 역할 분담** — ***Opus는 조율과 최종 리뷰, Sonnet은 주된 구현, Haiku는 작고 명확한 작업***을 담당. 비용·속도·품질을 모델 티어별로 나눠 배분하는 구조.
- **조율자 권한 제한(발췌 끊김)** — "조율자의 코드 수정 금지와 테…"에서 발췌가 끊겨, 구체적으로 조율자(Opus)가 코드를 직접 수정하지 못하게 막는 규칙과 그 뒤의 테스트 관련 규율이 무엇인지는 확인 불가.

### 핵심 전이 1 — [[2026-09-26-ordewell-multi-agent-orchestrator]]와 같은 "작업 단위를 쪼개 병렬 실행" 패턴의 또 다른 변주

Ordewell은 "Paseo·Orca·Proliferate 삼파전"에 합류한 네 번째 멀티 러너 오케스트레이터로, 코딩 에이전트의 작업을 여러 러너에 분산하는 도구였다. Superlite가 "작업별 파일·인터페이스·테스트를 정해 독립적인 작업을 병렬 실행"한다는 것은 정확히 같은 패턴을 Claude Code 플러그인이라는 더 가벼운 형태로 구현한 것으로 읽힌다 — 2026년 하반기 코딩 에이전트 생태계에서 "병렬 작업 분배"가 거의 공통 설계 패턴으로 수렴하고 있다는 신호. Superlite가 독립 도구가 아니라 "Claude Code 플러그인"이라는 더 가벼운 레이어로 같은 문제를 푼다는 점이 차이.

### 핵심 전이 2 — [[2026-09-27-plan-mode-is-dead]]의 "계획은 행위, 계획서는 산출물" 구분이 이 플러그인의 "승인 방식 선택"에 그대로 적용된다

그 글은 계획하는 행위는 필수지만 계획서라는 산출물은 점점 불필요해진다고 주장했다. Superlite가 "사람이 계획을 한 번 승인하거나 AI가 스스로 결정"하는 선택지를 준다는 것은, 바로 그 구분을 제품화한 것으로 보인다 — 승인이 필요한 상황에서도 "계획 문서를 꼼꼼히 읽고 승인"이 아니라 "한 번의 가벼운 승인"으로 축소했다는 점에서, 계획이라는 행위 자체는 유지하되 그 산출물의 무게를 줄이는 방향과 맞아떨어진다.

### Claude 사용 관점에서 참고할 점

Opus(조율/리뷰)·Sonnet(구현)·Haiku(단순 작업)로 모델을 역할별로 나누는 구조는, 비용과 품질을 맞바꾸는 실전적인 패턴이다. "조율자의 코드 수정 금지"라는 규칙(발췌가 끊겨 뒷부분은 불확실하지만)은 [[2026-10-20-nhn-harness-series-2-silver-bullet-agent]]가 보여준 "팀용으로 확장할 때 권한 분리가 새로운 문제로 등장한다"는 패턴과도 닿아 있다 — 여러 에이전트/역할이 협업하는 구조에서는 "누가 무엇을 할 수 있는가"를 역할별로 명시적으로 제한하는 것이 반복적으로 나타나는 설계 원칙으로 보인다.

## 호스피탈리티 / CRS 적용 포인트

**부분적으로 적용 가능.** 온다 개발팀이 Claude Code로 여러 기능을 동시에 작업할 때, "작업별 파일·인터페이스·테스트를 먼저 정의해 독립적인 작업으로 쪼갠 뒤 병렬 실행"하는 패턴은 CRS처럼 모듈이 비교적 명확히 분리되는(예약 엔진, 요금 엔진, 연동 어댑터 등) 시스템에 바로 적용해볼 만하다. 다만 "사용자 없이 푸시·병합하지 않는다"는 안전장치는 이미 이 가든의 커밋 규칙(요약 1개 = 커밋 1개, 최종 push는 수동/자동 파이프라인 명시)과 같은 결의 원칙이라 특별히 새롭진 않다.
