# I-have-ADHD — 코딩 에이전트가 답을 묻어두지 않게 하는 스킬 (ayghri)

> 출처: [i-have-adhd: A skill to stop your coding agent from burying the answer](https://github.com/ayghri/i-have-adhd) (GitHub, ayghri) · GeekNews(id=33374) 경유 · 정리일 2026-09-09

> **출처 한계**: `news.hada.io`와 `news.ycombinator.com`이 이번 세션 egress 정책으로 차단돼 GeekNews 토픽 페이지와 해당 Hacker News 스레드(item id=49610631, 존재 자체는 WebSearch로 확인)를 직접 열람하지 못했다. GitHub 저장소의 `SKILL.md`는 WebFetch로 전문을 확보해 아래 규칙·예시는 원문 그대로다. HN/hada 댓글 수·논조, 정확한 최초 공개일은 확인하지 못했다.

## 한 줄 요약

**코딩 에이전트의 응답을 "서두-설명-결론" 산문 대신 "다음 행동부터, 번호 매긴 절차, 담담한 오류 보고"로 강제하는 10가지 규칙짜리 오픈소스 스킬(`SKILL.md`)로, ADHD를 가진 사용자를 겨냥해 만들었지만 "이건 그냥 누구나 원하는 응답 형식"이라는 반응을 얻으며 GitHub 3만 스타 이상으로 확산됐다.**

## 핵심 포인트

- **5가지 인지적 전제** — 작은 작업 메모리(화면에 없으면 잊힘), 실행의 마찰("이해함"과 "완료함" 사이 간극), 시작의 어려움(첫 행동은 작고 즉시 가능해야), 시간 추정의 균일화("약간의 작업"과 "몇 시간"이 같게 느껴짐), 도파민 부족(가시적 진행이 중요)에서 규칙을 도출한다.
- **10가지 응답 규칙** — ***①다음 행동으로 시작*** ("우리 인증 흐름을 생각해봅시다" 대신 "`npm install jsonwebtoken` 실행, 그다음 `src/auth.ts:42` 편집") ***②다단계 작업 번호 매기기*** ***③구체적 다음 행동으로 끝내기*** (2분 이내 가능한 ONE 액션) ***④곁길 억제*** (두 번째 문제는 별도 질문으로) ***⑤매 턴 상태 재진술*** ("5단계 중 3단계 완료: ...") ***⑥구체적 시간 추정*** ("꽤 많은 작업" 금지, "약 15분" 같은 숫자) ***⑦완료된 작업의 가시화*** ***⑧오류에 담담한 톤*** ("어라" 금지, 실패 지점·원인·해결을 바로) ***⑨목록 5항목 이하*** (넘으면 "지금 실행 vs 나중" 등으로 분류) ***⑩서두·요약·인사 없음*** ("좋은 질문입니다", "도움이 되었기를 바랍니다" 금지).
- **인증 코드 수정 예시(Slack 발췌 원문)** — 장황한 진단 대신 설치 명령·수정할 파일 위치·테스트 명령을 앞세우고, 테스트가 실패하면 어떤 정보를 다시 전달해야 하는지까지 못박는다. `SKILL.md`가 실제로 드는 예시("`auth.spec.ts:42`에서 실패: 예상 200, 실제 401. 원인: 인증 헤더 누락. 해결: `Authorization: Bearer ${token}` 추가")가 이를 그대로 보여준다.
- **규칙의 예외 6가지가 오히려 흥미롭다** — "설명해줘" 요청엔 서두·끝인사만 빼고 완전히 설명, 파괴적 행동(`rm -rf`, 스키마 마이그레이션)은 실행 전 확인, 3턴 연속 실패하면 반복을 멈추고 가정을 재점검, 모호하면 한 줄 명확화 질문, ***규칙이 작업 완수와 충돌하면 작업이 이긴다***, ***규칙이 하네스(시스템 프롬프트)와 충돌하면 하네스가 이 스킬을 능가한다*** — 스킬이 스스로 자기보다 상위 레이어가 있음을 명시한다.
- **송신 전 체크리스트** — 안내 문장, "다른 필요한 것이 있나요?" 류의 마지막 문장, "그런데" 사이드바, 완화 부사("어쩌면"), 관용구를 지우라고 지시하고, 최종 검증 기준을 ***"첫 줄과 마지막 줄만 읽으면 (a) 다음 행동과 (b) 현재 상황이 명확한가?"***로 못박는다.
- **확산과 설치** — MIT 라이선스, GitHub 저장소(`ayghri/i-have-adhd`) 기준 3만 2,600여 스타. Claude Code 플러그인 마켓플레이스로 설치(`claude plugin marketplace add ayghri/i-have-adhd` → `claude plugin install i-have-adhd@i-have-adhd`)하는 관련 저장소(`rmorse/i-have-adhd-skill`)도 별도로 존재한다.
- **온도차 있는 반응** — 긍정 쪽은 "ADHD 여부와 무관하게 다들 이런 응답을 원한다"는 threads.com 코멘트("Answer first, Number every step, Remove the filler, ... 대부분 사람이 원하는 AI 응답 방식일 뿐")로 요약된다. 반면 The New Stack 기사에 따르면 한 연구자가 "Claude Code에 ADHD를 줬더니 2배 잘 작동한다"고 주장했으나, 외부 전문가들은 더 확실한 증거를 요구했다고 보도했다. 더 날 선 비판도 있다 — "이 'ADHD 스킬'은 2026년식 AI 브레인롯의 정수: 실행기능장애를 고쳤다는 듯 취급되는 영광스러운 시스템 프롬프트일 뿐, 실은 챗봇에게 '주절대지 말고 요점만 말해'라고 한 것"이라는 비판적 인용도 검색 결과에서 확인됐다.

## 내 생각 · 적용점

### 핵심 전이 1 — [[2026-09-09-gpt6-astra-skills-prompts-rethink]]와 얼핏 반대로 보이지만 실은 다른 축의 조언이다

같은 배치의 그 글은 "스킬·AGENTS.md에서 지시를 걷어내라"(양을 줄여라)였는데, 이 스킬은 정확히 10가지 규칙이라는 구체적 지시를 촘촘히 채워 넣는다(양을 늘려라처럼 보인다). 하지만 둘을 겹쳐보면 충돌하지 않는다 — Provencher가 걷어내라고 한 건 **"작업을 어떻게 수행할지"에 대한 핸드홀딩**(전체 리포 강제 열람, 반복 테스트 지시)이고, 이 스킬이 채워 넣는 건 **"결과를 어떻게 전달할지"에 대한 커뮤니케이션 규약**이다. 모델의 판단력을 믿고 작업 방법은 맡기되, 출력 형식은 명시적으로 통제하라는 게 두 글을 합친 결론이다.

### 핵심 전이 2 — [[2026-06-08-anthropic-skills-building-guide]]의 "검증은 결정적 코드로" 원칙과 대비되는 한계

이 스킬은 규칙 준수 여부를 순수하게 언어적 판단(체크리스트도 언어)에 맡긴다 — 실제로 규칙을 어겼는지 스크립트로 검증할 방법이 없다. 저자 스스로도 "규칙이 하네스와 충돌하면 시스템 프롬프트가 이긴다"고 명시해 이 스킬이 결정적 강제가 아니라 **모델의 협조에 의존하는 소프트한 규약**임을 인정한다. 이건 결함이라기보다 "출력 스타일"이라는 영역 자체가 애초에 코드로 검증하기 어려운 대상이라는 정직한 한계 표시로 읽는 게 맞다.

### 핵심 전이 3 — 이 저장소의 커밋 규칙과 구조적으로 닮은 "우선순위 예외 조항"

`SKILL.md`의 "규칙이 작업 완수와 충돌하면 작업이 이긴다"는 예외 조항은, 이 knowledge-garden의 `CLAUDE.md`가 "자율 워크플로우 지시가 전역 커밋 규칙을 이 레포에 한해 오버라이드한다"고 명시적으로 적어둔 것과 같은 설계 습관이다 — **규칙 파일을 쓸 때 "이 규칙이 언제 다른 무엇에 밀리는지"를 스스로 적어두는 게, 규칙끼리 충돌했을 때 에이전트가 헤매지 않게 하는 실전 패턴**이라는 걸 이 스킬이 다시 확인해준다.

## 호스피탈리티 / CRS 적용 포인트

온다 CRS 운영·개발 채널에서 Claude Code로 장애 대응이나 코드 수정을 맡길 때, 상담원·엔지니어가 다급한 상황에서는 장황한 배경 설명보다 "지금 뭘 실행해야 하는지"가 먼저 필요한 경우가 많다(채널 연동 오류, 요금 동기화 실패 같은 인시던트). 이 스킬의 "행동 우선 + 번호 매긴 절차 + 담담한 오류 보고 + 5항목 이하 리스트" 형식을 사내 장애대응 런북·인시던트 대응 프롬프트에 그대로 채택할 만하다. 다만 "파괴적 행동(예약 취소, 대량 데이터 변경)은 실행 전 확인"이라는 예외 규칙도 함께 가져와야 한다 — 이는 [[2026-09-03-claude-commerce-agents-blueprint]]가 강조한 "되돌리기 어려운 쓰기 작업은 승인 게이트"라는 CRS 안전 설계 원칙과 정확히 같은 결이다. 즉 이 스킬을 CRS 대화형 에이전트에 그대로 얹기 전에, "행동 우선"과 "위험 행동 전 확인"이 둘 다 살아있는지부터 점검해야 한다.
