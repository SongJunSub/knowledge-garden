# Python 3.15 정식 출시

## 한 줄 요약

**Python 3.15는 지연 임포트(PEP 810)로 시작 시간을 대폭 줄이고, 불변·해시 가능한 내장 딕셔너리 타입 frozendict(PEP 814)를 추가하고, `open()`·`subprocess`의 기본 인코딩을 OS 로케일 대신 항상 UTF-8로 고정(PEP 686)하는 세 가지 변경을 핵심으로 내세운다. 다만 릴리스 일정 자체가 지연임포트의 마지막 순간 버그 때문에 10/1→10/9로 한 차례 밀렸고, 이 세션에서는 10/9 최종 출시가 실제로 완료됐는지조차 직접 확인하지 못했다.**

## 핵심 포인트

- **PEP 810: 명시적 지연 임포트** — `lazy import` 소프트 키워드로 표시한 모듈은 실제로 처음 쓰일 때까지 로드되지 않고 `sys.modules`에도 나타나지 않는다. ***모듈 최상위 스코프에서만 쓸 수 있고, `from 모듈 import *` 형태나 `__future__`에는 적용할 수 없다***는 제약이 있다. PEP 자체의 주장으로는 CLI 도구 기준 시작 시간 50~70% 단축, 메모리 30~40% 절감 효과가 있다고 하는데, ***이 수치는 PEP 저자의 자체 측정이며 독립적인 제3자 재현 검증은 확인하지 못했다.***
- **PEP 814: frozendict** — 해시 가능하고 변경 불가능한 내장 딕셔너리 타입이 추가된다. 다만 `isinstance` 관련 주의사항이 있다는 언급만 확인했고, 정확히 어떤 함정인지는 교차확인하지 못했다 — ***세부 시맨틱은 공백으로 남긴다.***
- **PEP 686: UTF-8 기본 인코딩** — `encoding=` 인자를 명시하지 않은 모든 `open()` 텍스트 모드 호출과 `subprocess.run(text=True)`가 OS 로케일 인코딩 대신 항상 UTF-8을 쓰게 된다. macOS·Linux는 이미 UTF-8 로케일이 흔해 영향이 적지만, ***Windows에서 암묵적으로 로케일 인코딩(cp1252 등)에 의존하던 코드가 조용히 깨질 수 있는 변경***이라는 평가가 있다.
- **일정 지연 경위** — PEP 790 일정상 원래 최종 릴리스는 2026-10-01이었으나, 지연 임포트 관련 마지막 순간 블로커(`a.b as c` 형태 임포트가 `b`를 `a`의 속성으로 잘못 처리하는 버그 등)가 발견돼 rc3을 추가로 내고(2026-10-02, rc2 이후 약 156건 수정·82명 기여) 최종 릴리스를 10/9로 재조정했다.
- **동시 거론되는 다른 변경** — 일부 2차 소스는 PEP 799(고빈도·저오버헤드 통계적 샘플링 프로파일러)도 3.15의 주요 변경으로 언급하지만, ***제목에 명시된 세 가지(지연 임포트·불변 딕셔너리·UTF-8) 외의 항목은 이 노트의 확인 범위 밖으로 둔다.***

## 내 생각 · 적용점

### 핵심 전이 1 — "Python 런타임 내부 거동"이라는 같은 결의 관심사

[[2026-10-08-naver-python-gc-multiprocessing-airflow-part2]]와 [[2026-09-01-naver-python-multiprocessing-airflow-part1]]은 Python GC와 멀티프로세싱(fork 시 copy-on-write)이 만났을 때의 메모리 함정을 다뤘다. 지연 임포트는 모듈 로드 시점 자체를 미루는 변경이라, ***fork 시점에 이미 로드된 모듈의 집합이 달라지면 COW 메모리 복제 패턴에도 영향을 줄 수 있다***는 추정이 가능하다 — 다만 이건 이 노트의 추론이고, PEP 810이나 네이버 글 어느 쪽도 이 상호작용을 명시적으로 다루지는 않았다는 점을 밝혀둔다.

### 핵심 전이 2 — "파싱과 실행을 어떻게 다루는가"의 정반대 극단

[[2026-09-08-1024-byte-python-interpreter]]는 토큰화·AST·바이트코드 단계를 통째로 버려 1024바이트 안에 파싱=실행 단일 패스 인터프리터를 담았다. PEP 810의 지연 임포트는 "import 시점을 최대한 늦추는" 실행 모델 최적화이고, 1024바이트 인터프리터는 "파이프라인 단계 자체를 생략하는" 정반대 극단의 최적화다 — **둘 다 "표준 파이프라인을 당연하게 받아들이지 않는다"는 같은 태도에서 나온 서로 다른 해법**이라는 점에서 나란히 둘 만하다.

### 핵심 전이 3 — 언어 핵심과 배포 플랫폼이 동시에 전진한다

[[2026-09-22-cloudflare-python-workers-ga]]는 Python이 Cloudflare 엣지 플랫폼의 정식 지원 언어가 됐다는 소식이었다. 3.15의 언어 자체 발전(시작 시간 단축, 플랫폼 간 인코딩 일관성)과 Cloudflare의 배포 플랫폼 확장이 비슷한 시기에 겹친다는 건, ***Python 생태계가 "언어 핵심"과 "어디서 실행되는가" 양쪽에서 동시에 투자받고 있다***는 신호로 읽을 수 있다. 특히 UTF-8 기본 인코딩은 엣지·서버리스처럼 실행 환경의 OS 로케일을 예측할 수 없는 상황에서 정확히 Cloudflare Workers 같은 플랫폼의 요구와 맞아떨어진다.

## 호스피탈리티 / CRS 적용 포인트

**비교적 직접 적용 가능한 기술 노트다.** 온다 백엔드에 Python 컴포넌트가 있다면, 세 변경 모두 실무적으로 점검할 가치가 있다. 첫째, **지연 임포트**는 배치 스크립트·CLI 도구(마이그레이션, 리포팅 등)의 콜드 스타트를 줄이는 데 바로 적용해볼 만하다 — 다만 모듈 최상위 스코프 제약이 있으니 적용 전 범위를 확인해야 한다. 둘째, **UTF-8 기본 인코딩 전환**은 Windows 환경에서 운영되는 내부 툴이나 파트너 연동 스크립트가 암묵적 로케일 인코딩에 의존하고 있었다면 업그레이드 시 조용히 깨질 수 있으므로, 3.15 업그레이드 전 인코딩 명시 여부를 점검하는 회귀 테스트가 필요하다. 셋째, **frozendict**는 설정 객체나 정적 참조 데이터(요금 규칙, 채널 매핑 테이블 등)의 불변성을 타입 수준에서 보장하는 데 쓸 수 있다.
