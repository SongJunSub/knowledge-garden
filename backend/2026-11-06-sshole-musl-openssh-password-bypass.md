# Sshole - musl 기반 OpenSSH에서 비밀번호 인증을 우회하는 취약점

> 출처: 원문 미확인 (GeekNews 경유, id=36654) · 정리일 2026-11-06

> **출처 한계 — 이번 배치 중 확인 수준 최저.** "Sshole"이라는 이름의 취약점·도구·CVE를 WebSearch로 찾지 못했다(일반적인 OpenSSH CVE들만 검색됨 — CVE-2016-6515 비밀번호 길이 DoS, CVE-2026-35414 authorized_keys 우회 등 전부 다른 사안). musl libc와 PAM 미사용 조합에서 발생하는 `crypt()` 반환값 문제라는 **메커니즘 자체는 기술적으로 그럴듯하지만, 이 세션에서는 Slack 발췌 외 어떤 1차 자료도 확인하지 못했다.** 아래 내용은 전부 Slack 발췌 그대로이며, 독립 검증 없이는 신뢰도를 낮게 봐야 한다.

## 한 줄 요약

**Slack 발췌에 따르면, PAM 없이 실행되는 musl 기반 Linux의 OpenSSH에서 특정 조건의 계정(비밀번호 필드가 `*`인 계정)에 임의의 긴 비밀번호로 로그인을 허용하는 문제가 있다고 주장한다. musl의 `crypt()` 실패 반환값(`*`)이 계정의 비밀번호 필드 값과 우연히 일치해 OpenSSH가 다른 계정의 솔트로 해시를 계산하는 처리와 비밀번호 길이 제한이 맞물려 발생한다는 메커니즘이다. 다만 이 서술을 1차 자료로 확인하지 못했다는 점을 먼저 밝힌다.**

## 핵심 포인트 (Slack 발췌 기준, 미확인)

- **대상 환경**: PAM 없이 실행되는 musl 기반 Linux의 OpenSSH.
- **핵심 메커니즘(주장)**: musl의 `crypt()` 실패 반환값이 `*`인데, 이것이 비밀번호 필드가 `*`인 계정(일반적으로 "비밀번호 로그인 비활성화"를 의미하는 관례적 표기)과 일치해버려 OpenSSH가 다른 계정의 솔트로 해시를 계산하는 처리 방식과 충돌한다고 서술.
- **공격 조건(주장)**: 비밀번호 로그인이 활성화되어 있고, 비밀번호 필드가 `*`인 대상 계정이 있으며, 실제 비밀번호가 설정된 다른 계정이 필요하다는 세 가지 조건.
- **공격 범위(주장)**: 이 조건에서 257~1024바이트 비밀번호로 인증을 우회할 수 있다고 서술.
- Slack 발췌 자체가 중간에서 끊겨 패치 여부·영향받는 배포판·CVE 번호 등 후속 정보는 확인할 수 없었다.

## 내 생각 · 적용점

### 핵심 전이 1 — "특수 반환값이 의미를 가진 상태와 우연히 일치"하는 보안 결함의 계열

메커니즘이 사실이라면, 이는 [[2026-10-18-nist-curve-seed-mystery-solved-drand48]]에서 다룬 "구현 세부사항의 기본값/반환값이 암묵적 가정을 깨는" 패턴과 같은 계열이다. `crypt()`가 실패 시 반환하는 매직 값 `*`이 "비밀번호 비활성화"를 뜻하는 관례적 플레이스홀더와 같다는 것 자체가, **"실패를 나타내는 센티널 값"과 "의미 있는 상태를 나타내는 값"을 같은 문자로 재사용하면 언젠가 충돌한다**는 일반 원칙을 보여준다(확인된다면).

### 핵심 전이 2 — [[2026-10-12-passkeys-are-a-trap]]과 "인증 메커니즘 신뢰의 전제 조건"

패스키 노트는 "패스키라는 이름 아래 서로 다른 성질의 인증 수단이 묶여 있다"고 짚었는데, 이번 사례(확인된다면)도 "PAM 유무"라는 배포 환경 차이가 같은 OpenSSH 코드베이스의 인증 보장을 완전히 바꿔버린다는 점에서 유사하다 — **"인증이 안전하다"는 말은 항상 특정 배포 구성을 전제로 한다는 걸 재확인.**

## 호스피탈리티 / CRS 적용 포인트

**판단 불가.** 메커니즘조차 확인되지 않은 상태라 CRS 적용점을 섣불리 끌어내는 건 위험하다. 다만 일반 원칙만: CRS·PMS 인프라가 musl 기반 경량 컨테이너(Alpine Linux 등)에서 SSH 접근을 쓴다면, **"PAM 없이 돌아가는 조합"이 보안 가정을 깨는 사례가 실제로 존재할 수 있다**는 경고로만 참고하고, 실제 패치·CVE가 확인되기 전까지 이 노트의 기술적 주장을 그대로 믿고 조치하지는 말 것.
