# wsrv.nl — 가입도 API 키도 없이 쓰는 무료 오픈소스 이미지 CDN

> 출처: [Image cache & resize service](https://wsrv.nl/) (wsrv.nl, 원래 이름 images.weserv.nl) · 정리일 2026-08-27
> **출처 한계**: `news.hada.io`와 `wsrv.nl` 본체(랜딩 페이지·`/docs/`)가 모두 이 세션에서 egress 차단이다. **직접 열어 확인한 건 소스 저장소 `github.com/weserv/images`의 README와 위키 첫 페이지뿐**이고, 서비스 자체의 파라미터 문서·요금/제한 정책·최신 운영 규모 수치는 **WebSearch 스니펫(nesin.io 블로그, opensourcealternative.to 등 2차 소개 글)으로만 재구성**했다. 이번 글은 Slack 스레드에 댓글 15개가 달려 있다고 안내됐지만, 해당 Slack 스레드·GeekNews 댓글 모두 이 세션에서 직접 확인하지 못했다 — **Slack 스레드 반응은 확인 못함**을 명시한다.

## 한 줄 요약

**wsrv.nl은 원본 이미지 URL을 파라미터와 함께 넘기면 리사이즈·크롭·포맷 변환·압축을 실시간으로 처리하고 CDN에 캐싱해 전달하는 무료 이미지 프록시 서비스다.** 가입도 API 키도 없이 바로 쓸 수 있고, `w`·`h`·`dpr`로 크기·해상도를 조절하고 `fit=cover/contain`과 직접 크롭 지정, `attention`·`entropy` 기반 **스마트 크롭**, 회전·마스크·블러·샤픈·밝기/채도/색조 조절까지 URL 파라미터만으로 지원한다. JPEG·PNG·WebP·GIF·TIFF·JXL 등 다양한 포맷을 다루며, 애니메이션 WebP/GIF도 지원한다. 소스는 `weserv/images`로 오픈소스 공개돼 있고(BSD 3-Clause, 자체 호스팅 가능), 기술 스택은 nginx + libvips + Cloudflare CDN 조합이다. 이 서비스의 진짜 흥미로운 지점은 기능표가 아니라 **운영 방식**이다 — 2007년경 남는 서버 자원에서 시작해 2011년부터 개인 자금으로 운영 중이며, 운영진은 ***"어떤 금전적 보상이나 후원도 받은 적이 없다"***는 정책을 명시적으로 유지한다 — 이해 상충을 피하고 장기 운영을 지속하기 위해서라고 밝힌다.

## 핵심 포인트

- **핵심 기능** — 원본 이미지 URL + 파라미터 → 실시간 처리(리사이즈·크롭·포맷 변환·압축) → CDN 캐싱 → 전달. 가입·API 키 불필요.
- **파라미터 범위** — `w`/`h`/`dpr`(크기·해상도), `fit=cover/contain`+위치 지정, 직접 크롭, **`attention`·`entropy` 기반 스마트 크롭**, 회전, 마스크, 블러, 샤픈, 밝기/채도/색조.
- **지원 포맷** — JPEG, PNG, BMP, GIF, TIFF, WebP, PDF, SVG, JXL 등. **애니메이션 WebP·GIF**도 지원.
- **기술 스택**(GitHub README 직접 확인) — **nginx**(웹서버·포워드 프록시·HTTP 캐시), **libvips**(이미지 처리 핵심 라이브러리), **Valkey**(속도 제한), **Cloudflare**(CDN 캐싱·IP 차단), **OpenDNS**(DNS 필터링). Docker로 **자체 호스팅**도 지원.
- **오픈소스 상태**(GitHub 직접 확인, 2026-08-27 기준) — 저장소 `weserv/images`, **BSD 3-Clause 라이선스**, 스타 약 2.8k, 포크 241개, 핵심 기여자 Andries Louw Wolthuizen·Kleis Auke Wolthuizen.
- **역사·운영 철학**(GitHub 위키 직접 확인) — **2007년경 남는 서버 자원**에서 시작해 원래 고객 웹사이트·모바일 앱용으로 설계됐고, **2011년부터 개인 펀딩으로 운영**. ***"어떤 금전적 보상이나 후원도 받은 적이 없다"***는 정책을 명시 — 이해 상충 회피와 장기 운영 지속이 목적이라고 밝힌다.
- **운영 규모**(2차 소개 글 기준, 원문 대조 못함) — 평균 시간당 약 **600만 이미지 처리**, 월 약 **400TB 아웃바운드 트래픽**, Cloudflare CDN 300개 이상 데이터센터에서 캐싱·전달.
- **포지셔닝** — ImgIX 같은 유료 이미지 CDN의 **오픈소스 대안**으로 소개되는 사례가 확인된다(opensourcealternative.to).

## 내 생각 · 적용점

### 핵심 전이 1 — "후원도 안 받는다"는 wsrv.nl의 운영 철학은, 무료 티어가 갑자기 사라지는 문제의 정반대 답이다

[[2026-08-25-microsoft-onedrive-nonprofit-data-loss]]는 Microsoft가 무료 M365 비영리 라이선스를 단계적으로 종료하면서 **17만 개 이상의 NGO가 OneDrive 데이터를 잃었다**는 사건을 다뤘다 — 벤더가 사업적 판단으로 무료 티어를 접으면 그 위에 얹힌 사용자들이 통째로 위험에 노출된다는 사례였다. wsrv.nl의 "금전적 보상·후원을 일절 받지 않는다"는 선언은 그 문제에 대한 **다른 각도의 답**이다 — 후원이나 스폰서를 받지 않으면 "수익성이 안 맞아 접는다"는 사업적 판단 자체가 애초에 발생할 유인이 줄어든다(대신 운영자 개인의 지속 의지에 전적으로 의존한다는 반대급부는 남는다). 두 사례를 나란히 놓으면, **"무료 인프라의 지속가능성"이라는 같은 질문에 "사업 모델을 최소화해서 답한 경우"와 "무료 사업 모델이 종료되며 실패한 경우"**라는 대구가 만들어진다.

### 핵심 전이 2 — URL 파라미터 하나로 리사이즈·크롭·포맷변환을 처리하는 패턴은, 클라이언트가 "무엇을 원하는지"만 선언하고 "어떻게 만들지"는 서버가 알아서 하는 설계다

이 구조는 이번 배치에서 정리한 [[2026-08-27-rag-is-simpler-than-you-think]]가 강조한 "복잡도는 필요할 때만 얹는다"는 원칙과 결이 비슷하다 — wsrv.nl을 쓰는 쪽은 이미지 리사이징 파이프라인(포맷 감지, 라이브러리 선택, 캐싱 계층)을 직접 구축하지 않고 **URL 파라미터로 의도만 선언**하면 된다. 자체 이미지 처리 인프라를 구축하는 대신 이런 선언적 프록시 계층에 위임하는 것도, "필요성이 입증되기 전까지는 무거운 인프라를 직접 짓지 않는다"는 같은 원칙의 실천으로 볼 수 있다.

## 호스피탈리티 / CRS 적용 포인트

- **CRS 접점이 이번 배치 중 상당히 직접적이다.** 파트너 호텔이 제공하는 객실·시설 사진은 해상도·화질·포맷이 제각각인 경우가 많은데, wsrv.nl류의 "URL 파라미터 기반 온디맨드 리사이즈+캐싱" 패턴은 원본 이미지를 그대로 두고 노출 시점에만 필요한 크기·포맷으로 변환하는 방식을 참고할 만하다 — 자체 이미지 파이프라인을 처음부터 구축하는 대신, 이런 프록시 계층(자체 호스팅형이든 상용이든)을 앞단에 두는 선택지를 검토할 수 있다.
- 다만 **PII·파트너 계약상 이미지 자산을 제3자 서비스로 프록시하는 것 자체가 데이터 처리 위탁에 해당할 수 있어**, wsrv.nl 같은 완전 무료·비영리 운영 서비스를 상업 프로덕션에 그대로 붙이기보다는 자체 호스팅(오픈소스 `weserv/images`를 내부 인프라에 배포)이 더 현실적인 선택지일 것이다 — 이 판단은 이 노트가 확정할 수 있는 범위를 넘는다.
