# Supabase가 조사한 2026년 스타트업 현황 (창업자 2,000명) — 기술은 해결됐고 병목은 유통·수익화·운영으로 옮겨갔다

> 출처: [State of Startups 2026](https://supabase.com/state-of-startups) (Supabase · 창업자 ~2,000명 설문 · GeekNews GN⁺ 요약) · 정리일 2026-07-20

## 한 줄 요약

**창업자 약 2,000명 설문(2025 vs 2026)이 1년 사이의 급전환을 기록한다. 다섯 줄기: ①창업자 프로필 변화(1인 53→61%, 기술창업자 82→78%, 40세+ 18→25% — "경험 많은 비기술 운영자가 AI를 들고 다시 창업"), ②Anthropic의 도구층 장악(Claude Code 63%, Claude 유료 28→59%, Anthropic 모델 38→64%, Cursor −19pp), ③AI가 코드를 씀(61%가 코드베이스 절반 이상 AI 작성, 40%가 76~100%), ④스택 수렴(Postgres 80%·Supabase Auth 72%·Vercel이 AWS 추월), ⑤그런데 병목이 기술에서 유통으로 이동 — 기술 복잡도 과제가 24→11%로 최대 낙폭, 대신 고객 확보(32%)·번아웃·런웨이가 부상, 그리고 결정적으로 빠르게 만들수록 수익화가 늦다(76~100% AI 코드 → 수익화 31% vs 0% AI → 56%). 결론: 기술 문제는 해결됐고 남은 건 시장·마음·커뮤니티다. (단, Supabase 자사 설문이라 스택 점유 수치는 표본 편향이 크다.)**

## 핵심 포인트

- **창업자 프로필 변화** — 1인 창업 **53→61%**, 기술 창업자 **82→78%**(비기술 22%), **40세+ 18→25%**(22~29세 −4pp). 지역 분산(북미 28·유럽 28·아시아 17·아프리카 9). *"경험 많은 운영자들이 AI를 손에 들고 다시 창업 중."*
- **Anthropic의 도구층 장악** — AI 코딩 도구: **Claude Code 63%** · VS Code 44% · **Cursor 31%(−19pp)** · Antigravity 22%(신규 4위). 유료 구독: **Claude 28→59%(+31pp)**, OpenAI 57→39%(−18pp). 모델 제공자: **Anthropic 38→64%(+26pp)**, OpenAI 69→52%(−17pp).
- **AI가 코드를 쓴다** — **61%가 코드베이스 50%+ AI 작성**, **40%가 76~100%**, 0%(미사용)는 2%뿐. **비기술 창업자 54%·50대 창업자 60%가 76~100%** → *나이 많고 기술 배경 약할수록 AI 의존 높음.*
- **스택 수렴** — Postgres 계열 80%(Supabase 49·PG 22). **Supabase Auth 72%**. 호스팅 Supabase 65·**Vercel 45(AWS 추월)**·Cloudflare 27·AWS 21(하락). 프론트 React 56·Next 53. **선택지 폭증 → 사실상 표준 구성(Postgres+Supabase+Vercel+Claude)으로 수렴.**
- **병목이 기술→유통으로 이동** — 최대 과제: **고객 확보 32%**. **기술 복잡도 24→11%(−13pp, 최대 낙폭)**. 신규 우려: **번아웃 11%·AI 경쟁 7%·런웨이 4%**. 유료 획득 시도 안 함 67%. 가격모델은 Tiered 23→36%로 결정화.
- **빠르게 만들수록 수익화는 늦다(핵심)** — **76~100% AI 코드 → 수익화 ~31%** vs **0% AI → ~56%**(약 2배). (초기 단계 특성이지만) *만들기의 속도가 파는 것의 성숙을 보장하지 않는다.*
- **운영 인프라 격차 = 다음 기회** — **CRM 미보유 43→53%** · **프롬프트 관리 정식 시스템 없음 47%**(하드코딩 26·버전파일 25) · **AI 모니터링 미사용 59%** · 정식 평가 프로세스 없음 36%(수동 테스트 52%). *"에이전트는 배포되는데 운영 인프라는 부재."*
- **커뮤니티가 진짜 우위** — 개발자 커뮤니티 구축은 **11%뿐**인데, 그들은 채널 믹스가 완전히 다름: **Discord/Slack 전환 38% vs 7%**, **오픈소스→유료 전환 29% vs 3%**(5배+).
- **정서** — 낙관 57%(−1pp). 역설: **AI 헤비 유저가 더 낙관(61%)하지만 수익화는 더 낮음(31%)** — "만들 수 있다"는 느낌과 실제 시장 검증의 괴리.
- **에이전트/MCP** — 52%가 에이전트 구축(멀티에이전트 프로덕션 24%), **MCP 총 채택 57%**(1년 만에 주류화).

## 댓글

**GN⁺가 원문(Supabase 리포트)을 직접 요약한 신규 포스트(게시 ~25분)로 hada 댓글·HN 큐레이션 없음.** **읽을 때 반드시 감안 — 이건 Supabase 자사 설문이다.** 표본이 Supabase 사용자 층에 쏠려 **스택 점유 수치(Supabase 49%·Auth 72%·호스팅 65%·Postgres 80%)는 명백히 부풀려져 있다**(자기 청중에게 물으면 자기 제품이 1등). 반면 **방향성 발견(유통이 병목·운영 인프라 격차·AI 코드↔수익화 역관계·번아웃 부상)은 표본 편향에 덜 민감**해 더 신뢰할 만하다. 절대 점유율은 걸러 읽고, 추세와 상관관계만 취한다.

## 내 생각 · 적용점

### 핵심 전이 1 — "유통이 병목"의 2,000명짜리 정량 확증

이 설문의 중심 서사(*"개발은 쉬워졌지만 판매는 어려워졌다"*)는 나흘 전 정리한 [[2026-07-16-build-and-scale-consumer-apps]]의 *"병목은 제품이 아니라 유통"*을 **창업자 2,000명 데이터로 확증**한다. 고객 확보가 최대 과제(32%)이고 기술 복잡도가 반토막(24→11%)났다는 건, [[2026-07-20-ai-wrapper-dead-verticalization]](오늘 짝)의 *"얇게 빠르게 만든 회사는 죽는다"*와 정확히 같은 그림이다 — **AI가 '만들기'를 공짜로 만들자, 유일하게 값이 남는 곳은 만들기 어려운 것(유통·워크플로·관계)으로 이동했다.**

### 핵심 전이 2 — 빠른 빌드 ≠ 사업: "PR 몇 개"가 가짜 지표인 것의 회사 버전

**76~100% AI 코드 → 수익화 31% vs 0% AI → 56%**는 이번 주 반복된 주제의 결정적 데이터다. [[2026-07-19-human-in-the-loop-is-tired]]의 *"시작할 수 있는 일은 폭증, 완료는 그대로"*·[[2026-07-18-ai-music-video-arena-fable-vs-sol]]의 *"예산을 늘려도 클립만 늘 뿐 창의성은 그대로"*가 **회사 스케일**로 나타난 것 — 코드 생산량(만들기)과 사업 성과(팔기)는 다른 축이고, AI는 앞만 가속한다. [[2026-07-18-make-out-like-bandits-senior-dev-value]]의 "AI가 코드를 쌓는다"와도 이어진다. **속도 지표에 취하지 말 것.**

### 핵심 전이 3 — 운영 인프라 격차 = 이 가든이 내내 말한 "평가·하네스 규율"의 부재를 시장이 증명

**프롬프트 관리 없음 47% · AI 모니터링 없음 59% · 정식 평가 없음 36%**는 충격적이다 — 대부분의 스타트업이 에이전트를 배포하면서 **평가·관측 없이** 운영한다. 이건 [[2026-07-18-ai-music-video-arena-fable-vs-sol]]의 *"평가 함수 없으면 자율성은 더 많은 평균만 낳는다"*·방법론의 *"DoD를 실행 가능한 체크로"*가 **시장에서 지켜지지 않고 있다는 증거**이고, 동시에 [[2026-07-18-state-of-open-source-ai-2026-mozilla]]의 *"에이전트는 배포되는데 운영 인프라가 미성숙"*·[[2026-07-20-why-data-teams-fail]]의 *"기술이 아니라 조직·운영이 병목"*과 정확히 겹친다. **역설적으로 이 격차가 온다에겐 규율의 차별점이 된다**(아래).

### 핵심 전이 4 — 기술 복잡도가 준 자리를 번아웃이 채웠다

**기술 복잡도 24→11%가 빠진 자리를 번아웃(11%)·AI 경쟁(7%)·런웨이(4%)가 채웠다.** 이건 [[2026-07-19-human-in-the-loop-is-tired]]가 개인 개발자 층에서 말한 *"AI는 업무량이 아니라 심리적 강도를 올린다"*가 **창업자 층에서도** 확인된 것이다. AI가 기술 장벽을 낮춘 대가는 **더 많은 결정·더 얇은 차별화·더 치열한 경쟁**이고, 그게 심리적 부담으로 전이된다. 낙관의 역설(AI 헤비 유저가 더 낙관하지만 수익화는 낮다)은 *"만들 수 있다"는 도취와 "팔린다"는 검증 사이의 간극*이다.

### 핵심 전이 5 — 스택 수렴과 커뮤니티 우위

**스택이 Postgres+Supabase+Vercel+Claude로 수렴**한 건 [[2026-07-17-wes-mckinney-ai-arrow-future-of-software]]의 *"하루 10배 결정"*에 대한 시장의 답이다 — 선택지 폭증에 지친 창업자들이 **결정 비용을 줄이려 표준 구성으로 수렴**한다(결정 피로의 집단적 해소). 그리고 **커뮤니티(11%만 구축, 5배 전환)**는 [[2026-07-16-build-and-scale-consumer-apps]]의 "신뢰를 빌린다"·[[2026-07-13-how-to-kill-churn]]의 "신뢰 기록이 자산"과 같은 유통 해자다. 참고로 Anthropic이 도구층을 장악(Claude Code 63%)한 것은 어제 [[2026-07-20-the-kimi-k3-moment]]의 "오픈이 온다"와 **표면적으로 상충**하는데, 실은 [[2026-07-18-state-of-open-source-ai-2026-mozilla]]가 말한 *"가치는 모델이 아니라 하네스에"* — 즉 오픈웨이트가 모델에서 패리티를 이뤄도 **도구층(Claude Code)은 여전히 폐쇄형이 잡고 있다**는 것으로 정합된다.

## 호스피탈리티 / CRS 적용 포인트

Supabase 스택 자체는 온다와 거리가 있지만, 발견의 방향성은 직접적이다.

- **운영·평가 규율이 곧 차별점(전이 3).** 시장의 47%가 프롬프트 관리를, 59%가 모니터링을 안 한다면, **온다가 방법론대로 평가·관측·하네스를 갖추는 것 자체가 해자**다. 남들이 안 하는 규율이 우리의 우위.
- **빠른 빌드에 취하지 말 것(전이 2).** AI로 CRS 기능을 빨리 만드는 것과 그게 사업 성과를 내는 건 다른 축 — 속도 지표가 아니라 **채택·수익화·의사결정 변화**로 측정.
- **유통·커뮤니티에 레버리지(전이 1·5).** 온다의 다음 병목도 만들기가 아니라 파는 것 — 숙박사업자 커뮤니티·레퍼런스·신뢰 기록에 투자.
- **번아웃을 지표로(전이 4).** AI 도입이 팀의 심리적 강도를 올린다는 걸 창업자 데이터도 확인 — 온다도 감독 피로·결정 부담을 설계 변수로.
