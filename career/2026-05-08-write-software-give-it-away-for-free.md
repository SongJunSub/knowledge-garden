# 소프트웨어를 만들어서 무료로 나눠주기

> 출처: [Nonograph — Write Some Software, Give It Away for Free](https://nonogra.ph/write-some-software-give-it-away-for-free-05-05-2026) · 레퍼러: [GeekNews 29269](https://news.hada.io/topic?id=29269) · 정리일 2026-05-08

## 한 줄 요약
오픈소스 블로그 플랫폼 Nonograph 개발자의 자기 변호 — **취미를 금전화하면 또 하나의 직업이 되고 직업은 재미없다**. $600 만들어서 월 $5 호스팅으로 *수십만 일일 사용자* 운영 중. 수익화 강요 시대에 *그냥 무료로 나눠주는* 선택.

## 핵심 주장

### 1. 사실 — 비용·운영 수치
- **개발 비용**: ~$600 (대부분 *보안 검토비*)
- **운영 비용**: 월 ~$5 호스팅
- **사용자**: 수십만 *일일* 독자
- → *수익화 없이 작동하는* 모델이 *기술적으로 가능*

### 2. Enshittification 비판
- 구독료·강제 AI 기능·VC 유치 목표로 설계된 요소들
- 좋은 서비스가 *서서히 악화되는 패턴*
- 기본 기능이 *점진적으로 유료화*

### 3. 무료 배포 철학
- *취미를 금전화하면 또 다른 직업이 됨, 직업은 재미없음*
- *자기탐색의 수단*으로 소프트웨어 개발 보기
- 청소년기 게임 콘텐츠 판매 경험 — *열정이 이윤 추구로 변질*되는 것을 본 자기 학습

### 댓글 논점
- **유료가 더 나은 고객 필터** vs **돈 낸 사용자의 권리 의식이 더 문제**
- **오픈소스가 수익화 가능 영역을 좁힌다** 비판
- *생계 직업으로 코딩 + 모든 사이드 프로젝트는 비수익화*라는 균형 모델
- *90년대 해커 문화*의 공동체 정신과 현재의 상업화 대비

## 내 생각 · 적용점

### 가든 시리즈의 *왜 만드는가* 회귀
가든이 9개 비판 + 1개 SQLite 자산 글로 *어떻게 위험을 피하고 무엇이 시간을 견디는가*에 집중했는데, 이 글은 *그래서 왜 만드는가* 본질 질문. 지금까지 가든의 *왜 만드는가* 글들과 짝:

| 글 | 왜의 답 |
|---|---|
| [Lynagh — 성공 기준 내면화](../engineering/2026-04-27-overthinking-scope-creep-structural-diffs.md) | *"가끔은 그냥 선반이 필요할 뿐"* |
| [Lord 3 제약](../engineering/2026-04-28-three-constraints-before-i-build-anything.md) | one-pager로 끝나는 단순한 의도 |
| [시니어 엔지니어 — 싫어하지 않는 일](2026-04-23-things-ive-learned-as-a-senior-engineer.md) | 좋아하는 게 아니라 *싫어하지 않는* 정도 |
| **이 글** | **취미는 *수익화 안 하기로* 선택할 때 취미로 남는다** |

### *취미 = 수익화 안 한 선택의 결과*
이 글의 가장 강한 명제. 한국 IT에서 *모든 사이드 프로젝트가 수익화 후보*로 평가되는 분위기와 정반대.
- BugSip을 *수익화 후보*로 보면 → *왜 진도 안 나가는지* 압박이 늘어남
- BugSip을 *취미 = 수익화 안 함 선택*으로 보면 → *그냥 만들고 싶을 때만 만든다*는 자유
- [생산적 미루기](2026-05-07-productive-procrastination.md)의 *지연 만족 vs 도파민*과 결합 — *수익화가 도파민 신호를 외부화*해서 본래 흥미를 갉아먹을 수 있음

### 가든 자체에 직접 적용
- 가든은 *수익화 안 하기로 선택*한 자산
- [Willison의 *사용량 = 증거*](../ai/2026-05-07-vibe-coding-agentic-engineering-converging.md): 가든 가치는 *내가 매일 쓰느냐*이지 *외부 수익*이 아님
- [Anthropic Fairy 후원 검토 메모](../weekly/2026-W18-geeknews-356.md)도 *받지 않기로* 선택할 가치 — *후원 = 외부 신호 → 더 자주 써야 한다는 압박* 발생

### 호스피탈리티 적용 (간접)
- *내부 도구·자동화 스크립트*는 *팀 내 무료 배포* 모델로 운영 가능
- [Glaser team-skills repo](../engineering/2026-05-07-when-everyone-has-ai-but-company-learns-nothing.md)와 결합 — *공유 자산은 수익화 압박이 없을 때 가장 잘 자란다*
- 회사 정책이 *모든 내부 도구를 수익화 후보로 평가*하면 → *공유가 안 일어남* (인센티브 비대칭)

### 90년대 해커 문화 vs 현재
- 90년대: *공유가 기본*, 수익화는 *예외*
- 현재: *수익화가 기본*, 공유는 *예외*
- 어느 쪽이 옳은지가 아니라, *디폴트가 바뀌었다*는 사실 자체가 의식할 가치
- [Steven Langbroek의 *탐욕* 비판](2026-05-08-programming-still-sucks.md)이 *디폴트 변화*를 더 강하게 표현한 형태 — *경영진의 탐욕*이 디폴트를 바꿨다

### *수익화 압박 vs 학습 자유* 트레이드오프
| 수익화 시 | 비수익화 시 |
|---|---|
| 책임감 ↑ | 자유 ↑ |
| 외부 피드백 ↑ | 내적 동기 보존 |
| 강제적 완성도 ↑ | 미완성도 OK |
| 본업과 충돌 가능 | 본업과 분리 가능 |

→ 한 사이드 프로젝트 안에서 *어느 쪽 트레이드오프가 더 가치 있는가*를 시작 단계에 명시 — Lord의 *defining constraint* 한 줄로 박을 수 있음.

### 반론·균형점
- *모든 사이드를 무료로*는 *생계가 보장된 경우*에만 가능 — 글로벌 IT 평균이 그렇지 않음
- *수익화가 좋은 인센티브*인 경우도 분명 존재 — *외부 피드백이 강제 학습*을 만든다
- 이 글의 진짜 가치는 *반드시 무료여야 한다*가 아니라 ***기본값을 의식적으로 선택하라***. 한국 IT의 *수익화 디폴트*에 *비수익화 옵션*이 가능함을 환기

### 개인 정책 후보
- BugSip: *비수익화 디폴트*로 박기 — 1년 내 수익화 검토 X
- knowledge-garden: *영구 비수익화* — 후원·광고 X
- claude-code-docs-ko: *비수익화*, 다만 *기여 받기는 OK*
- 회사 일은 *수익화 디폴트* (당연)

### 가든 메타 — 9 비판 + 1 자산 + 1 철학 = 11
가든이 30+ 글로 자란 시점에 *분류 축*을 다시 보면:
- **위험 인식** (비판 9): AI 도구·조직 위험
- **시간 견디는 가치** (자산 1): SQLite
- **왜 만드는가** (철학 — 이 글 포함 4-5개): Lynagh·Lord·시니어 교훈·이 글
- **방법론** (도구·기법 다수): mattpocock·하네스·MangoLove·etc

→ 다음 분기 회고에서 *thematic index* 만들기 강력 후보.

1. **BugSip·knowledge-garden·claude-code-docs-ko 각각의 *수익화 정책*을 README에 1줄로 명시** — *기본값 의식적 선택*

3. **사이드 프로젝트 시작 시 *defining constraint*에 *수익화/비수익화* 1줄 박기** 룰
