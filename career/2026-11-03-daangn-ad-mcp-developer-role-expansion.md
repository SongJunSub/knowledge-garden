# 국내 최초 광고 MCP를 출시하며, 개발자의 역할은 어디까지 넓어졌을까(당근마켓)

>
> **출처 한계**: medium.com 접근이 이 세션에서 egress 차단으로 원문을 직접 열람하지 못했다. Slack 본문 발췌와 스레드 답글, WebSearch로 교차확인했다. **중요한 불일치 하나를 발견했다**: Slack TechArticles 봇의 자동 요약은 "MCP"를 ***"Marketing Cloud Platform"***으로 풀어썼지만, WebSearch로 찾은 보도는 이 기능을 "광고주가 질문 한 줄로 광고 성과를 확인하고, 클로드·챗GPT에서 당근 광고 MCP 서버를 등록해 쓸 수 있다"고 설명한다 — 이는 명백히 ***Model Context Protocol(AI 에이전트가 외부 시스템과 데이터를 주고받는 연동 프로토콜)***이며, Slack 봇의 약어 전개가 틀렸다. 이 노트는 Model Context Protocol로 바로잡아 서술한다.

## 한 줄 요약

**당근이 국내 광고 플랫폼 최초로 AI 에이전트 연동용 '광고 MCP(Model Context Protocol)'를 출시했고, 그 결과 개발자의 역할이 광고 기술의 기획부터 운영까지, 나아가 비즈니스 성과를 최적화하는 데이터 기반 의사결정자로 확장됐다는 회고다.**

## 핵심 포인트

- **MCP는 "Marketing Cloud Platform"이 아니라 Model Context Protocol** — Slack 자동 요약 봇이 약어를 잘못 풀었다(위 출처 한계 참고). WebSearch로 확인한 실제 기능은 ***광고주가 API 키나 개발 지식 없이 당근 광고 MCP 서버 주소를 클로드·챗GPT에 등록하면, "지난 7일간 광고 성과를 요약해줘" 같은 자연어 질문으로 광고 계정·잔액·집행 현황·기간별 성과를 조회***할 수 있는 기능이다.
- **국내 광고 플랫폼 최초** — WebSearch로 교차확인한 보도에 따르면 ***"당근, 국내 광고 플랫폼 최초로 '광고 MCP' 출시"***라고 명시됐다. "국내 최초"는 당근 측 주장에 기반한 표현이다.
- **개발자 역할의 확장** — Slack 발췌(원문)는 ***"광고 MCP 출시를 통해 개발자가 광고 기술의 기획부터 운영까지 전 과정을 주도하는 역할로 확장됨"***, ***"기술적 구현을 넘어 비즈니스 성과를 최적화하는 데이터 기반의 의사결정자로 성장하는 과정"***이라고 요약하며 말줄임으로 끊긴다.
- **향후 확장 계획** — WebSearch 결과에 따르면 당근은 조회·분석 기능을 고도화하고, ***광고 생성·수정 기능 등 MCP 지원 범위를 단계적으로 확대***할 계획이라고 밝혔다.

## 내 생각 · 적용점

**핵심 전이 — 이 글이 보여주는 "역할 확장"은 가든이 여러 번 다룬 Product Engineer 담론의 광고 도메인 버전이다.** [[2026-10-29-yogiyo-product-engineer-scope-expansion]]·[[2026-10-29-oliveyoung-pm-ai-workflow]]가 "코드는 AI에, 사람은 문제 정의·데이터 분석·검증에 집중"이라는 패턴을 다뤘다면, 이 글은 그 패턴을 "광고 기술을 AI 에이전트에 노출하는 MCP를 만든 개발자가, 그 결과 광고 운영의 기획·의사결정까지 맡게 됐다"는 구체적 사례로 보여준다. [[2026-10-12-we-are-all-product-engineers-now]]의 "모두가 제품 엔지니어다"라는 낙관론이 실제 사례로 뒷받침되는 셈이다. 다만 Slack 자동 요약이 MCP의 약어 자체를 잘못 풀어썼다는 사실은, 자동화된 요약 파이프라인이 전문용어를 얼마나 쉽게 오염시킬 수 있는지 보여주는 작은 교훈이기도 하다([[2026-10-30-zombie-statistics-ai-citation-provenance]]의 "인용이 있어도 출처를 보장하지 않는다"는 원칙과 같은 축).

## 호스피탈리티 / CRS 적용 포인트

**직접 적용 가능성 있음.** CRS/호스피탈리티 B2B 서비스도 "호텔 운영자가 자연어로 예약·매출 현황을 질의할 수 있는 MCP 서버"를 노출하는 방향을 검토할 수 있다. 당근의 사례처럼 조회·분석 기능부터 시작해 점진적으로 쓰기(예약 생성·수정) 기능까지 확대하는 단계적 설계가 참고할 가치가 있다. 동시에 "개발자가 기획·운영까지 역할을 넓힌다"는 조직적 변화도 CRS 개발팀 구조에 시사점을 준다.
